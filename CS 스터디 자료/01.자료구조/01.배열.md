# 01. 배열 (Array)

> **학습 목표**
> - 배열이 메모리에 어떻게 저장되는지 설명할 수 있다.
> - 인덱스 접근이 왜 O(1)인지 설명할 수 있다.
> - 정적 배열과 동적 배열(ArrayList)의 차이와 확장 비용을 설명할 수 있다.

---

## 1. 개념

배열은 **같은 타입의 데이터를 연속된 메모리 공간에 순서대로 저장**하는 자료구조입니다.

```
int[] arr = {10, 20, 30, 40};

주소:   0x100   0x104   0x108   0x10C
       +-------+-------+-------+-------+
값:    |  10   |  20   |  30   |  40   |
       +-------+-------+-------+-------+
인덱스:   [0]     [1]     [2]     [3]
```

- 각 원소의 크기가 같고(int = 4byte) 메모리가 연속되어 있습니다.
- 그래서 **i번째 원소의 주소 = 시작 주소 + i × 원소 크기** 로 바로 계산됩니다.
- 이 계산이 원소 개수와 무관하게 한 번이면 끝나므로 인덱스 접근은 **O(1)** 입니다.

> 인덱스가 0부터 시작하는 이유도 여기에 있습니다. 인덱스는 "시작 주소로부터 몇 칸 떨어져 있는가(offset)"를 뜻하기 때문입니다.

---

## 2. 연산별 시간복잡도

| 연산 | 시간복잡도 | 이유 |
|---|---|---|
| 인덱스 접근 `arr[i]` | O(1) | 주소 계산 한 번 |
| 값 탐색 (정렬 X) | O(n) | 처음부터 하나씩 비교 |
| 값 탐색 (정렬 O) | O(log n) | 이분탐색 가능 |
| 맨 끝 삽입/삭제 | O(1) | 뒤에 붙이거나 떼기만 하면 됨 |
| 중간 삽입/삭제 | O(n) | 뒤의 원소를 한 칸씩 밀거나 당겨야 함 |

### 중간 삽입이 O(n)인 이유

```
[10, 20, 30, 40, _ ]  인덱스 1에 15 삽입

1) 40을 한 칸 뒤로   [10, 20, 30, _, 40]
2) 30을 한 칸 뒤로   [10, 20, _, 30, 40]
3) 20을 한 칸 뒤로   [10, _, 20, 30, 40]
4) 15 삽입           [10, 15, 20, 30, 40]
```

최악의 경우(맨 앞 삽입) n개를 모두 이동해야 합니다.

## 3. 정적 배열 vs 동적 배열

### 정적 배열
- 선언할 때 크기가 고정됩니다. (`new int[10]`)
- 크기를 넘으면 더 넣을 수 없습니다.

### 동적 배열 (Java `ArrayList`, C++ `vector`, Python `list`)
- 내부적으로는 배열을 쓰지만, 꽉 차면 **더 큰 배열을 새로 만들고 기존 원소를 복사**합니다.
- Java `ArrayList`는 기존 용량의 **1.5배**로 늘립니다. (`newCapacity = old + (old >> 1)`)

```
용량 4: [a, b, c, d]       ← 꽉 참
e 추가 → 용량 6짜리 새 배열 생성 후 복사
용량 6: [a, b, c, d, e, _]
```

### 분할 상환 분석 (Amortized Analysis)
- 확장이 일어날 때 한 번은 O(n)이 걸립니다.
- 하지만 확장은 드물게 일어나므로 **n번 삽입의 총 비용은 O(n)**, 한 번 평균은 **O(1)** 입니다.
- 이를 "맨 끝 삽입은 **분할 상환 O(1)**"이라고 표현합니다.

---

## 4. 장단점

| 장점 | 단점 |
|---|---|
| 인덱스 접근이 O(1)로 빠름 | 중간 삽입/삭제가 O(n) |
| 메모리가 연속 → **캐시 지역성**이 좋아 실제 속도가 빠름 | 크기 변경이 어려움 (정적 배열) |
| 구조가 단순하고 오버헤드가 적음 | 미리 크게 잡으면 메모리 낭비 |

> **캐시 지역성**: CPU는 메모리를 읽을 때 주변 데이터까지 캐시에 함께 가져옵니다. 배열은 원소가 붙어 있어서 다음 원소가 이미 캐시에 있을 확률이 높습니다. (→ `06.컴퓨터구조/03.메모리계층과캐시.md`)

## 5. 2차원 배열

```
int[][] grid = new int[3][4];
```

- C/C++: 행 우선(row-major)으로 하나의 연속된 메모리에 저장됩니다.
- Java: **배열의 배열**입니다. `grid`는 길이 3인 참조 배열이고, 각 칸이 길이 4인 int 배열을 가리킵니다. 그래서 행마다 길이가 달라도 됩니다(jagged array).

```java
int[][] jagged = new int[3][];
jagged[0] = new int[2];
jagged[1] = new int[5];
```

> 2차원 배열을 순회할 때 `grid[i][j]`에서 **j를 안쪽 루프**에 두는 것이 캐시 효율이 좋습니다.

---

## 6. Java 예시

```java
import java.util.*;

public class ArrayExample {
    public static void main(String[] args) {
        // 정적 배열
        int[] arr = new int[5];        // 0으로 초기화
        arr[0] = 10;
        System.out.println(arr.length); // 5

        // 정렬, 출력
        int[] nums = {5, 2, 9, 1};
        Arrays.sort(nums);
        System.out.println(Arrays.toString(nums)); // [1, 2, 5, 9]

        // 동적 배열
        List<Integer> list = new ArrayList<>();
        list.add(1);          // 맨 끝 삽입: 분할 상환 O(1)
        list.add(0, 99);      // 맨 앞 삽입: O(n)
        list.get(1);          // 인덱스 접근: O(1)
        list.remove(0);       // 맨 앞 삭제: O(n)
    }
}
```

## 7. 면접 질문

1. **배열의 인덱스 접근이 O(1)인 이유는?**
   → 연속된 메모리에 같은 크기로 저장되어 `시작 주소 + i × 크기`로 주소를 바로 계산할 수 있기 때문입니다.
2. **ArrayList의 add가 O(1)이라고 하는데, 확장할 때는 O(n) 아닌가요?**
   → 확장 시에는 O(n)이지만 드물게 일어나므로 분할 상환하면 평균 O(1)입니다.
3. **배열과 연결리스트 중 무엇을 쓰겠습니까?**
   → 조회가 많으면 배열, 앞/중간 삽입·삭제가 많고 위치를 이미 알고 있으면 연결리스트입니다. 실무에서는 캐시 지역성 때문에 대부분 배열 기반(ArrayList)이 더 빠릅니다.

---

## 핵심 정리
- 배열 = **연속 메모리 + 같은 크기** → 인덱스 접근 O(1)
- 중간 삽입/삭제는 원소 이동 때문에 O(n)
- 동적 배열은 꽉 차면 1.5~2배로 늘려 복사 → 끝 삽입은 분할 상환 O(1)
