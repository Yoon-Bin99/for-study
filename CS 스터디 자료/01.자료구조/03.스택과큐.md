# 03. 스택과 큐 (Stack & Queue)

> **학습 목표**
> - LIFO와 FIFO의 차이를 설명할 수 있다.
> - 스택과 큐가 실제로 쓰이는 곳을 예로 들 수 있다.
> - 덱(Deque)과 원형 큐의 필요성을 설명할 수 있다.

---

## 1. 스택 (Stack)

**나중에 넣은 것이 먼저 나오는(LIFO, Last In First Out)** 자료구조입니다. 접시를 쌓는 것과 같습니다.

```
push(1) push(2) push(3)        pop() → 3

  |   |        | 3 | ← top        |   |
  |   |        | 2 |              | 2 | ← top
  |   |        | 1 |              | 1 |
  +---+        +---+              +---+
```

| 연산 | 설명 | 시간 |
|---|---|---|
| push(x) | 맨 위에 추가 | O(1) |
| pop() | 맨 위 꺼내기 | O(1) |
| peek() | 맨 위 확인만 | O(1) |
| isEmpty() | 비었는지 확인 | O(1) |

### 스택이 쓰이는 곳
- **함수 호출 (Call Stack)**: 함수가 호출되면 지역변수·복귀 주소를 담은 스택 프레임이 쌓이고, 끝나면 pop됩니다. 재귀가 너무 깊으면 `StackOverflowError`가 납니다.
- **괄호 검사**: 여는 괄호는 push, 닫는 괄호가 나오면 pop해서 짝 확인
- **되돌리기(Undo)**, 브라우저 뒤로 가기
- **DFS** (반복문으로 구현할 때)
- **후위 표기식 계산**

---

## 2. 큐 (Queue)

**먼저 넣은 것이 먼저 나오는(FIFO, First In First Out)** 자료구조입니다. 줄 서기와 같습니다.

```
enqueue(1) enqueue(2) enqueue(3)

front                 rear
  ↓                    ↓
+---+---+---+
| 1 | 2 | 3 |    dequeue() → 1
+---+---+---+
```

| 연산 | 설명 | 시간 |
|---|---|---|
| enqueue(x) / offer | 뒤에 추가 | O(1) |
| dequeue() / poll | 앞에서 꺼내기 | O(1) |
| peek() | 앞 확인만 | O(1) |

### 큐가 쓰이는 곳
- **BFS** (너비 우선 탐색)
- **프로세스 스케줄링** (Ready Queue)
- **메시지 큐** (Kafka, RabbitMQ), 프린터 대기열
- 네트워크 패킷 버퍼

---

## 3. 원형 큐 (Circular Queue)

배열로 큐를 단순 구현하면 dequeue할 때마다 앞쪽이 비어서 공간이 낭비됩니다.

```
dequeue 3번 후:  [_, _, _, 4, 5]   ← 앞 3칸이 놀고 있는데 rear가 끝이라 더 못 넣음
```

원형 큐는 배열의 끝과 처음을 이어 붙인 것처럼 사용합니다.

```java
rear = (rear + 1) % capacity;
front = (front + 1) % capacity;
```

- 빈 상태와 꽉 찬 상태를 구분하기 위해 **한 칸을 비워 두거나**, size 변수를 따로 둡니다.
  - 비었다: `front == rear`
  - 꽉 찼다: `(rear + 1) % capacity == front`

---

## 4. 덱 (Deque, Double-Ended Queue)

**양쪽 끝에서 모두 삽입·삭제**가 가능한 자료구조입니다. 스택과 큐를 모두 대체할 수 있습니다.

| 연산 | 앞쪽 | 뒤쪽 |
|---|---|---|
| 삽입 | offerFirst | offerLast |
| 삭제 | pollFirst | pollLast |
| 확인 | peekFirst | peekLast |

- 슬라이딩 윈도우 최댓값, 0-1 BFS, 회문 검사 등에 씁니다.

---

## 5. Java에서 사용하기

```java
import java.util.*;

// 스택: Stack 클래스보다 ArrayDeque 권장
Deque<Integer> stack = new ArrayDeque<>();
stack.push(1);
stack.push(2);
stack.pop();   // 2
stack.peek();  // 1

// 큐
Queue<Integer> queue = new ArrayDeque<>();   // 또는 new LinkedList<>()
queue.offer(1);
queue.offer(2);
queue.poll();  // 1
queue.peek();  // 2

// 덱
Deque<Integer> dq = new ArrayDeque<>();
dq.offerFirst(1);
dq.offerLast(2);
dq.pollFirst(); // 1
dq.pollLast();  // 2
```

> **왜 `Stack` 대신 `ArrayDeque`?**
> `Stack`은 `Vector`를 상속해 모든 메서드에 `synchronized`가 걸려 있어 느리고, 인덱스로 중간 접근이 가능해 스택의 의미가 깨집니다. Java 공식 문서도 `Deque` 사용을 권장합니다.

### 괄호 검사 예시
```java
boolean isValid(String s) {
    Deque<Character> stack = new ArrayDeque<>();
    for (char c : s.toCharArray()) {
        if (c == '(' || c == '{' || c == '[') {
            stack.push(c);
        } else {
            if (stack.isEmpty()) return false;
            char open = stack.pop();
            if (c == ')' && open != '(') return false;
            if (c == '}' && open != '{') return false;
            if (c == ']' && open != '[') return false;
        }
    }
    return stack.isEmpty();
}
```

## 6. 응용: 단조 스택 (Monotonic Stack)

스택 안의 값이 항상 증가(또는 감소) 상태를 유지하도록 관리하는 기법입니다. **"오른쪽에서 처음으로 나보다 큰 수"** 같은 문제를 O(n)에 풉니다.

```java
// 각 원소의 오른쪽에서 처음 나오는 더 큰 수 (없으면 -1)
int[] nextGreater(int[] arr) {
    int n = arr.length;
    int[] ans = new int[n];
    Arrays.fill(ans, -1);
    Deque<Integer> st = new ArrayDeque<>(); // 인덱스 저장
    for (int i = 0; i < n; i++) {
        while (!st.isEmpty() && arr[st.peek()] < arr[i]) {
            ans[st.pop()] = arr[i];
        }
        st.push(i);
    }
    return ans;
}
```

## 7. 면접 질문

1. **스택 2개로 큐를 만들 수 있나요?**
   → 입력 스택에 push하고, 출력 스택이 비었을 때만 입력 스택을 모두 옮긴 뒤 pop합니다. 분할 상환 O(1)입니다.
2. **콜 스택이란?**
   → 함수 호출 정보(매개변수, 지역변수, 복귀 주소)를 담는 스택 프레임이 쌓이는 메모리 영역입니다.
3. **큐를 배열로 구현할 때 문제점은?**
   → dequeue 후 앞 공간이 낭비됩니다. 원형 큐로 해결합니다.

---

## 핵심 정리
- 스택 = LIFO (함수 호출, 괄호, DFS, Undo)
- 큐 = FIFO (BFS, 스케줄링, 메시지 큐)
- 덱 = 양쪽 삽입·삭제, Java에서는 `ArrayDeque` 하나로 스택·큐·덱 모두 사용
