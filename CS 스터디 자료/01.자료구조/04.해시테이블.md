# 04. 해시 테이블 (Hash Table)

> **학습 목표**
> - 해시 함수와 해시 테이블이 평균 O(1)을 달성하는 원리를 설명할 수 있다.
> - 해시 충돌과 해결 방법(체이닝, 개방 주소법)을 비교할 수 있다.
> - Java HashMap의 내부 동작을 설명할 수 있다.

---

## 1. 개념

해시 테이블은 **키(key)를 해시 함수에 넣어 나온 값으로 배열의 위치(버킷)를 정하고, 그 위치에 값을 저장**하는 자료구조입니다.

```
key "apple" ──hash()──> 9283741 ──% 8──> 5

버킷 배열 (크기 8)
[0] 
[1] 
[2] 
[3] 
[4] 
[5] ("apple", 1000)
[6] 
[7] 
```

- 키만 알면 위치를 바로 계산하므로 **삽입·조회·삭제 모두 평균 O(1)** 입니다.
- 순서는 보장되지 않습니다.

---

## 2. 해시 함수

좋은 해시 함수의 조건:
1. **결정적**: 같은 입력이면 항상 같은 출력
2. **균등 분포**: 출력이 버킷에 고르게 퍼져야 충돌이 적음
3. **빠른 계산**

대표적인 방법:
- **나눗셈법**: `h(k) = k mod m` (m은 소수로 잡으면 분포가 좋음)
- **곱셈법**: `h(k) = floor(m × (k × A mod 1))`, A는 0~1 사이 상수

---

## 3. 해시 충돌 (Collision)

서로 다른 키가 같은 버킷으로 가는 현상입니다. 버킷 수는 유한하고 키는 무한하므로 **충돌은 반드시 발생**합니다(비둘기집 원리).

### 해결 방법 1: 체이닝 (Separate Chaining)
같은 버킷에 들어온 원소들을 **연결리스트로 이어** 저장합니다.

```
[3] → ("cat", 1) → ("dog", 2) → null
[4] → null
[5] → ("apple", 3) → null
```
- 구현이 쉽고, 테이블이 꽉 차도 계속 넣을 수 있습니다.
- 한 버킷에 몰리면 O(n)까지 느려집니다.
- **Java HashMap이 사용하는 방식**입니다.

### 해결 방법 2: 개방 주소법 (Open Addressing)
충돌하면 **배열의 다른 빈 칸을 찾아** 저장합니다.

| 방식 | 다음 위치 | 특징 |
|---|---|---|
| 선형 탐사 | h+1, h+2, h+3 ... | 구현 쉬움, 데이터가 뭉치는 **1차 군집** 발생 |
| 이차 탐사 | h+1², h+2², h+3² ... | 1차 군집 완화, 2차 군집 발생 |
| 이중 해싱 | h + i × h2(k) | 군집 가장 적음, 계산 비용 큼 |

- 포인터가 없어 메모리 효율과 캐시 효율이 좋습니다.
- 삭제할 때 그냥 비우면 탐사가 끊기므로 **삭제 표시(tombstone)**를 남겨야 합니다.
- Python dict가 개방 주소법을 사용합니다.

---

## 4. 부하율과 리해싱

**부하율(Load Factor) = 저장된 원소 수 / 버킷 수**

- 부하율이 높을수록 충돌이 많아집니다.
- 기준치를 넘으면 버킷 배열을 **2배로 늘리고 모든 원소를 다시 해싱(rehashing)** 합니다. 이때 O(n)이 걸리지만 분할 상환하면 평균 O(1)입니다.
- Java HashMap의 기본값: 초기 용량 16, 부하율 0.75 → 원소가 12개를 넘으면 32로 확장

---

## 5. Java HashMap 내부 동작

```
put("apple", 1)
 1. "apple".hashCode() 계산
 2. hash = h ^ (h >>> 16)        ← 상위 비트를 섞어 분포 개선
 3. index = hash & (n - 1)       ← n이 2의 거듭제곱이라 % 대신 비트 AND
 4. 버킷이 비었으면 저장
 5. 있으면 equals()로 같은 키인지 비교 → 같으면 값 교체, 다르면 체인에 추가
```

- **Java 8부터** 한 버킷의 원소가 **8개 이상**이고 테이블 크기가 64 이상이면 연결리스트를 **레드블랙 트리**로 바꿉니다. 최악의 경우가 O(n) → O(log n)으로 개선됩니다. (6개 이하로 줄면 다시 리스트로)

### hashCode()와 equals()
- HashMap은 **hashCode로 버킷을 찾고, equals로 같은 키인지 확인**합니다.
- 그래서 `equals()`를 재정의하면 **반드시 `hashCode()`도 재정의**해야 합니다. 그렇지 않으면 같은 객체인데 다른 버킷에 들어가 찾지 못합니다.

```java
class Member {
    String id;
    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Member)) return false;
        return id.equals(((Member) o).id);
    }
    @Override
    public int hashCode() {
        return Objects.hash(id);
    }
}
```

## 6. 시간복잡도

| 연산 | 평균 | 최악 |
|---|---|---|
| 삽입 | O(1) | O(n) (Java 8+ 트리화 시 O(log n)) |
| 조회 | O(1) | O(n) |
| 삭제 | O(1) | O(n) |

---

## 7. 관련 자료구조 비교 (Java)

| 클래스 | 순서 | 내부 구조 | 특징 |
|---|---|---|---|
| HashMap | 없음 | 해시 테이블 | 가장 빠름, null 키 1개 허용 |
| LinkedHashMap | 삽입 순서 | 해시 + 이중 연결리스트 | LRU 캐시 구현에 사용 |
| TreeMap | 키 정렬 | 레드블랙 트리 | O(log n), 범위 검색 가능 |
| Hashtable | 없음 | 해시 테이블 | 전체 synchronized, 레거시 |
| ConcurrentHashMap | 없음 | 해시 테이블 | 버킷 단위 락(CAS) → 멀티스레드에 권장 |

## 8. 활용 예시

```java
// 빈도수 세기
Map<String, Integer> count = new HashMap<>();
for (String w : words) {
    count.put(w, count.getOrDefault(w, 0) + 1);
    // 또는 count.merge(w, 1, Integer::sum);
}

// Two Sum: 합이 target인 두 인덱스 O(n)
int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> seen = new HashMap<>();
    for (int i = 0; i < nums.length; i++) {
        int need = target - nums[i];
        if (seen.containsKey(need)) return new int[]{seen.get(need), i};
        seen.put(nums[i], i);
    }
    return new int[0];
}
```

## 9. 면접 질문

1. **해시 충돌 해결 방법은?**
   → 체이닝(버킷에 연결리스트)과 개방 주소법(빈 칸 탐사). Java HashMap은 체이닝 + 트리화를 씁니다.
2. **equals만 재정의하면 어떤 문제가?**
   → 논리적으로 같은 객체가 다른 hashCode를 가져 HashMap/HashSet에서 찾지 못하거나 중복 저장됩니다.
3. **HashMap은 스레드 안전한가요?**
   → 아닙니다. 멀티스레드 환경에서는 ConcurrentHashMap을 씁니다.
4. **HashMap 용량이 2의 거듭제곱인 이유는?**
   → `hash % n` 대신 `hash & (n-1)` 비트 연산으로 빠르게 인덱스를 구하기 위해서입니다.

---

## 핵심 정리
- 해시 테이블 = 해시 함수로 위치 계산 → 평균 O(1)
- 충돌은 필연 → 체이닝 or 개방 주소법
- 부하율 0.75 초과 시 2배 확장 + 리해싱
- equals 재정의 시 hashCode도 반드시 재정의
