# 06. 힙과 우선순위 큐 (Heap & Priority Queue)

> **학습 목표**

> - 삽입(up-heap)과 삭제(down-heap) 과정을 그릴 수 있다.
> - 우선순위 큐를 언제 쓰는지 알고 Java로 사용할 수 있다.

---

## 1. 우선순위 큐란?

일반 큐는 먼저 들어온 순서대로 나오지만, **우선순위 큐는 우선순위가 가장 높은 원소가 먼저 나옵니다.**

| 구현 방법 | 삽입 | 최댓값 삭제 |
|---|---|---|
| 정렬 안 된 배열 | O(1) | O(n) |
| 정렬된 배열 | O(n) | O(1) |
| **힙** | **O(log n)** | **O(log n)** |

→ 삽입과 삭제 모두 효율적인 **힙**으로 구현하는 것이 일반적입니다.

---

## 2. 힙 (Heap)

힙은 다음 두 조건을 만족하는 트리입니다.
1. **완전 이진 트리**: 왼쪽부터 빈틈없이 채워짐
2. **힙 속성**:
   - 최대 힙(Max Heap): 부모 ≥ 자식
   - 최소 힙(Min Heap): 부모 ≤ 자식

```
최대 힙                     배열 표현 (1-based)
        50                  인덱스: 1   2   3   4   5   6
       /  \                 값:    50  30  40  10  20  35
     30    40
    /  \   /                부모 = i/2, 왼쪽 = 2i, 오른쪽 = 2i+1
   10  20 35
```

> **주의**: 힙은 BST와 다릅니다. 형제끼리는 대소 관계가 없습니다. **루트가 최댓값(최솟값)이라는 것만 보장**합니다.

완전 이진 트리이므로 **배열로 빈틈없이 표현**할 수 있고, 높이는 항상 **O(log n)** 입니다.

---

## 3. 삽입 (Up-Heap / Sift-Up)

1. 맨 끝(마지막 리프 다음 자리)에 새 원소를 넣는다.
2. 부모와 비교해서 힙 속성을 어기면 **부모와 교환**한다.
3. 루트에 도달하거나 속성을 만족할 때까지 반복한다.

```
최대 힙에 45 삽입

      50                50                50
     /  \              /  \              /  \
   30    40    →     30    40    →     30    45
  /  \   / \        /  \   / \        /  \   / \
 10  20 35 45      10  20 35 45      10  20 35 40
             ↑ 끝에 추가     45 > 40 → 교환   45 < 50 → 종료
```

---

## 4. 삭제 (Down-Heap / Sift-Down)

힙에서 삭제는 항상 **루트(최댓값)** 를 꺼냅니다.
1. 루트를 꺼낸다.
2. **맨 마지막 원소를 루트로** 옮긴다.
3. 두 자식 중 **더 큰 자식**과 비교해서 작으면 교환한다.
4. 리프에 도달하거나 속성을 만족할 때까지 반복한다.

```
최대 힙에서 50 삭제

      50                35                40
     /  \              /  \              /  \
   30    40    →     30    40    →     30    35
  /  \   /          /  \               /  \
 10  20 35         10  20             10  20
 루트 꺼냄        마지막 원소 35를     자식 30, 40 중 더 큰 40과 교환
                  루트로 이동          → 리프 도달, 종료
```
(더 큰 자식과 교환하는 이유: 작은 자식과 바꾸면 새 부모가 다른 자식보다 작아져 속성이 깨지기 때문)

## 5. 시간복잡도

| 연산 | 시간 |
|---|---|
| 최댓값/최솟값 확인 (peek) | O(1) |
| 삽입 | O(log n) |
| 삭제 | O(log n) |
| 배열로 힙 만들기 (heapify) | **O(n)** |
| 임의 원소 탐색 | O(n) |

> **heapify가 O(n log n)이 아니라 O(n)인 이유**: 아래쪽 노드일수록 개수는 많지만 내려갈 높이가 작습니다. 전체 합을 계산하면 O(n)이 됩니다.

## 6. Java 구현 (최소 힙)

```java
public class MinHeap {
    private int[] heap = new int[100];
    private int size = 0;   // 1-based

    public void push(int x) {
        heap[++size] = x;
        int i = size;
        while (i > 1 && heap[i / 2] > heap[i]) {   // 부모가 더 크면 교환
            swap(i, i / 2);
            i /= 2;
        }
    }

    public int pop() {
        int top = heap[1];
        heap[1] = heap[size--];
        int i = 1;
        while (2 * i <= size) {
            int child = 2 * i;
            if (child + 1 <= size && heap[child + 1] < heap[child]) child++; // 더 작은 자식
            if (heap[i] <= heap[child]) break;
            swap(i, child);
            i = child;
        }
        return top;
    }

    private void swap(int a, int b) { int t = heap[a]; heap[a] = heap[b]; heap[b] = t; }
}
```

### Java PriorityQueue 사용
```java
// 최소 힙 (기본)
PriorityQueue<Integer> minPq = new PriorityQueue<>();

// 최대 힙
PriorityQueue<Integer> maxPq = new PriorityQueue<>(Collections.reverseOrder());

// 객체: 비용이 작은 순
PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[1] - b[1]);
// 값이 매우 크면 오버플로 위험 → Integer.compare(a[1], b[1]) 권장

pq.offer(new int[]{1, 5});
pq.poll();
pq.peek();
```

## 7. 활용

| 활용 | 설명 |
|---|---|
| **다익스트라 최단경로** | 현재까지 거리가 가장 짧은 노드를 꺼냄 |
| **힙 정렬** | 힙에서 계속 꺼내면 정렬됨, O(n log n) |
| **Top-K 문제** | 크기 K의 최소 힙 유지 → 상위 K개, O(n log K) |
| **중앙값 유지** | 최대 힙(왼쪽 절반) + 최소 힙(오른쪽 절반) |
| **OS 작업 스케줄링** | 우선순위 스케줄링 |
| **이벤트 시뮬레이션, 타이머** | 가장 빠른 시간의 이벤트 처리 |

```java
// 배열에서 K번째로 큰 수
int kthLargest(int[] nums, int k) {
    PriorityQueue<Integer> pq = new PriorityQueue<>(); // 최소 힙
    for (int n : nums) {
        pq.offer(n);
        if (pq.size() > k) pq.poll();  // 가장 작은 것 제거
    }
    return pq.peek();
}
```

## 8. 면접 질문

1. **힙과 BST의 차이는?**
   → 힙은 부모-자식 관계만 보장해 최댓값/최솟값 조회가 O(1)이고, BST는 좌<부모<우를 보장해 임의 값 탐색이 O(log n)입니다.
2. **힙을 배열로 구현하는 이유는?**
   → 완전 이진 트리라 빈칸 없이 저장할 수 있고, 인덱스 계산만으로 부모·자식에 접근할 수 있어 포인터가 필요 없습니다.
3. **우선순위 큐가 쓰이는 알고리즘은?**
   → 다익스트라, 프림, 힙 정렬, Top-K, 허프만 코딩.

---

## 핵심 정리
- 힙 = 완전 이진 트리 + (부모 ≥ 자식 or 부모 ≤ 자식)
- 삽입: 끝에 넣고 위로 / 삭제: 루트 빼고 마지막을 올린 뒤 아래로 → 둘 다 O(log n)
- Java `PriorityQueue`는 기본 최소 힙
