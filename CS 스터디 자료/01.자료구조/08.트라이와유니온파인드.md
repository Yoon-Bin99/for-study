# Part 1. 트라이 (Trie, 접두사 트리)

## 1. 개념

트라이는 **문자열을 한 글자씩 노드로 저장하는 트리**입니다. 공통 접두사를 공유하므로 사전, 자동완성에 씁니다.

```
"car", "cat", "dog" 저장

          (root)
          /    \
         c      d
         |      |
         a      o
        / \     |
      r*   t*   g*        * = 단어의 끝 표시 (isEnd)
```

- "ca"로 시작하는 단어 → c → a 노드까지 내려간 뒤 그 아래를 모두 탐색: **car, cat**

## 2. 시간복잡도

문자열 길이를 L이라 하면:

| 연산 | 트라이 | 해시셋 | 정렬 배열 |
|---|---|---|---|
| 삽입 | O(L) | O(L) (해시 계산) | O(n) |
| 정확히 일치 검색 | O(L) | O(L) | O(L log n) |
| **접두사 검색** | **O(L)** | 불가 (전부 확인 O(n·L)) | O(L log n) |

- 단점: 노드마다 자식 포인터를 가지므로 **메모리를 많이 씁니다.**

## 3. Java 구현

```java
class Trie {
    private static class Node {
        Node[] child = new Node[26];   // 소문자 a~z
        boolean isEnd;
    }
    private final Node root = new Node();

    public void insert(String word) {
        Node cur = root;
        for (char c : word.toCharArray()) {
            int i = c - 'a';
            if (cur.child[i] == null) cur.child[i] = new Node();
            cur = cur.child[i];
        }
        cur.isEnd = true;
    }

    public boolean search(String word) {
        Node n = find(word);
        return n != null && n.isEnd;
    }

    public boolean startsWith(String prefix) {
        return find(prefix) != null;
    }

    private Node find(String s) {
        Node cur = root;
        for (char c : s.toCharArray()) {
            cur = cur.child[c - 'a'];
            if (cur == null) return null;
        }
        return cur;
    }
}
```

> 문자 종류가 많으면(한글 등) 배열 대신 `Map<Character, Node>`를 씁니다.

## 4. 활용
- 검색창 **자동완성**, 사전, 맞춤법 검사
- IP 라우팅 테이블의 **최장 접두사 매칭** (→ `05.네트워크/03.네트워크계층.md`)
- 전화번호 목록에서 한 번호가 다른 번호의 접두사인지 확인

# Part 2. 유니온 파인드 (Union-Find, Disjoint Set)

## 1. 개념

**서로소 집합(겹치지 않는 집합)들을 관리**하는 자료구조입니다. 두 가지 연산을 지원합니다.

- `find(x)`: x가 속한 집합의 대표(루트) 찾기
- `union(a, b)`: a와 b가 속한 두 집합 합치기

> "두 정점이 같은 그룹인가?"를 빠르게 판단할 때 씁니다.

## 2. 동작 원리

각 원소는 부모를 가리키며, 루트가 그 집합의 대표입니다.

```
초기: 모두 자기 자신이 부모
parent = [0, 1, 2, 3, 4]

union(1, 2): 2의 루트를 1로     union(3, 4)       union(2, 4)
    1                           1      3            1
    |                           |      |           / \
    2                           2      4          2   3
                                                      |
                                                      4
find(4) → 4 → 3 → 1  (대표: 1)
```

## 3. 최적화 2가지

최적화 없이는 트리가 한쪽으로 길어져 find가 O(n)이 될 수 있습니다.

### 경로 압축 (Path Compression)
find하면서 지나간 모든 노드를 **루트에 바로 연결**합니다.
```
Before: 4 → 3 → 1         After find(4): 4 → 1, 3 → 1
```

### 랭크/크기 기반 합치기 (Union by Rank/Size)
**작은 트리를 큰 트리 밑에** 붙여 높이가 커지지 않게 합니다.

두 가지를 함께 쓰면 연산당 시간이 **O(α(n))** 이 됩니다. α는 아커만 함수의 역함수로, 현실적인 n에서 4 이하라 **사실상 O(1)** 입니다.

## 4. Java 구현

```java
class UnionFind {
    int[] parent, size;

    UnionFind(int n) {
        parent = new int[n];
        size = new int[n];
        for (int i = 0; i < n; i++) { parent[i] = i; size[i] = 1; }
    }

    int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]);  // 경로 압축
        return parent[x];
    }

    boolean union(int a, int b) {
        int ra = find(a), rb = find(b);
        if (ra == rb) return false;          // 이미 같은 집합 → 사이클
        if (size[ra] < size[rb]) { int t = ra; ra = rb; rb = t; }
        parent[rb] = ra;                     // 작은 쪽을 큰 쪽 밑으로
        size[ra] += size[rb];
        return true;
    }
}
```

## 5. 활용
- **크루스칼 MST**: 간선을 추가할 때 사이클이 생기는지 확인 (→ `02.알고리즘/09.MST와위상정렬.md`)
- 무방향 그래프의 **사이클 판별**
- 네트워크 연결 여부, 친구 관계 그룹 수 세기

## 면접 질문

1. **트라이를 해시셋 대신 쓰는 이유는?**
   → 접두사 검색(자동완성)을 O(L)에 할 수 있기 때문입니다. 해시셋은 접두사 검색이 불가능합니다.
2. **유니온 파인드의 시간복잡도와 최적화 방법은?**
   → 경로 압축과 랭크 기반 합치기를 함께 쓰면 연산당 O(α(n)), 사실상 상수 시간입니다.

## 핵심 정리
- 트라이: 문자 단위 트리, 삽입·검색·접두사 검색 O(L), 메모리 많이 사용
- 유니온 파인드: find + union, 경로 압축 + 크기 기반 합치기 → 거의 O(1)
