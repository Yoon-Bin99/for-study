# 01. 시간복잡도와 공간복잡도

> **학습 목표**
> - 빅오(Big-O) 표기법의 의미를 설명할 수 있다.
> - 코드를 보고 시간복잡도를 계산할 수 있다.
> - 입력 크기를 보고 필요한 알고리즘 복잡도를 역산할 수 있다.

---

## 1. 왜 필요한가?

같은 문제를 푸는 알고리즘이라도 입력이 커질 때 걸리는 시간은 크게 다릅니다. 실행 시간은 컴퓨터 성능에 따라 달라지므로, **입력 크기 n에 대해 연산 횟수가 어떻게 늘어나는지**로 비교합니다.

---

## 2. 점근 표기법

| 표기 | 의미 | 비유 |
|---|---|---|
| **O (빅오)** | 상한. "최악이어도 이 정도" | ≤ |
| Ω (빅오메가) | 하한. "최소한 이 정도는 걸림" | ≥ |
| Θ (빅세타) | 상한과 하한이 같음. "딱 이 정도" | = |

실무와 코딩테스트에서는 주로 **빅오(최악의 경우)** 를 씁니다.

### 빅오 계산 규칙
1. **상수는 버린다**: O(2n) → O(n), O(100) → O(1)
2. **가장 큰 항만 남긴다**: O(n² + n + 1) → O(n²)
3. 서로 다른 입력은 따로 쓴다: 배열 두 개를 각각 순회 → O(n + m)

---

## 3. 대표 복잡도

```
빠름  O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)  느림
```

| 복잡도 | 이름 | 예시 | n = 1,000일 때 연산량 |
|---|---|---|---|
| O(1) | 상수 | 배열 인덱스 접근, 해시 조회 | 1 |
| O(log n) | 로그 | 이분 탐색, 균형 BST 탐색 | 약 10 |
| O(n) | 선형 | 배열 순회, 선형 탐색 | 1,000 |
| O(n log n) | 선형 로그 | 병합 정렬, 퀵 정렬(평균), 힙 정렬 | 약 10,000 |
| O(n²) | 이차 | 이중 반복문, 버블 정렬 | 1,000,000 |
| O(2ⁿ) | 지수 | 부분집합 전부 탐색 | 매우 큼 |
| O(n!) | 팩토리얼 | 순열 전부 탐색 | 매우 큼 |

---

## 4. 코드로 계산하기

```java
// O(1)
int first(int[] a) { return a[0]; }

// O(n)
int sum(int[] a) {
    int s = 0;
    for (int x : a) s += x;
    return s;
}

// O(n²)
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++)
        doSomething();

// O(n²) — 합이 n(n-1)/2 이므로
for (int i = 0; i < n; i++)
    for (int j = i + 1; j < n; j++)
        doSomething();

// O(log n) — 매번 절반
while (n > 1) n /= 2;

// O(n log n) — 바깥 n번 × 안쪽 log n
for (int i = 0; i < n; i++)
    for (int j = 1; j < n; j *= 2)
        doSomething();

// O(2ⁿ) — 호출마다 2갈래
int fib(int n) {
    if (n <= 1) return n;
    return fib(n - 1) + fib(n - 2);
}
```

### 재귀의 시간복잡도
**호출 횟수 × 한 번 호출할 때 드는 일** 로 생각합니다.
- 병합 정렬: 깊이 log n, 각 깊이에서 합쳐서 n만큼 작업 → **O(n log n)**
- 피보나치 재귀: 호출이 약 2ⁿ번 → **O(2ⁿ)**, 메모이제이션하면 O(n)

---

## 5. 코딩테스트 실전: 입력 크기로 알고리즘 고르기

일반적으로 **1초에 약 1억(10⁸) 번 연산**을 기준으로 잡습니다. (Java는 조금 보수적으로 잡는 것이 안전)

| 입력 크기 n | 허용 복잡도 | 떠올릴 알고리즘 |
|---|---|---|
| n ≤ 10 | O(n!) | 순열 완전탐색 |
| n ≤ 20 | O(2ⁿ) | 부분집합, 비트마스크 |
| n ≤ 500 | O(n³) | 플로이드-워셜 |
| n ≤ 5,000 | O(n²) | 이중 반복문, 2차원 DP |
| n ≤ 1,000,000 | O(n log n) | 정렬, 이분탐색, 힙 |
| n ≤ 10,000,000 | O(n) | 투포인터, 누적합, 해시 |
| n > 10⁹ | O(log n) | 이분탐색, 수학 |

---

## 6. 공간복잡도

알고리즘이 사용하는 **추가 메모리**의 양입니다.
- 배열 크기 n 하나 생성 → O(n)
- 2차원 배열 n×n → O(n²)
- 재귀 깊이 d → **콜 스택 O(d)** (재귀도 메모리를 씁니다!)

> 메모리 제한 256MB면 int(4byte) 기준 약 6,000만 개까지 가능합니다.

---

## 7. 최선·평균·최악

퀵 정렬 예시:
- 최선: O(n log n) — 피벗이 항상 중간
- 평균: O(n log n)
- 최악: O(n²) — 이미 정렬된 배열에서 맨 앞을 피벗으로 선택

해시 테이블 조회: 평균 O(1), 최악 O(n)

> 면접에서 복잡도를 말할 때는 **어떤 경우(평균/최악)인지** 같이 말하는 것이 좋습니다.

---

## 8. 면접 질문

1. **O(n)과 O(n log n)의 차이를 체감할 수 있는 예는?**
   → n = 100만이면 O(n)은 100만, O(n log n)은 약 2,000만 번입니다.
2. **빅오에서 상수를 무시하는 이유는?**
   → n이 충분히 커지면 증가율이 지배적이기 때문입니다. 다만 실제 성능에서는 상수(캐시, 메모리 접근)도 중요합니다.
3. **분할 상환(amortized) 복잡도란?**
   → 가끔 비싼 연산이 있어도 여러 번의 연산 전체 비용을 나누면 평균이 낮은 경우입니다. 예: ArrayList add는 분할 상환 O(1).

---

## 핵심 정리
- 빅오 = 입력이 커질 때 최악의 증가율, 상수·낮은 차수 무시
- 1초 ≈ 1억 연산 → n 크기로 필요한 복잡도를 역산
- 재귀 공간복잡도 = 재귀 깊이
