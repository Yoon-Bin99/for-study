# 02. 정렬 (Sorting)

> **학습 목표**
> - 주요 정렬 알고리즘의 동작 원리와 복잡도를 설명할 수 있다.
> - 안정 정렬과 제자리 정렬의 의미를 설명할 수 있다.
> - Java의 `Arrays.sort`가 어떤 알고리즘을 쓰는지 알고 Comparator를 활용할 수 있다.

## 1. 한눈에 비교

| 알고리즘 | 최선 | 평균 | 최악 | 추가 공간 | 안정 |
|---|---|---|---|---|---|
| 버블 정렬 | O(n) | O(n²) | O(n²) | O(1) | O |
| 선택 정렬 | O(n²) | O(n²) | O(n²) | O(1) | X |
| 삽입 정렬 | **O(n)** | O(n²) | O(n²) | O(1) | O |
| 병합 정렬 | O(n log n) | O(n log n) | **O(n log n)** | O(n) | **O** |
| 퀵 정렬 | O(n log n) | O(n log n) | **O(n²)** | O(log n) | X |
| 힙 정렬 | O(n log n) | O(n log n) | O(n log n) | **O(1)** | X |
| 계수 정렬 | O(n + k) | O(n + k) | O(n + k) | O(k) | O |

- **안정 정렬(Stable)**: 값이 같은 원소들의 **원래 순서가 유지**됨
  - 예: "나이순 정렬" 후 "이름순 정렬"했을 때, 이름이 같으면 나이순이 유지됨
- **제자리 정렬(In-place)**: 추가 메모리를 거의 쓰지 않음

## 2. O(n²) 정렬

### 버블 정렬 (Bubble Sort)
**인접한 두 원소를 비교해서 큰 값을 뒤로 보냅니다.** 한 바퀴 돌면 가장 큰 값이 맨 뒤에 고정됩니다.

```
[5, 3, 8, 1]
1회전: [3, 5, 1, 8]   ← 8 고정
2회전: [3, 1, 5, 8]   ← 5 고정
3회전: [1, 3, 5, 8]
```

### 선택 정렬 (Selection Sort)
**남은 원소 중 최솟값을 찾아 맨 앞과 교환합니다.**
```
[5, 3, 8, 1] → 최솟값 1과 5 교환 → [1, 3, 8, 5] → [1, 3, 8, 5] → [1, 3, 5, 8]
```
- 교환 때문에 같은 값의 순서가 바뀔 수 있어 **불안정**합니다.

### 삽입 정렬 (Insertion Sort)
**앞쪽은 정렬된 상태로 유지하고, 새 원소를 알맞은 자리에 끼워 넣습니다.** (카드 정리 방식)
```
[5 | 3, 8, 1]
[3, 5 | 8, 1]
[3, 5, 8 | 1]
[1, 3, 5, 8]
```
- **거의 정렬된 데이터에서는 O(n)** 으로 매우 빠릅니다.
- 데이터가 작을 때 효율이 좋아 Java·Python 내부 정렬(TimSort)에서도 작은 구간에 사용합니다.

```java
void insertionSort(int[] a) {
    for (int i = 1; i < a.length; i++) {
        int key = a[i], j = i - 1;
        while (j >= 0 && a[j] > key) {
            a[j + 1] = a[j];
            j--;
        }
        a[j + 1] = key;
    }
}
```

## 3. O(n log n) 정렬

### 병합 정렬 (Merge Sort) — 분할 정복
1. **분할**: 배열을 절반으로 계속 나눈다 (길이 1이 될 때까지)
2. **정복**: 나눈 배열을 정렬하면서 합친다

```
        [38, 27, 43, 3]
         /           \
    [38, 27]       [43, 3]
     /    \         /    \
   [38]  [27]     [43]   [3]
     \    /         \    /
    [27, 38]       [3, 43]
         \           /
        [3, 27, 38, 43]
```

- 항상 O(n log n) 보장, **안정 정렬**
- 합칠 때 임시 배열이 필요해서 **O(n) 추가 메모리**
- 연결리스트 정렬, 외부 정렬(대용량 파일)에 적합

```java
void mergeSort(int[] a, int l, int r, int[] tmp) {
    if (l >= r) return;
    int m = (l + r) / 2;
    mergeSort(a, l, m, tmp);
    mergeSort(a, m + 1, r, tmp);
    int i = l, j = m + 1, k = l;
    while (i <= m && j <= r) tmp[k++] = (a[i] <= a[j]) ? a[i++] : a[j++]; // <= 로 안정성 유지
    while (i <= m) tmp[k++] = a[i++];
    while (j <= r) tmp[k++] = a[j++];
    for (k = l; k <= r; k++) a[k] = tmp[k];
}
```

### 퀵 정렬 (Quick Sort) — 분할 정복
1. **피벗(pivot)** 을 하나 고른다.
2. 피벗보다 작은 값은 왼쪽, 큰 값은 오른쪽으로 나눈다 (**파티션**)
3. 왼쪽과 오른쪽을 각각 재귀로 정렬한다.

```
[5, 3, 8, 1, 9, 2]   피벗 = 5
→ [3, 1, 2] 5 [8, 9]
→ [1] 2 [3] 5 [8] 9 ...
```

- 평균 O(n log n), 실제로 **가장 빠른 경우가 많음** (캐시 효율, 상수가 작음)
- **최악 O(n²)**: 이미 정렬된 배열에서 매번 최솟값/최댓값이 피벗이 되면 한쪽만 줄어듦
- 해결: **랜덤 피벗**, **중앙값 3개 중 중간(median-of-three)**

```java
void quickSort(int[] a, int lo, int hi) {
    if (lo >= hi) return;
    int pivot = a[(lo + hi) / 2];
    int i = lo, j = hi;
    while (i <= j) {
        while (a[i] < pivot) i++;
        while (a[j] > pivot) j--;
        if (i <= j) { int t = a[i]; a[i] = a[j]; a[j] = t; i++; j--; }
    }
    quickSort(a, lo, j);
    quickSort(a, i, hi);
}
```

### 힙 정렬 (Heap Sort)
1. 배열을 최대 힙으로 만든다 (O(n))
2. 루트(최댓값)를 맨 뒤와 바꾸고 힙 크기를 줄인 뒤 down-heap (n번 × O(log n))

- 최악도 O(n log n), 추가 메모리 O(1)
- 캐시 효율이 나빠 실제로는 퀵 정렬보다 느린 편 (→ `01.자료구조/06.힙과우선순위큐.md`)

## 4. 비교 기반이 아닌 정렬

비교 기반 정렬의 하한은 **O(n log n)** 이라는 것이 증명되어 있습니다. 이를 넘으려면 값을 비교하지 않는 방식을 써야 합니다.

### 계수 정렬 (Counting Sort)
값의 범위(k)가 작을 때, **각 값이 몇 번 나왔는지 세어서** 정렬합니다.
```
[3, 1, 2, 3, 1]  → count[1]=2, count[2]=1, count[3]=2 → [1, 1, 2, 3, 3]
```
- O(n + k). 값의 범위가 크면(예: 0 ~ 10억) 메모리 낭비

### 기수 정렬 (Radix Sort)
1의 자리, 10의 자리, ... 순서로 자릿수별 안정 정렬을 반복합니다. O(d × (n + k))

## 5. Java 정렬 실전

| 메서드 | 대상 | 내부 알고리즘 |
|---|---|---|
| `Arrays.sort(int[])` | 기본형 배열 | **Dual-Pivot Quick Sort** (불안정, 최악 O(n²) 가능성) |
| `Arrays.sort(Object[])` | 객체 배열 | **TimSort** (병합 + 삽입, 안정) |
| `Collections.sort(List)` | 리스트 | TimSort |

> 기본형은 같은 값을 구분할 필요가 없어 안정성이 필요 없으므로 더 빠른 퀵 정렬을 씁니다. 객체는 안정성이 중요해서 TimSort를 씁니다.

```java
// 내림차순 (객체 배열만 가능)
Integer[] arr = {3, 1, 2};
Arrays.sort(arr, Collections.reverseOrder());

// 2차원 배열: 첫 번째 기준 오름차순, 같으면 두 번째 기준 내림차순
int[][] pts = {{1, 2}, {1, 5}, {0, 3}};
Arrays.sort(pts, (a, b) -> a[0] != b[0] ? Integer.compare(a[0], b[0])
                                       : Integer.compare(b[1], a[1]));

// 객체 정렬
list.sort(Comparator.comparing(Person::getAge)
                    .thenComparing(Person::getName));
```

> **주의**: `(a, b) -> a - b`는 값이 크면 **오버플로**가 날 수 있습니다. `Integer.compare(a, b)`를 쓰는 습관을 들이세요.

## 6. 면접 질문

1. **퀵 정렬의 최악 시간복잡도와 개선 방법은?**
   → 피벗이 계속 최솟값/최댓값이 되면 O(n²). 랜덤 피벗이나 median-of-three로 개선합니다.
2. **병합 정렬과 퀵 정렬 중 무엇이 좋나요?**
   → 퀵 정렬은 평균적으로 빠르고 추가 메모리가 적지만 최악 O(n²)이고 불안정합니다. 병합 정렬은 항상 O(n log n)이고 안정적이지만 O(n) 메모리가 필요합니다.
3. **안정 정렬이 필요한 경우는?**
   → 여러 기준으로 순차 정렬할 때, 앞선 정렬 결과를 유지해야 하는 경우입니다.
4. **Java Arrays.sort는 어떤 알고리즘을 쓰나요?**
   → 기본형은 Dual-Pivot Quick Sort, 객체는 TimSort입니다.

## 핵심 정리
- O(n²): 버블, 선택, 삽입 (삽입은 거의 정렬된 데이터에 O(n))
- O(n log n): 병합(안정, O(n) 메모리), 퀵(평균 최고, 최악 O(n²)), 힙(O(1) 메모리)
- 비교 기반 하한 O(n log n), 계수·기수 정렬은 조건부로 O(n)
