# 03. 이분 탐색 (Binary Search)

> **학습 목표**
> - 이분 탐색의 전제 조건과 O(log n)인 이유를 설명할 수 있다.
> - lower bound / upper bound를 구현할 수 있다.
> - "답을 이분 탐색하는" 파라메트릭 서치 문제를 알아볼 수 있다.

---

## 1. 개념

**정렬된 배열**에서 가운데 값과 비교해 탐색 범위를 **절반씩 줄여 나가는** 탐색 방법입니다.

```
찾는 값: 23
[2, 5, 8, 12, 16, 23, 38, 56, 72, 91]
 lo              mid                hi    mid=16 < 23 → 오른쪽
                     lo    mid      hi    mid=56 > 23 → 왼쪽
                     lo,mid hi             mid=23 → 찾음!
```

- 전제 조건: **정렬되어 있어야 합니다.** (또는 조건이 단조적이어야 함)
- n개 → n/2 → n/4 → ... → 1 이므로 비교 횟수는 **log₂ n**
- n = 10억이어도 약 30번이면 찾습니다.

---

## 2. 기본 구현

```java
int binarySearch(int[] a, int target) {
    int lo = 0, hi = a.length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;   // (lo + hi) / 2 는 오버플로 위험
        if (a[mid] == target) return mid;
        else if (a[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;   // 없음
}
```

> **`(lo + hi) / 2` 오버플로**: lo와 hi가 모두 20억 근처면 더하는 순간 int 범위를 넘습니다. `lo + (hi - lo) / 2`로 쓰는 습관을 들이세요. (Java의 `Arrays.binarySearch`도 과거 이 버그가 있었습니다.)

---

## 3. Lower Bound / Upper Bound

중복된 값이 있을 때 "어디서부터 어디까지인가"를 구합니다.

```
a = [1, 2, 4, 4, 4, 7, 9]
         idx: 0  1  2  3  4  5  6

lowerBound(4) = 2   ← 4 이상이 처음 나오는 위치
upperBound(4) = 5   ← 4 초과가 처음 나오는 위치
4의 개수 = 5 - 2 = 3
```

```java
// target 이상이 처음 나오는 인덱스
int lowerBound(int[] a, int target) {
    int lo = 0, hi = a.length;   // hi는 a.length (끝 다음)
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] >= target) hi = mid;
        else lo = mid + 1;
    }
    return lo;
}

// target 초과가 처음 나오는 인덱스
int upperBound(int[] a, int target) {
    int lo = 0, hi = a.length;
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] > target) hi = mid;
        else lo = mid + 1;
    }
    return lo;
}
```

**포인트**: `lo < hi`, `hi = mid` 형태는 범위가 `[lo, hi)` 반열린 구간이라 무한 루프가 없습니다.

## 4. 파라메트릭 서치 (Parametric Search)

**"조건을 만족하는 최솟값/최댓값"** 을 구하는 문제를 **"이 값이 가능한가? (Yes/No)"** 문제로 바꾸고, 답을 이분 탐색합니다.

조건: 답 x에 대해 `가능(x)`가 **단조적**이어야 합니다.
```
x:      1  2  3  4  5  6  7  8
가능?   N  N  N  Y  Y  Y  Y  Y    ← 처음 Y가 나오는 지점을 이분 탐색
```

### 예시: 나무 자르기
> 나무들을 높이 H로 잘라서 잘린 윗부분을 가져간다. 최소 M미터를 가져가려면 H의 최댓값은?

- H가 낮을수록 많이 가져감 → "H로 자르면 M 이상인가?"는 단조적
- H의 범위 0 ~ 최대 높이를 이분 탐색

```java
long maxHeight(int[] trees, long m) {
    long lo = 0, hi = Arrays.stream(trees).max().getAsInt();
    long ans = 0;
    while (lo <= hi) {
        long mid = (lo + hi) / 2;
        long got = 0;
        for (int t : trees) if (t > mid) got += t - mid;
        if (got >= m) { ans = mid; lo = mid + 1; }  // 가능 → 더 높여 본다
        else hi = mid - 1;
    }
    return ans;
}
```
시간복잡도: O(n × log(최대 높이))

### 이런 표현이 보이면 파라메트릭 서치를 의심
- "~의 **최솟값의 최댓값**", "**최대**를 **최소화**"
- 입수 심사 (모든 사람이 심사받는 최소 시간), 공유기 설치, 랜선 자르기, 징검다리

## 5. Java 라이브러리

```java
int[] a = {1, 3, 5, 7};
Arrays.binarySearch(a, 5);   // 2
Arrays.binarySearch(a, 4);   // 음수: -(삽입 위치) - 1 = -3

List<Integer> list = List.of(1, 3, 5, 7);
Collections.binarySearch(list, 5);  // 2

// TreeSet / TreeMap으로 lower/upper bound
TreeSet<Integer> set = new TreeSet<>(List.of(1, 3, 5, 7));
set.ceiling(4);   // 5  (4 이상 중 최솟값)
set.floor(4);     // 3  (4 이하 중 최댓값)
set.higher(5);    // 7  (5 초과)
set.lower(5);     // 3  (5 미만)
```

> `Arrays.binarySearch`는 중복이 있을 때 **어떤 인덱스를 반환할지 보장하지 않습니다.** 첫 위치가 필요하면 lower bound를 직접 구현하세요.

## 6. 면접 질문

1. **이분 탐색의 전제 조건은?**
   → 데이터가 정렬되어 있어야 하고(또는 판정 함수가 단조적이어야 하고), 임의 접근이 O(1)이어야 합니다. 연결리스트에서는 비효율적입니다.
2. **이분 탐색의 시간복잡도가 O(log n)인 이유는?**
   → 매 단계 탐색 범위가 절반으로 줄어 k번 후 n/2ᵏ = 1이 되므로 k = log₂ n입니다.
3. **mid 계산 시 주의할 점은?**
   → `(lo + hi) / 2`는 오버플로가 날 수 있어 `lo + (hi - lo) / 2`를 씁니다.

---

## 핵심 정리
- 정렬된 데이터에서 절반씩 줄임 → O(log n)
- lower bound(이상 첫 위치) / upper bound(초과 첫 위치)
- "최솟값의 최댓값" 류는 답을 이분 탐색 (파라메트릭 서치)
