# 06. 그리디 알고리즘 (Greedy)

> **학습 목표**
> - 그리디 알고리즘이 정답을 보장하는 조건을 설명할 수 있다.
> - 그리디가 실패하는 반례를 들 수 있다.
> - 대표 그리디 문제(활동 선택, 거스름돈, 회의실 배정)를 풀 수 있다.

---

## 1. 개념

그리디는 **매 순간 가장 좋아 보이는 선택을 하는** 방법입니다. 선택을 되돌리지 않습니다.

- 장점: 빠르고 구현이 간단함 (대부분 정렬 + 순회 → O(n log n))
- 단점: **항상 최적해를 보장하지 않음**

---

## 2. 그리디가 성립하는 조건

1. **탐욕적 선택 속성 (Greedy Choice Property)**
   지금의 최선의 선택이 나중의 선택에 영향을 주지 않고, 전체 최적해의 일부가 된다.
2. **최적 부분 구조 (Optimal Substructure)**
   문제의 최적해가 부분 문제의 최적해로 구성된다.

> 코딩테스트에서는 엄밀한 증명보다 **"반례가 있는지"** 를 먼저 생각해 보는 것이 실전적입니다. 반례가 떠오르면 DP를 고려하세요.

---

## 3. 그리디가 실패하는 예: 거스름돈

### 성공하는 경우
동전 [500, 100, 50, 10]으로 1,260원 → 큰 동전부터
```
500 × 2 = 1000
100 × 2 = 200
 50 × 1 = 50
 10 × 1 = 10   → 총 6개 (최적)
```
큰 동전이 **작은 동전의 배수**라서 그리디가 성립합니다.

### 실패하는 경우
동전 [500, 400, 100]으로 800원
```
그리디: 500 + 100 + 100 + 100 = 4개
최적:   400 + 400             = 2개
```
배수 관계가 아니면 그리디가 틀립니다 → **DP**로 풀어야 합니다.

## 4. 대표 문제

### 4-1. 회의실 배정 (활동 선택 문제)
> 회의들의 시작·종료 시간이 주어질 때, 겹치지 않게 최대한 많은 회의를 배정하라.

**핵심: 끝나는 시간이 빠른 회의부터 선택**

```
회의: (1,4) (3,5) (0,6) (5,7) (3,9) (5,9) (6,10) (8,11) (8,12) (2,14) (12,16)
종료 시간순 정렬 후:
(1,4) 선택 → (5,7) 선택 → (8,11) 선택 → (12,16) 선택 → 4개
```

왜 맞을까? 가장 빨리 끝나는 회의를 고르면 **남은 시간이 가장 많이 남기** 때문에, 다른 회의를 골라서 더 좋아질 수 없습니다.

```java
int maxMeetings(int[][] meetings) {
    // 종료 시간 오름차순, 같으면 시작 시간 오름차순
    Arrays.sort(meetings, (a, b) -> a[1] != b[1] ? Integer.compare(a[1], b[1])
                                                 : Integer.compare(a[0], b[0]));
    int count = 0, end = 0;
    for (int[] m : meetings) {
        if (m[0] >= end) {
            count++;
            end = m[1];
        }
    }
    return count;
}
```

> 시작 시간순이나 짧은 회의순으로 정렬하면 반례가 있습니다. 예: (0,10) (1,2) (3,4) — 시작순이면 (0,10) 하나만 선택됩니다.

### 4-2. 분할 가능 배낭 문제 (Fractional Knapsack)
물건을 **쪼갤 수 있으면** 무게당 가치가 높은 것부터 담으면 최적입니다.
- 쪼갤 수 없는 **0/1 배낭 문제**는 그리디로 안 됨 → DP (→ `07.동적계획법.md`)

### 4-3. 그 밖의 그리디 문제
| 문제 | 그리디 전략 |
|---|---|
| ATM 대기 시간 최소화 | 처리 시간이 짧은 사람부터 |
| 큰 수 만들기 (k개 숫자 제거) | 앞자리부터 더 큰 수가 오면 앞의 작은 수 제거 (스택) |
| 구명보트 | 정렬 후 가장 무거운 사람 + 가장 가벼운 사람 짝짓기 (투포인터) |
| 단속 카메라 | 진출 지점 기준 정렬, 카메라를 가장 늦게 설치 |
| 허프만 코딩 | 빈도가 가장 낮은 두 노드를 계속 합침 (우선순위 큐) |

## 5. 그래프에서의 그리디

다음 유명 알고리즘도 그리디입니다.

| 알고리즘 | 그리디 선택 |
|---|---|
| 다익스트라 | 현재까지 거리가 **가장 짧은 정점**을 확정 |
| 크루스칼 | **가장 가벼운 간선**부터 (사이클이 안 생기면) 선택 |
| 프림 | 현재 트리에 연결된 **가장 가벼운 간선** 선택 |

---

## 6. 그리디 vs DP

| 항목 | 그리디 | DP |
|---|---|---|
| 선택 방식 | 지금 최선 하나만 | 모든 부분 문제를 계산해 비교 |
| 되돌리기 | 없음 | 이전 결과를 조합 |
| 속도 | 빠름 | 상대적으로 느림 |
| 최적해 보장 | 조건 만족 시만 | 항상 |

---

## 7. 면접 질문

1. **그리디 알고리즘이 최적해를 보장하려면?**
   → 탐욕적 선택 속성과 최적 부분 구조를 만족해야 합니다.
2. **회의실 배정에서 종료 시간 기준으로 정렬하는 이유는?**
   → 일찍 끝나는 회의를 고를수록 남은 시간이 많아 이후 선택지가 가장 넓기 때문입니다.
3. **그리디로 풀 수 없는 문제의 예는?**
   → 배수 관계가 없는 동전 거스름돈, 0/1 배낭 문제.

---

## 핵심 정리
- 그리디 = 매 순간 최선, 되돌리지 않음
- 성립 조건: 탐욕적 선택 속성 + 최적 부분 구조
- 반례를 먼저 찾아보고, 있으면 DP로
- 대부분 "정렬 기준을 무엇으로 할지"가 핵심
