# 10. 투 포인터, 슬라이딩 윈도우, 누적합

> **학습 목표**
> - O(n²) 이중 반복문을 O(n)으로 줄이는 투 포인터 기법을 이해한다.
> - 고정/가변 크기 슬라이딩 윈도우를 구현할 수 있다.
> - 누적합으로 구간 합을 O(1)에 구할 수 있다.

---

## 1. 투 포인터 (Two Pointers)

**두 개의 인덱스를 움직이며** 조건을 만족하는 구간이나 쌍을 찾는 기법입니다. 각 포인터가 한 방향으로만 움직이므로 **O(n)** 입니다.

### 유형 1: 양 끝에서 좁혀오기 (정렬된 배열)
> 정렬된 배열에서 합이 target인 두 수 찾기

```
[1, 2, 4, 7, 11, 15], target = 15
 L                 R    1+15=16 > 15 → R 왼쪽
 L             R        1+11=12 < 15 → L 오른쪽
    L          R        2+11=13 < 15 → L 오른쪽
       L       R        4+11=15 → 찾음!
```

```java
int[] twoSumSorted(int[] a, int target) {
    int l = 0, r = a.length - 1;
    while (l < r) {
        int sum = a[l] + a[r];
        if (sum == target) return new int[]{l, r};
        if (sum < target) l++;     // 합을 키워야 함
        else r--;                  // 합을 줄여야 함
    }
    return null;
}
```

### 유형 2: 같은 방향으로 이동 (구간)
> 양수 배열에서 합이 S 이상인 가장 짧은 연속 구간의 길이

```java
int minLength(int[] a, int s) {
    int l = 0, sum = 0, best = Integer.MAX_VALUE;
    for (int r = 0; r < a.length; r++) {
        sum += a[r];                       // 오른쪽 확장
        while (sum >= s) {                 // 조건 만족하는 동안
            best = Math.min(best, r - l + 1);
            sum -= a[l++];                 // 왼쪽 축소
        }
    }
    return best == Integer.MAX_VALUE ? 0 : best;
}
```

> 같은 방향 투 포인터는 **원소가 모두 양수**처럼 "구간을 늘리면 합이 커지고 줄이면 작아진다"는 **단조성**이 있어야 합니다. 음수가 섞이면 누적합 + 해시맵을 고려하세요.

## 2. 슬라이딩 윈도우 (Sliding Window)

**일정한 범위(창문)를 한 칸씩 밀면서**, 새로 들어온 값은 더하고 빠진 값은 빼서 다시 계산하지 않는 기법입니다.

### 고정 크기 윈도우
> 길이 k인 연속 부분 배열의 최대 합

```
[2, 1, 5, 1, 3, 2], k = 3
[2, 1, 5] = 8
   [1, 5, 1] = 8 - 2 + 1 = 7
      [5, 1, 3] = 7 - 1 + 3 = 9   ← 최대
         [1, 3, 2] = 9 - 5 + 2 = 6
```

```java
int maxSumK(int[] a, int k) {
    int sum = 0;
    for (int i = 0; i < k; i++) sum += a[i];
    int best = sum;
    for (int i = k; i < a.length; i++) {
        sum += a[i] - a[i - k];      // 들어온 값 더하고, 나간 값 빼기
        best = Math.max(best, sum);
    }
    return best;
}
```

### 가변 크기 윈도우
> 중복 문자가 없는 가장 긴 부분 문자열 ("abcabcbb" → "abc", 3)

```java
int longestUnique(String s) {
    Map<Character, Integer> last = new HashMap<>();
    int l = 0, best = 0;
    for (int r = 0; r < s.length(); r++) {
        char c = s.charAt(r);
        if (last.containsKey(c) && last.get(c) >= l) {
            l = last.get(c) + 1;          // 중복 문자 다음으로 왼쪽 이동
        }
        last.put(c, r);
        best = Math.max(best, r - l + 1);
    }
    return best;
}
```

## 3. 누적합 (Prefix Sum)

**앞에서부터의 합을 미리 계산**해 두면 임의 구간의 합을 O(1)에 구할 수 있습니다.

```
a      = [3, 1, 4, 1, 5]
prefix = [0, 3, 4, 8, 9, 14]      prefix[i] = a[0] + ... + a[i-1]

a[1..3]의 합 = prefix[4] - prefix[1] = 9 - 3 = 6   (1 + 4 + 1)
```

```java
long[] prefix = new long[n + 1];
for (int i = 0; i < n; i++) prefix[i + 1] = prefix[i] + a[i];

// [l, r] 구간 합 (0-based, 양끝 포함)
long rangeSum = prefix[r + 1] - prefix[l];
```

### 2차원 누적합
```
S[i][j] = (0,0) ~ (i-1, j-1) 직사각형의 합

(r1,c1) ~ (r2,c2) 합 = S[r2+1][c2+1] - S[r1][c2+1] - S[r2+1][c1] + S[r1][c1]
```

### 누적합 + 해시맵: 합이 K인 부분 배열 개수 (음수 포함 가능)
```java
int subarraySum(int[] a, int k) {
    Map<Long, Integer> cnt = new HashMap<>();
    cnt.put(0L, 1);
    long sum = 0; int ans = 0;
    for (int x : a) {
        sum += x;
        ans += cnt.getOrDefault(sum - k, 0);   // 이전 누적합이 sum-k인 개수
        cnt.merge(sum, 1, Integer::sum);
    }
    return ans;
}
```

## 4. 언제 무엇을 쓰나

| 문제 신호 | 기법 |
|---|---|
| 정렬된 배열에서 두 수의 합/차 | 양 끝 투 포인터 |
| 연속 구간 + 양수 + "최소 길이/최대 길이" | 같은 방향 투 포인터 |
| 길이 k 고정 구간 | 고정 슬라이딩 윈도우 |
| 구간 합 질의가 여러 번 | 누적합 |
| 음수가 섞인 구간 합 조건 | 누적합 + 해시맵 |

## 5. 면접 질문

1. **투 포인터가 O(n)인 이유는?**
   → 두 포인터가 각각 최대 n번만, 한 방향으로만 움직이기 때문입니다.
2. **누적합의 장점과 한계는?**
   → 구간 합 질의를 O(1)에 처리하지만, 배열 값이 자주 바뀌면 매번 다시 계산해야 해서 펜윅 트리·세그먼트 트리가 필요합니다.

---

## 핵심 정리
- 투 포인터: 두 인덱스를 한 방향으로만 이동 → O(n)
- 슬라이딩 윈도우: 들어온 값 더하고 나간 값 빼기
- 누적합: `sum(l..r) = prefix[r+1] - prefix[l]`
