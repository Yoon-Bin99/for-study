# 01. 운영체제 개요

> **학습 목표**
> - 운영체제의 역할과 커널의 의미를 설명할 수 있다.
> - 사용자 모드와 커널 모드, 시스템 콜의 흐름을 설명할 수 있다.
> - 인터럽트의 종류와 처리 과정을 설명할 수 있다.

## 1. 운영체제란?

운영체제(OS, Operating System)는 **하드웨어 자원을 관리하고, 응용 프로그램이 하드웨어를 쉽고 안전하게 쓸 수 있게 해 주는 소프트웨어**입니다.

```
+-----------------------------------------+
|   응용 프로그램 (브라우저, IDE, 게임)        |
+-----------------------------------------+
|   시스템 콜 인터페이스                       |
+-----------------------------------------+
|   커널 (프로세스·메모리·파일·장치 관리)       |
+-----------------------------------------+
|   하드웨어 (CPU, 메모리, 디스크, 네트워크)    |
+-----------------------------------------+
```

### 주요 역할
| 역할 | 내용 |
|---|---|
| **프로세스 관리** | 프로그램 실행, CPU 스케줄링, 동기화 |
| **메모리 관리** | 프로세스별 메모리 할당, 가상 메모리 |
| **파일 시스템 관리** | 파일·디렉토리 생성, 저장, 권한 |
| **입출력(I/O) 관리** | 디바이스 드라이버, 버퍼링 |
| **보호와 보안** | 프로세스끼리 서로의 메모리를 침범하지 못하게 함 |

### 커널 (Kernel)
운영체제의 **핵심 부분으로, 항상 메모리에 상주**하며 자원 관리를 담당합니다. 쉘(Shell)이나 GUI는 사용자와 커널 사이의 인터페이스일 뿐 커널이 아닙니다.

| 구조 | 설명 | 예 |
|---|---|---|
| 모놀리식 커널 | 모든 기능이 커널 공간에 → 빠름, 하나가 죽으면 전체 위험 | Linux |
| 마이크로 커널 | 최소 기능만 커널에, 나머지는 사용자 공간 → 안정적, 통신 오버헤드 | Minix, QNX |
| 하이브리드 | 둘의 절충 | Windows NT, macOS(XNU) |

## 2. 사용자 모드와 커널 모드 (Dual Mode)

CPU는 **모드 비트**로 현재 실행 권한을 구분합니다.

| 모드 | 할 수 있는 일 |
|---|---|
| **사용자 모드** (User Mode) | 일반 명령어만 실행. 하드웨어 직접 접근 X |
| **커널 모드** (Kernel Mode) | 모든 명령어(특권 명령어) 실행, 하드웨어 직접 제어 |

왜 나눌까? 일반 프로그램이 디스크를 마음대로 지우거나 다른 프로그램의 메모리를 읽으면 시스템 전체가 위험해지기 때문입니다. 위험한 작업은 **반드시 OS를 통해서만** 하게 만듭니다.

---

## 3. 시스템 콜 (System Call)

**사용자 프로그램이 커널의 기능을 요청하는 인터페이스**입니다.

```
Java: Files.readString(path)
      ↓
C 라이브러리: read()          ← 사용자 모드
      ↓  (trap 명령어 → 소프트웨어 인터럽트)
커널: sys_read() 실행          ← 커널 모드로 전환
      ↓  디스크에서 데이터 읽기
결과 반환 → 사용자 모드로 복귀
```

### 시스템 콜 종류
| 분류 | 예 (Linux) |
|---|---|
| 프로세스 제어 | `fork()`, `exec()`, `exit()`, `wait()` |
| 파일 조작 | `open()`, `read()`, `write()`, `close()` |
| 장치 관리 | `ioctl()` |
| 정보 유지 | `getpid()`, `time()` |
| 통신 | `socket()`, `pipe()`, `mmap()` |

> 시스템 콜은 모드 전환 비용이 있어서, 잦은 호출은 성능에 영향을 줍니다. 그래서 버퍼링(`BufferedReader`)으로 호출 횟수를 줄입니다.

## 4. 인터럽트 (Interrupt)

**CPU가 프로그램을 실행하는 중에 처리해야 할 일이 생겼다고 알리는 신호**입니다.

### 종류
| 종류 | 발생 원인 | 예 |
|---|---|---|
| **하드웨어 인터럽트** | 외부 장치 | 키보드 입력, 디스크 I/O 완료, **타이머** |
| **소프트웨어 인터럽트 (트랩)** | 프로그램 실행 중 | **시스템 콜**, 0으로 나누기, 페이지 폴트 |

### 처리 과정
```
1. 인터럽트 발생
2. CPU가 현재 실행 중인 명령어를 마침
3. 현재 상태(PC, 레지스터)를 저장
4. 인터럽트 벡터 테이블에서 해당 인터럽트 처리 루틴(ISR) 주소를 찾음
5. ISR 실행 (커널 모드)
6. 저장한 상태 복원 → 원래 작업 재개
```

> **타이머 인터럽트**가 중요합니다. 일정 시간마다 발생해서 OS가 CPU를 되찾아 올 수 있게 해 줍니다. 이것이 없으면 무한 루프를 도는 프로그램이 CPU를 영원히 독점합니다. (→ 선점형 스케줄링)

### 폴링 vs 인터럽트
| 방식 | 설명 | 단점 |
|---|---|---|
| 폴링 (Polling) | CPU가 주기적으로 장치 상태를 확인 | 할 일이 없어도 계속 확인 → CPU 낭비 |
| 인터럽트 | 장치가 끝나면 CPU에 알림 | 인터럽트가 너무 잦으면 오버헤드 |

---

## 5. 부팅 과정 (간단히)

```
전원 ON → BIOS/UEFI (하드웨어 점검, POST)
       → 부트로더 (GRUB 등) 로드
       → 커널을 메모리에 적재
       → init/systemd 실행 → 서비스 시작
       → 로그인 화면
```

## 6. 면접 질문

1. **운영체제의 역할은?**
   → 하드웨어 자원(CPU, 메모리, 저장장치, 입출력)을 관리하고, 프로그램에 추상화된 인터페이스를 제공하며, 프로그램 간 보호를 담당합니다.
2. **사용자 모드와 커널 모드를 나누는 이유는?**
   → 일반 프로그램이 하드웨어나 다른 프로세스 영역에 직접 접근하지 못하게 해 시스템을 보호하기 위해서입니다.
3. **시스템 콜이란?**
   → 사용자 프로그램이 커널의 기능(파일, 프로세스, 네트워크 등)을 사용하기 위한 인터페이스로, 호출 시 커널 모드로 전환됩니다.
4. **인터럽트와 트랩의 차이는?**
   → 인터럽트는 외부 하드웨어가 비동기적으로 발생시키고, 트랩은 프로그램 실행 중 시스템 콜이나 예외로 동기적으로 발생합니다.

---

## 핵심 정리
- OS = 자원 관리자 + 하드웨어 추상화 + 보호
- 사용자 모드 ↔ 커널 모드, 전환은 시스템 콜/인터럽트로
- 타이머 인터럽트 덕분에 OS가 CPU를 되찾을 수 있음
