# 02. 프로세스와 스레드 (Process & Thread)

> **학습 목표**
> - 프로세스의 메모리 구조와 PCB를 설명할 수 있다.
> - 프로세스 상태 전이를 그릴 수 있다.
> - 프로세스와 스레드의 차이, 멀티프로세스와 멀티스레드의 장단점을 비교할 수 있다.
> - 컨텍스트 스위칭과 IPC를 설명할 수 있다.

---

## 1. 프로그램 vs 프로세스

- **프로그램**: 디스크에 저장된 실행 파일 (정적)
- **프로세스**: 메모리에 올라와 **실행 중인 프로그램** (동적). OS로부터 자원을 할당받는 **작업의 단위**

같은 크롬 프로그램을 두 번 실행하면 프로세스는 2개입니다.

---

## 2. 프로세스 메모리 구조

```
높은 주소
+------------------+
|     Stack        |  지역변수, 매개변수, 복귀 주소   ↓ 아래로 자람
|        ↓         |
|                  |
|        ↑         |
|     Heap         |  동적 할당 (new, malloc)         ↑ 위로 자람
+------------------+
|     Data         |  전역변수, static 변수 (초기화된 것 / BSS: 초기화 안 된 것)
+------------------+
|     Code (Text)  |  실행할 기계어 코드 (읽기 전용)
+------------------+
낮은 주소
```

| 영역 | 저장 내용 | 생성 시점 |
|---|---|---|
| Code | 프로그램 명령어 | 컴파일 시 크기 결정 |
| Data | 전역·static 변수 | 프로그램 시작 시 |
| Heap | `new`로 만든 객체 | 런타임 (프로그래머가 할당) |
| Stack | 함수 호출 정보, 지역변수 | 함수 호출 시 |

> Java에서는 객체가 Heap에, 지역 변수(참조값 포함)는 Stack에 저장됩니다. Heap은 GC가 관리합니다.

---

## 3. PCB (Process Control Block)

OS가 **프로세스를 관리하기 위해 저장하는 정보 묶음**입니다. 커널 메모리에 저장됩니다.

| 항목 | 내용 |
|---|---|
| PID | 프로세스 식별 번호 |
| 프로세스 상태 | new, ready, running, waiting, terminated |
| **프로그램 카운터 (PC)** | 다음에 실행할 명령어 주소 |
| **CPU 레지스터** | 실행 중이던 레지스터 값 |
| 스케줄링 정보 | 우선순위 |
| 메모리 관리 정보 | 페이지 테이블 주소 |
| 입출력 상태 | 열린 파일 목록 |

---

## 4. 프로세스 상태 전이

```
 [New] ──admit──> [Ready] ──dispatch──> [Running] ──exit──> [Terminated]
                   ↑  ↑                   │   │
                   │  └───── 인터럽트 ──────┘   │
                   │     (시간 할당량 만료)      │ I/O 요청, 이벤트 대기
                   │                          ↓
                   └─────── I/O 완료 ─────── [Waiting]
```

| 상태 | 의미 |
|---|---|
| New | 프로세스 생성 중 |
| **Ready** | CPU만 받으면 실행 가능, 준비 큐에서 대기 |
| **Running** | CPU를 받아 실행 중 |
| **Waiting (Blocked)** | I/O 등 이벤트를 기다리는 중 (CPU를 줘도 실행 불가) |
| Terminated | 실행 종료 |

- Ready → Running: **디스패치** (스케줄러가 선택)
- Running → Ready: 시간 할당량 만료(타이머 인터럽트), 더 높은 우선순위 프로세스 등장
- Running → Waiting: I/O 요청
- Waiting → Ready: I/O 완료

---

## 5. 컨텍스트 스위칭 (Context Switching)

**CPU가 실행 중인 프로세스를 바꿀 때, 현재 상태를 PCB에 저장하고 다음 프로세스의 상태를 PCB에서 복원**하는 과정입니다.

```
프로세스 A 실행 중
   ↓ 인터럽트/시스템 콜
A의 상태 → PCB_A에 저장
PCB_B에서 상태 복원
   ↓
프로세스 B 실행
```

- 이 동안 CPU는 실제 작업을 못 하므로 **오버헤드**입니다.
- 프로세스 전환 시 **캐시와 TLB가 무효화**되어 이후 한동안 느려집니다.
- 스레드 간 전환은 메모리 공간을 공유하므로 **프로세스 전환보다 가볍습니다.**

---

## 6. 스레드 (Thread)

**프로세스 안에서 실행되는 흐름의 단위**입니다. 한 프로세스는 여러 스레드를 가질 수 있습니다.

```
          프로세스
+--------------------------------+
|  Code  |  Data  |  Heap        |  ← 스레드들이 공유
+--------------------------------+
| Thread1 | Thread2 | Thread3    |
| Stack   | Stack   | Stack      |  ← 스레드마다 따로
| PC,레지스터| PC,레지스터| PC,레지스터 |
+--------------------------------+
```

- **공유**: Code, Data, Heap, 열린 파일
- **독립**: Stack, PC, 레지스터 (각자 다른 함수를 실행해야 하므로)

---

## 7. 프로세스 vs 스레드

| 항목 | 프로세스 | 스레드 |
|---|---|---|
| 정의 | 자원 할당의 단위 | CPU 실행(스케줄링)의 단위 |
| 메모리 | 독립된 주소 공간 | 같은 프로세스 내 공유 |
| 생성·전환 비용 | 큼 | 작음 |
| 통신 | IPC 필요 (복잡) | 공유 메모리로 쉬움 |
| 안정성 | 하나가 죽어도 다른 프로세스 영향 X | **하나가 죽으면 프로세스 전체가 죽을 수 있음** |
| 동기화 | 거의 필요 X | **필요** (공유 자원 경쟁) |

### 멀티프로세스 vs 멀티스레드
| | 멀티프로세스 | 멀티스레드 |
|---|---|---|
| 장점 | 안정성 (격리) | 자원 효율, 빠른 전환, 쉬운 데이터 공유 |
| 단점 | 메모리 사용 많음, 전환 비용 큼 | 동기화 문제, 디버깅 어려움 |
| 예 | 크롬 브라우저(탭마다 프로세스), Nginx 워커 | **Spring 톰캣**(요청마다 스레드), 게임 |

> **Spring MVC + Tomcat**은 요청 하나당 스레드 풀의 스레드 하나가 처리합니다. 그래서 싱글톤 빈에 상태(필드)를 두면 여러 스레드가 동시에 바꿔 버그가 생깁니다.

## 8. 프로세스 생성: fork()와 exec()

```c
pid_t pid = fork();     // 현재 프로세스를 복제
if (pid == 0) {
    // 자식 프로세스
    exec("/bin/ls");    // 자식의 메모리를 새 프로그램으로 교체
} else {
    wait(NULL);         // 부모는 자식 종료 대기
}
```
- `fork()`: 부모를 복제해 자식 생성. **Copy-on-Write**로 실제로 쓰기가 일어날 때만 메모리를 복사
- **좀비 프로세스**: 자식이 종료됐는데 부모가 `wait()`로 회수하지 않아 PCB가 남은 상태
- **고아 프로세스**: 부모가 먼저 종료된 자식 → init(systemd)이 입양

## 9. IPC (Inter-Process Communication)

프로세스는 메모리가 분리되어 있어서 데이터를 주고받으려면 OS가 제공하는 방법이 필요합니다.

| 방식 | 설명 |
|---|---|
| **공유 메모리** | 같은 메모리 영역을 함께 매핑. 가장 빠르지만 동기화 필요 |
| **메시지 전달** | 커널을 통해 메시지 송수신. 안전하지만 느림 |
| 파이프 | 단방향 통신 (`ls \| grep`). 익명 파이프는 부모-자식 사이만 |
| 네임드 파이프 (FIFO) | 이름이 있어 관련 없는 프로세스끼리도 통신 |
| 메시지 큐 | 커널이 관리하는 큐 |
| **소켓** | 네트워크를 통해 다른 컴퓨터 프로세스와도 통신 |
| 시그널 | 이벤트 알림 (`kill -9`) |

---

## 10. Java 스레드 예시

```java
// Runnable + Thread
Thread t = new Thread(() -> System.out.println("hello from " + Thread.currentThread().getName()));
t.start();     // run()이 아니라 start()! run()은 그냥 메서드 호출
t.join();      // 종료까지 대기

// 스레드 풀 (실무에서는 직접 생성보다 풀 사용)
ExecutorService pool = Executors.newFixedThreadPool(4);
Future<Integer> f = pool.submit(() -> 1 + 1);
System.out.println(f.get());
pool.shutdown();
```

> Java 21의 **가상 스레드(Virtual Thread)** 는 OS 스레드보다 훨씬 가벼운 JVM 관리 스레드로, I/O가 많은 서버에서 수많은 동시 요청을 처리하기 좋습니다.

## 11. 면접 질문

1. **프로세스와 스레드의 차이는?**
   → 프로세스는 독립된 메모리 공간을 가진 실행 단위이고, 스레드는 프로세스 내에서 Code·Data·Heap을 공유하고 Stack만 따로 가지는 실행 흐름입니다.
2. **스레드마다 Stack을 따로 가지는 이유는?**
   → 각 스레드가 독립적으로 함수를 호출하고 실행 흐름을 가져야 하므로, 호출 정보와 지역변수를 분리해야 하기 때문입니다.
3. **컨텍스트 스위칭이란? 스레드가 더 빠른 이유는?**
   → 실행 중인 작업의 상태를 저장하고 다른 작업 상태를 복원하는 것입니다. 스레드는 주소 공간을 공유해 메모리 매핑 교체와 TLB 플러시가 필요 없어 더 가볍습니다.
4. **멀티스레드의 단점은?**
   → 공유 자원 접근 시 경쟁 상태가 생겨 동기화가 필요하고, 한 스레드의 오류가 전체 프로세스에 영향을 줍니다.

---

## 핵심 정리
- 프로세스 = 실행 중인 프로그램, 메모리 구조 Code/Data/Heap/Stack
- PCB에 상태 저장 → 컨텍스트 스위칭
- 스레드 = Stack·PC·레지스터만 독립, 나머지 공유 → 가볍지만 동기화 필요
