# 03. CPU 스케줄링 (CPU Scheduling)

> **학습 목표**
> - 스케줄링 평가 지표(대기 시간, 반환 시간, 응답 시간)를 계산할 수 있다.
> - 선점형과 비선점형의 차이를 설명할 수 있다.
> - FCFS, SJF, SRTF, Priority, Round Robin, MLFQ의 동작과 장단점을 비교할 수 있다.

---

## 1. CPU 스케줄링이란?

Ready 큐에 있는 여러 프로세스 중 **다음에 CPU를 누구에게 줄지 결정**하는 것입니다.

### CPU 버스트와 I/O 버스트
프로세스는 CPU를 쓰는 구간(CPU burst)과 I/O를 기다리는 구간(I/O burst)을 번갈아 가집니다.
- **CPU 바운드**: 계산이 많음 (영상 인코딩, 머신러닝 학습)
- **I/O 바운드**: 입출력이 많음 (웹 서버, 텍스트 편집기) → 짧은 CPU 버스트가 자주

---

## 2. 평가 지표

| 지표 | 정의 | 목표 |
|---|---|---|
| CPU 이용률 | CPU가 일한 시간 비율 | 높게 |
| 처리량 (Throughput) | 단위 시간당 완료한 프로세스 수 | 높게 |
| **반환 시간 (Turnaround)** | 도착 ~ 완료까지 걸린 시간 | 낮게 |
| **대기 시간 (Waiting)** | Ready 큐에서 기다린 시간의 합 | 낮게 |
| **응답 시간 (Response)** | 도착 ~ **처음 CPU를 받을 때**까지 | 낮게 (대화형 시스템) |

- 반환 시간 = 완료 시각 - 도착 시각
- 대기 시간 = 반환 시간 - 실행 시간(버스트)

---

## 3. 선점형 vs 비선점형

| 구분 | 설명 | 예 |
|---|---|---|
| **비선점형** (Non-preemptive) | 프로세스가 CPU를 **스스로 놓을 때까지**(종료, I/O) 뺏지 않음 | FCFS, SJF |
| **선점형** (Preemptive) | OS가 실행 중인 프로세스에게서 CPU를 **강제로 뺏을 수 있음** | SRTF, RR, 선점형 Priority |

현대 OS(Windows, Linux, macOS)는 모두 **선점형**입니다. 응답성을 위해서입니다.

---

## 4. 스케줄링 알고리즘

예시 프로세스 (모두 0초에 도착):
| 프로세스 | 버스트 시간 |
|---|---|
| P1 | 24 |
| P2 | 3 |
| P3 | 3 |

### 4-1. FCFS (First-Come, First-Served)
**먼저 온 순서대로** 실행합니다. (비선점)

```
| P1                       | P2 | P3 |
0                         24   27   30
대기 시간: P1=0, P2=24, P3=27 → 평균 17
```

- 구현이 쉽고 공정해 보임
- **호위 효과 (Convoy Effect)**: 긴 작업 하나 뒤에 짧은 작업들이 줄줄이 기다림

순서만 P2, P3, P1로 바꿔도:
```
| P2 | P3 | P1                       |
0    3    6                         30
평균 대기 = (0 + 3 + 6) / 3 = 3
```

### 4-2. SJF (Shortest Job First)
**실행 시간이 가장 짧은 작업부터** 실행합니다. (비선점)

- **평균 대기 시간이 최소**임이 증명되어 있습니다.
- 문제 1: 다음 CPU 버스트 시간을 **미리 알 수 없음** → 과거 기록으로 예측 (지수 평균)
- 문제 2: **기아 (Starvation)** — 긴 작업은 짧은 작업이 계속 들어오면 영원히 실행 못 함

### 4-3. SRTF (Shortest Remaining Time First)
SJF의 **선점형** 버전. 새 프로세스의 실행 시간이 현재 프로세스의 **남은 시간**보다 짧으면 CPU를 뺏습니다.

| 프로세스 | 도착 | 버스트 |
|---|---|---|
| P1 | 0 | 8 |
| P2 | 1 | 4 |
| P3 | 2 | 9 |
| P4 | 3 | 5 |

```
| P1 | P2       | P4         | P1             | P3                 |
0    1          5           10               17                  26
t=1: P2(4) < P1 남은 7 → 선점
```
평균 대기 = ((10-1) + 0 + (17-2) + (5-3)) / 4 = (9 + 0 + 15 + 2) / 4 = 6.5

### 4-4. 우선순위 스케줄링 (Priority)
**우선순위가 높은 프로세스부터** 실행합니다. (선점/비선점 모두 가능)

- 문제: **기아** — 우선순위 낮은 프로세스가 실행되지 못함
- 해결: **에이징 (Aging)** — 오래 기다릴수록 우선순위를 점점 높여 줌

### 4-5. 라운드 로빈 (Round Robin, RR)
각 프로세스에 **같은 시간 할당량(Time Quantum)** 을 주고, 다 쓰면 Ready 큐 맨 뒤로 보냅니다. (선점)

Time Quantum = 4, 위의 P1(24), P2(3), P3(3):
```
| P1 | P2 | P3 | P1 | P1 | P1 | P1 | P1 |
0    4    7   10   14   18   22   26   30
대기 시간: P1 = 10 - 4 = 6, P2 = 4, P3 = 7 → 평균 5.67
```

- **응답 시간이 좋음** → 대화형(시분할) 시스템에 적합
- Time Quantum 선택이 중요:
  - **너무 크면** → FCFS와 같아짐
  - **너무 작으면** → 컨텍스트 스위칭이 너무 잦아 오버헤드 증가
- 일반적으로 10~100ms

### 4-6. 다단계 큐 / 다단계 피드백 큐 (MLQ / MLFQ)

**다단계 큐 (Multilevel Queue)**: 프로세스를 성격별로 여러 큐로 나눔 (시스템 > 대화형 > 배치). 큐 간 이동 불가.

**다단계 피드백 큐 (MLFQ)**: 큐 간 **이동이 가능**합니다.
```
Q0 (RR, quantum 8)    ← 새 프로세스는 여기서 시작
   ↓ 시간을 다 쓰면 아래로
Q1 (RR, quantum 16)
   ↓
Q2 (FCFS)
```
- CPU를 오래 쓰는 프로세스(CPU 바운드)는 점점 아래 큐로 → 우선순위 하락
- 짧게 쓰고 I/O 하러 가는 프로세스(I/O 바운드, 대화형)는 위에 남음 → 빠른 응답
- 오래 기다린 프로세스는 위로 올려 기아 방지
- 실행 시간을 미리 몰라도 SJF와 비슷한 효과 → **현대 OS 스케줄러의 기본 아이디어**

> Linux는 과거 CFS(Completely Fair Scheduler, 실행 시간이 가장 적은 프로세스를 레드블랙 트리로 관리)를 썼고, 커널 6.6부터 EEVDF 스케줄러로 바뀌었습니다.

## 5. 비교 정리

| 알고리즘 | 선점 | 장점 | 단점 |
|---|---|---|---|
| FCFS | X | 단순 | 호위 효과 |
| SJF | X | 평균 대기 최소 | 실행 시간 예측 필요, 기아 |
| SRTF | O | SJF보다 더 좋은 평균 대기 | 기아, 잦은 문맥 전환 |
| Priority | O/X | 중요 작업 우선 | 기아 → 에이징으로 해결 |
| RR | O | 응답 시간 좋음, 공정 | 퀀텀 설정에 민감 |
| MLFQ | O | 적응적, 범용 | 구현 복잡 |

## 6. 면접 질문

1. **선점형과 비선점형 스케줄링의 차이는?**
   → 비선점형은 프로세스가 스스로 CPU를 놓을 때까지 기다리고, 선점형은 OS가 타이머 인터럽트 등으로 강제로 CPU를 회수할 수 있습니다.
2. **기아 현상과 해결 방법은?**
   → 우선순위가 낮거나 실행 시간이 긴 프로세스가 계속 밀려 실행되지 못하는 현상이며, 에이징으로 해결합니다.
3. **라운드 로빈의 타임 퀀텀이 너무 작거나 크면?**
   → 너무 크면 FCFS처럼 동작하고, 너무 작으면 컨텍스트 스위칭 오버헤드가 커집니다.
4. **SJF가 이론적으로 최적인데 실제로 쓰기 어려운 이유는?**
   → 프로세스의 다음 CPU 버스트 시간을 미리 알 수 없기 때문입니다.

---

## 핵심 정리
- 지표: 반환 시간 = 완료 - 도착, 대기 시간 = 반환 - 실행
- FCFS(호위 효과) / SJF(최적, 예측 불가, 기아) / RR(응답성, 퀀텀) / MLFQ(현대 OS 기본)
- 기아 → 에이징
