# 06. 메모리 관리 (Memory Management)

> **학습 목표**
> - 논리 주소와 물리 주소, MMU의 역할을 설명할 수 있다.
> - 연속 할당과 단편화(내부/외부)를 설명할 수 있다.
> - 페이징과 세그멘테이션의 원리와 장단점을 비교할 수 있다.
> - TLB가 필요한 이유를 설명할 수 있다.

---

## 1. 논리 주소와 물리 주소

| 구분 | 설명 |
|---|---|
| **논리 주소** (가상 주소) | 프로세스가 보는 주소. 각 프로세스는 0번지부터 시작한다고 생각함 |
| **물리 주소** | 실제 RAM의 주소 |

**MMU (Memory Management Unit)**: CPU 안의 하드웨어로, 논리 주소를 물리 주소로 **실행 중에 변환**합니다.

```
CPU ──논리 주소 346──> [MMU: 재배치 레지스터 14000] ──물리 주소 14346──> 메모리
```

왜 나눌까?
- 프로세스끼리 **메모리 보호** (다른 프로세스 주소에 접근 불가)
- 프로그램을 메모리 어디에 올려도 동작 (재배치)
- 실제 메모리보다 큰 프로그램 실행 가능 (가상 메모리)

---

## 2. 연속 메모리 할당

프로세스를 메모리의 **연속된 한 공간**에 올리는 방식입니다.

### 할당 전략 (빈 공간 = 홀(hole) 중 어디에?)
| 전략 | 방법 |
|---|---|
| 최초 적합 (First Fit) | 처음 발견한 충분히 큰 홀 → **빠름** |
| 최적 적합 (Best Fit) | 크기가 가장 딱 맞는 홀 → 작은 조각이 많이 남음 |
| 최악 적합 (Worst Fit) | 가장 큰 홀 |

### 단편화 (Fragmentation)

**외부 단편화 (External Fragmentation)**
```
[P1][  20KB  ][P2][ 15KB ][P3][ 10KB ]
빈 공간 합계 45KB인데 30KB짜리 프로세스를 못 넣음 (연속된 공간이 없어서)
```
- 해결: **압축(Compaction)** — 프로세스들을 한쪽으로 몰아 빈 공간을 합침 (비용 큼)
- 근본 해결: **페이징** (연속으로 할 필요를 없앰)

**내부 단편화 (Internal Fragmentation)**
```
4KB 블록 단위로 줄 때 프로세스가 13KB 필요 → 16KB 할당 → 3KB 낭비 (블록 안쪽 낭비)
```

## 3. 페이징 (Paging)

프로세스의 논리 메모리를 **고정 크기의 페이지(Page)** 로, 물리 메모리를 **같은 크기의 프레임(Frame)** 으로 나누고, 페이지를 **아무 빈 프레임에나** 배치합니다.

```
 논리 메모리         페이지 테이블          물리 메모리
+---------+       +------+-------+       +---------+ 프레임 0
| Page 0  | ───>  |  0   |   5   |       |         |
| Page 1  |       |  1   |   2   |       +---------+ 프레임 1
| Page 2  |       |  2   |   7   |       |         |
| Page 3  |       |  3   |   0   |       +---------+ 프레임 2
+---------+       +------+-------+       | Page 1  |
                  페이지 → 프레임          +---------+ ...
```

### 주소 변환
논리 주소 = **페이지 번호(p) + 오프셋(d)**
```
페이지 크기 4KB (2¹² = 4096) → 하위 12비트가 오프셋

논리 주소 0x00003ABC
  페이지 번호 = 0x3 → 페이지 테이블 조회 → 프레임 0
  오프셋     = 0xABC
물리 주소 = 프레임 0 시작 주소 + 0xABC
```

### 장단점
| 장점 | 단점 |
|---|---|
| **외부 단편화 없음** | **내부 단편화** 있음 (마지막 페이지) |
| 메모리 할당·관리 단순 | 페이지 테이블 저장 공간 필요 |
| 페이지 단위 공유·보호 쉬움 | 주소 변환 시 메모리 접근이 **2번** (테이블 + 데이터) |

### 페이지 테이블이 너무 클 때
32비트 주소, 4KB 페이지 → 2²⁰ = 약 100만 개 엔트리 × 4B = **프로세스당 4MB**
- **계층적 페이징 (다단계 페이지 테이블)**: 테이블도 페이지로 나눠 쓰는 부분만 메모리에 둠 (x86-64는 4~5단계)
- 해시 페이지 테이블, 역 페이지 테이블

## 4. TLB (Translation Lookaside Buffer)

페이징은 데이터 한 번 읽을 때 **페이지 테이블 접근 + 실제 데이터 접근 = 메모리 2번**이 필요합니다. 이를 줄이기 위한 **페이지 테이블 전용 캐시**가 TLB입니다.

```
논리 주소 → TLB 조회
             ├─ Hit  → 바로 프레임 번호 획득 → 메모리 1번 접근
             └─ Miss → 페이지 테이블 조회 → TLB에 저장 → 메모리 접근
```

- TLB 적중률은 보통 99% 이상 (지역성 덕분)
- **컨텍스트 스위칭 시 TLB를 비워야(flush)** 해서 프로세스 전환 비용이 커집니다. (ASID로 프로세스 구분해 완화)

### 유효 메모리 접근 시간 (EAT)
```
메모리 접근 100ns, TLB 적중률 99%, TLB 접근 시간 무시
EAT = 0.99 × 100 + 0.01 × 200 = 101ns
```

## 5. 세그멘테이션 (Segmentation)

프로그램을 **논리적 의미 단위(세그먼트)** 로 나눕니다: 코드, 데이터, 스택, 힙 등. 세그먼트마다 **크기가 다릅니다.**

```
세그먼트 테이블
+-----+-------+-------+
| 번호 | base  | limit |
+-----+-------+-------+
|  0  | 1400  | 1000  |  코드
|  1  | 6300  |  400  |  데이터
|  2  | 4300  | 1100  |  스택
+-----+-------+-------+

논리 주소 (세그먼트 2, 오프셋 53)
→ 53 < limit 1100 확인 → 물리 주소 = 4300 + 53 = 4353
→ 오프셋 ≥ limit 이면 Segmentation Fault!
```

| 장점 | 단점 |
|---|---|
| 논리 단위라 **보호·공유가 자연스러움** (코드는 읽기 전용) | 크기가 달라 **외부 단편화** 발생 |
| 내부 단편화 없음 | 할당 관리 복잡 |

### 페이징 vs 세그멘테이션
| 항목 | 페이징 | 세그멘테이션 |
|---|---|---|
| 분할 단위 | 고정 크기 | 가변 크기 (논리 단위) |
| 외부 단편화 | 없음 | 있음 |
| 내부 단편화 | 있음 | 없음 |
| 보호·공유 | 페이지 단위 | 의미 단위로 자연스러움 |

> **페이지드 세그멘테이션**: 세그먼트로 나눈 뒤 각 세그먼트를 다시 페이지로 나눠 둘의 장점을 합칩니다. 현대 x86-64는 사실상 **페이징만** 사용합니다.

## 6. 스와핑 (Swapping)

메모리가 부족할 때 **프로세스 전체를 디스크(스왑 영역)로 내보내고(swap out)**, 필요할 때 다시 올리는(swap in) 기법입니다. 현대 OS는 프로세스 전체가 아니라 **페이지 단위**로 스왑합니다. (→ `07.가상메모리.md`)

## 7. 면접 질문

1. **내부 단편화와 외부 단편화의 차이는?**
   → 내부 단편화는 할당된 블록 안에서 사용하지 않는 공간이 낭비되는 것이고, 외부 단편화는 빈 공간의 합은 충분하지만 연속되지 않아 할당할 수 없는 것입니다.
2. **페이징이란? 장점은?**
   → 메모리를 고정 크기 페이지·프레임으로 나눠 불연속적으로 배치하는 기법으로, 외부 단편화를 없앱니다.
3. **TLB란?**
   → 페이지 테이블 변환 결과를 저장하는 MMU 안의 캐시로, 주소 변환 시 메모리 접근 횟수를 줄입니다.
4. **Segmentation Fault는 왜 발생하나요?**
   → 프로세스가 허용되지 않은 메모리 영역(세그먼트 limit 초과, 읽기 전용 영역에 쓰기, null 포인터)에 접근할 때 발생합니다.

---

## 핵심 정리
- 논리 주소 → (MMU) → 물리 주소
- 연속 할당 → 외부 단편화 / 고정 블록 → 내부 단편화
- 페이징: 고정 크기, 외부 단편화 X, TLB로 변환 속도 보완
- 세그멘테이션: 논리 단위, 보호 용이, 외부 단편화 O
