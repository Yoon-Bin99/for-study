## 1. SQL 분류

| 분류 | 의미 | 명령어 |
|---|---|---|
| **DDL** (Definition) | 구조 정의 | `CREATE`, `ALTER`, `DROP`, `TRUNCATE` |
| **DML** (Manipulation) | 데이터 조작 | `SELECT`, `INSERT`, `UPDATE`, `DELETE` |
| **DCL** (Control) | 권한 | `GRANT`, `REVOKE` |
| **TCL** (Transaction) | 트랜잭션 | `COMMIT`, `ROLLBACK`, `SAVEPOINT` |

### DELETE vs TRUNCATE vs DROP
| 명령 | 대상 | 롤백 | 속도 | 비고 |
|---|---|---|---|---|
| DELETE | 행 (WHERE 가능) | O | 느림 (행마다 로그) | 구조 유지 |
| TRUNCATE | 모든 행 | X (대부분 DBMS) | 빠름 | 구조 유지, AUTO_INCREMENT 초기화 |
| DROP | 테이블 자체 | X | 빠름 | 구조까지 삭제 |

## 2. 예제 테이블

```sql
CREATE TABLE department (
    dept_id   INT PRIMARY KEY,
    dept_name VARCHAR(50) NOT NULL
);

CREATE TABLE employee (
    emp_id   INT PRIMARY KEY AUTO_INCREMENT,
    name     VARCHAR(50) NOT NULL,
    salary   INT,
    dept_id  INT,
    FOREIGN KEY (dept_id) REFERENCES department(dept_id)
);
```

```
department                 employee
| dept_id | dept_name |    | emp_id | name | salary | dept_id |
|---------|-----------|    |--------|------|--------|---------|
| 1       | 개발       |    | 1      | 김   | 5000   | 1       |
| 2       | 기획       |    | 2      | 이   | 4000   | 1       |
| 3       | 디자인     |    | 3      | 박   | 4500   | 2       |
                           | 4      | 최   | 3000   | NULL    |
```

## 3. SELECT 실행 순서

**작성 순서**와 **논리적 실행 순서**가 다릅니다.

```sql
SELECT   dept_id, AVG(salary) AS avg_sal     -- 5
FROM     employee                             -- 1
WHERE    salary > 3000                        -- 2
GROUP BY dept_id                              -- 3
HAVING   AVG(salary) > 4000                   -- 4
ORDER BY avg_sal DESC                         -- 6
LIMIT    10;                                  -- 7
```

```
FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT
```

이 순서 때문에:
- `WHERE`에서는 SELECT의 별칭(`avg_sal`)을 쓸 수 없습니다.
- `ORDER BY`에서는 별칭을 쓸 수 있습니다.
- **WHERE는 그룹핑 전 행을 거르고, HAVING은 그룹핑 후 그룹을 거릅니다.** 집계 함수 조건은 HAVING에.

## 4. JOIN

### INNER JOIN — 양쪽에 모두 있는 것만
```sql
SELECT e.name, d.dept_name
FROM employee e
INNER JOIN department d ON e.dept_id = d.dept_id;
```
```
| 김 | 개발 |
| 이 | 개발 |
| 박 | 기획 |      ← 최(dept NULL)와 디자인(직원 없음)은 제외
```

### LEFT (OUTER) JOIN — 왼쪽은 모두, 오른쪽은 있으면
```sql
SELECT e.name, d.dept_name
FROM employee e
LEFT JOIN department d ON e.dept_id = d.dept_id;
```
```
| 김 | 개발 |
| 이 | 개발 |
| 박 | 기획 |
| 최 | NULL |      ← 왼쪽(직원)은 모두 나옴
```

### RIGHT JOIN — 오른쪽은 모두
→ 디자인 부서가 `NULL | 디자인` 으로 포함됩니다.

### FULL OUTER JOIN — 양쪽 모두
→ MySQL은 지원하지 않아 `LEFT JOIN UNION RIGHT JOIN`으로 구현합니다.

### CROSS JOIN — 모든 조합 (카테시안 곱)
→ 4행 × 3행 = 12행

### SELF JOIN — 자기 자신과 조인
```sql
-- 직원과 그 매니저 (manager_id 컬럼이 있다고 가정)
SELECT e.name, m.name AS manager
FROM employee e LEFT JOIN employee m ON e.manager_id = m.emp_id;
```

```
  INNER         LEFT          RIGHT         FULL OUTER
 ( A (█) B )  ( █(█) B )   ( A (█)█ )    ( █(█)█ )
```

### 특정 조건: "부서에 속하지 않은 직원"
```sql
SELECT e.name
FROM employee e
LEFT JOIN department d ON e.dept_id = d.dept_id
WHERE d.dept_id IS NULL;
```

## 5. 집계와 GROUP BY

```sql
-- 부서별 인원과 평균 연봉 (부서 있는 직원만)
SELECT dept_id, COUNT(*) AS cnt, AVG(salary) AS avg_sal
FROM employee
WHERE dept_id IS NOT NULL
GROUP BY dept_id
HAVING COUNT(*) >= 2;
```

| 함수 | 설명 |
|---|---|
| `COUNT(*)` | 행 수 (NULL 포함) |
| `COUNT(col)` | **NULL이 아닌** 값의 수 |
| `SUM`, `AVG`, `MAX`, `MIN` | **NULL은 무시** |

> `AVG(salary)`에서 salary가 NULL인 행은 분모에서도 빠집니다. NULL을 0으로 치려면 `AVG(COALESCE(salary, 0))`.

## 6. 서브쿼리

```sql
-- 평균보다 연봉이 높은 직원 (스칼라 서브쿼리)
SELECT name FROM employee
WHERE salary > (SELECT AVG(salary) FROM employee);

-- 개발 부서 직원 (IN)
SELECT name FROM employee
WHERE dept_id IN (SELECT dept_id FROM department WHERE dept_name = '개발');

-- 직원이 있는 부서 (EXISTS: 존재 여부만 확인, 찾으면 바로 멈춤)
SELECT dept_name FROM department d
WHERE EXISTS (SELECT 1 FROM employee e WHERE e.dept_id = d.dept_id);

-- 인라인 뷰 (FROM 절 서브쿼리)
SELECT t.dept_id, t.avg_sal
FROM (SELECT dept_id, AVG(salary) AS avg_sal FROM employee GROUP BY dept_id) t
WHERE t.avg_sal > 4000;
```

| 종류 | 위치 | 설명 |
|---|---|---|
| 스칼라 서브쿼리 | SELECT, WHERE | 값 하나 반환 |
| 인라인 뷰 | FROM | 임시 테이블처럼 사용 |
| 중첩 서브쿼리 | WHERE | IN, EXISTS, ANY, ALL |
| 상관 서브쿼리 | WHERE | 바깥 쿼리의 값을 참조 (행마다 실행 → 느릴 수 있음) |

> **NOT IN과 NULL 함정**: 서브쿼리 결과에 NULL이 하나라도 있으면 `NOT IN`은 결과가 항상 비어 있습니다. `NOT EXISTS`를 쓰는 것이 안전합니다.

## 7. 윈도우 함수

GROUP BY는 행을 묶어 줄이지만, **윈도우 함수는 행을 유지한 채** 그룹별 계산 결과를 붙입니다.

```sql
SELECT name, dept_id, salary,
       RANK()       OVER (PARTITION BY dept_id ORDER BY salary DESC) AS rnk,
       AVG(salary)  OVER (PARTITION BY dept_id) AS dept_avg,
       SUM(salary)  OVER (ORDER BY emp_id) AS running_total
FROM employee;
```

| 함수 | 같은 값 처리 (100, 90, 90, 80) |
|---|---|
| `ROW_NUMBER()` | 1, 2, 3, 4 (무조건 순번) |
| `RANK()` | 1, 2, 2, **4** (공동 순위 후 건너뜀) |
| `DENSE_RANK()` | 1, 2, 2, **3** (건너뛰지 않음) |

그 외: `LAG()`, `LEAD()` (이전/다음 행 값), `NTILE(n)`

### 실전: 부서별 연봉 1등
```sql
SELECT * FROM (
    SELECT name, dept_id, salary,
           ROW_NUMBER() OVER (PARTITION BY dept_id ORDER BY salary DESC) AS rn
    FROM employee
) t
WHERE rn = 1;
```

## 8. 기타 자주 쓰는 문법

```sql
-- UNION (중복 제거) vs UNION ALL (중복 유지, 더 빠름)
SELECT name FROM employee UNION ALL SELECT name FROM ex_employee;

-- CASE
SELECT name,
       CASE WHEN salary >= 5000 THEN '고액'
            WHEN salary >= 4000 THEN '중간'
            ELSE '일반' END AS grade
FROM employee;

-- NULL 처리
SELECT COALESCE(dept_id, 0) FROM employee;   -- NULL이면 0 (표준)
SELECT IFNULL(dept_id, 0) FROM employee;     -- MySQL

-- 페이징
SELECT * FROM employee ORDER BY emp_id LIMIT 10 OFFSET 20;
```

> **OFFSET 페이징의 문제**: `OFFSET 100000`이면 앞의 10만 행을 읽고 버립니다. 대용량에서는 `WHERE emp_id > 마지막ID ORDER BY emp_id LIMIT 10` 같은 **커서(키셋) 페이징**을 씁니다.

## 9. SQL Injection

```java
// 위험: 문자열 이어 붙이기
String sql = "SELECT * FROM users WHERE id = '" + input + "'";
// input = "' OR '1'='1"  → 모든 사용자 조회

// 안전: PreparedStatement (파라미터 바인딩)
PreparedStatement ps = conn.prepareStatement("SELECT * FROM users WHERE id = ?");
ps.setString(1, input);
```
JPA/MyBatis의 `#{}`, `:param` 바인딩도 같은 원리입니다. (MyBatis `${}`는 그대로 치환되어 위험)

## 10. 면접 질문

1. **WHERE와 HAVING의 차이는?**
   → WHERE는 그룹핑 전에 행을 필터링하고, HAVING은 GROUP BY 후 그룹을 필터링하며 집계 함수 조건을 사용할 수 있습니다.
2. **INNER JOIN과 LEFT JOIN의 차이는?**
   → INNER JOIN은 양쪽에 매칭되는 행만, LEFT JOIN은 왼쪽 테이블의 모든 행과 매칭되는 오른쪽 행(없으면 NULL)을 반환합니다.
3. **DELETE와 TRUNCATE의 차이는?**
   → DELETE는 조건으로 행을 하나씩 지우며 롤백 가능하고, TRUNCATE는 전체를 빠르게 비우며 보통 롤백할 수 없습니다.
4. **SQL Injection을 막는 방법은?**
   → PreparedStatement로 파라미터를 바인딩해 입력값이 SQL 구문으로 해석되지 않게 합니다.

## 핵심 정리
- 실행 순서: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT
- JOIN: INNER(교집합), LEFT/RIGHT(한쪽 전체), FULL, CROSS, SELF
- 윈도우 함수: 행 유지 + 그룹 계산 (ROW_NUMBER, RANK, DENSE_RANK)
- NOT IN + NULL 함정, OFFSET 페이징 성능, PreparedStatement
