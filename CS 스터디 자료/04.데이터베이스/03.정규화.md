# 03. 정규화 (Normalization)

> **학습 목표**
> - 이상 현상(삽입·갱신·삭제)을 예시로 설명할 수 있다.
> - 함수 종속(완전·부분·이행)을 판단할 수 있다.
> - 1NF ~ BCNF로 테이블을 분해할 수 있다.
> - 반정규화가 필요한 상황을 설명할 수 있다.

---

## 1. 왜 정규화를 하는가?

정규화는 **데이터 중복을 줄이고 이상 현상을 없애기 위해 테이블을 분해하는 과정**입니다.

### 정규화 안 된 테이블
```
수강 (학번, 이름, 학과, 학과사무실, 과목코드, 과목명, 성적)

| 학번 | 이름  | 학과  | 학과사무실 | 과목코드 | 과목명   | 성적 |
|------|------|------|----------|--------|---------|-----|
| 100  | 김철수 | 컴공  | 공학관301 | C01    | 자료구조  | A   |
| 100  | 김철수 | 컴공  | 공학관301 | C02    | 운영체제  | B   |
| 200  | 이영희 | 전자  | 공학관205 | C01    | 자료구조  | A   |
```

### 이상 현상 (Anomaly)
| 이상 | 상황 |
|---|---|
| **삽입 이상** | 아직 수강 신청을 안 한 신입생은 과목코드(기본키 일부)가 없어서 **학생 정보를 넣을 수 없음** |
| **갱신 이상** | 컴공 사무실이 바뀌면 **여러 행을 모두 고쳐야** 하고, 하나라도 빠뜨리면 데이터 불일치 |
| **삭제 이상** | 이영희가 유일한 수강을 취소하면 **학생 정보와 전자과 사무실 정보까지 사라짐** |

원인: 한 테이블에 **여러 주제(학생, 학과, 과목, 수강)** 가 섞여 있기 때문입니다.

---

## 2. 함수 종속 (Functional Dependency)

**X의 값이 정해지면 Y의 값이 하나로 정해질 때**, "Y는 X에 함수적으로 종속된다"라고 하고 `X → Y`로 씁니다.

```
학번 → 이름          (학번을 알면 이름을 안다)
학번 → 학과
학과 → 학과사무실
과목코드 → 과목명
{학번, 과목코드} → 성적
```

| 종류 | 의미 | 예 |
|---|---|---|
| **완전 함수 종속** | 기본키 **전체**에 종속 | {학번, 과목코드} → 성적 |
| **부분 함수 종속** | 기본키의 **일부**에만 종속 | {학번, 과목코드} 중 학번 → 이름 |
| **이행 함수 종속** | X → Y, Y → Z 이면 X → Z | 학번 → 학과 → 학과사무실 |

---

## 3. 정규형 단계

```
비정규형 → 1NF → 2NF → 3NF → BCNF → (4NF → 5NF)
         원자값  부분종속제거 이행종속제거  결정자가 모두 후보키
```

### 3-1. 제1정규형 (1NF): 모든 속성 값이 원자값

```
위반                                     1NF
| 학번 | 전화번호                |         | 학번 | 전화번호       |
|-----|------------------------|   →    |-----|---------------|
| 100 | 010-1111, 010-2222     |         | 100 | 010-1111      |
                                         | 100 | 010-2222      |
```
- 한 칸에 여러 값(리스트, 콤마 구분)을 넣지 않습니다.

### 3-2. 제2정규형 (2NF): 1NF + 부분 함수 종속 제거

기본키 {학번, 과목코드}에서 **학번에만 종속된 것(이름, 학과, 학과사무실)** 과 **과목코드에만 종속된 것(과목명)** 을 분리합니다.

```
학생 (학번, 이름, 학과, 학과사무실)
과목 (과목코드, 과목명)
수강 (학번, 과목코드, 성적)       ← 성적만 기본키 전체에 완전 종속
```

> 기본키가 **단일 속성**이면 부분 종속이 생길 수 없으므로 1NF면 자동으로 2NF입니다.

### 3-3. 제3정규형 (3NF): 2NF + 이행 함수 종속 제거

학생 테이블에 `학번 → 학과 → 학과사무실` 이행 종속이 남아 있습니다.

```
학생 (학번, 이름, 학과)
학과 (학과, 학과사무실)
```

→ 이제 학과사무실이 바뀌어도 학과 테이블 **한 행만** 수정하면 됩니다.

### 3-4. BCNF (Boyce-Codd Normal Form): 모든 결정자가 후보키

3NF여도 **후보키가 아닌 속성이 다른 속성을 결정**하면 이상 현상이 생길 수 있습니다.

```
특강 신청 (학생, 과목, 교수)
- 기본키: {학생, 과목}
- 규칙: 교수 한 명은 한 과목만 담당 → 교수 → 과목

| 학생 | 과목     | 교수 |
|-----|---------|-----|
| 100 | 데이터베이스 | P1 |
| 200 | 데이터베이스 | P2 |
| 100 | 네트워크    | P3 |
```
- `교수 → 과목`에서 결정자 **교수는 후보키가 아님** → BCNF 위반
- P1이 가르치는 과목이 바뀌면 여러 행 수정 필요

```
분해:
교수담당 (교수, 과목)
특강신청 (학생, 교수)
```

### 정리표
| 정규형 | 조건 |
|---|---|
| 1NF | 모든 값이 원자값 |
| 2NF | 1NF + 부분 함수 종속 제거 (완전 함수 종속) |
| 3NF | 2NF + 이행 함수 종속 제거 |
| BCNF | 모든 결정자가 후보키 |
| 4NF | 다치 종속 제거 |
| 5NF | 조인 종속 제거 |

> 실무에서는 보통 **3NF 또는 BCNF**까지 정규화합니다.

> **외우는 팁**: "도부이결다조" — **도**메인 원자값, **부**분 종속 제거, **이**행 종속 제거, **결**정자가 후보키, **다**치 종속, **조**인 종속

---

## 4. 정규화의 장단점

| 장점 | 단점 |
|---|---|
| 중복 감소 → 저장 공간 절약 | 테이블이 많아짐 |
| 이상 현상 제거 → 데이터 일관성 | **조회 시 JOIN이 많아져 성능 저하** 가능 |
| 구조 변경에 유연 | 쿼리가 복잡해짐 |

---

## 5. 반정규화 (Denormalization)

**조회 성능을 위해 의도적으로 중복을 허용**하는 것입니다. 정규화를 먼저 한 뒤, 성능 문제가 확인된 곳에 적용합니다.

| 기법 | 예 |
|---|---|
| 중복 컬럼 추가 | 주문 테이블에 회원 이름을 복사해 JOIN 제거 |
| 파생 컬럼 추가 | 게시글 테이블에 `comment_count` 저장 (매번 COUNT 안 함) |
| 테이블 병합 | 1:1 관계 테이블 합치기 |
| 요약(집계) 테이블 | 일별 매출 통계 테이블 |
| 테이블 분할 | 자주 쓰는 컬럼과 큰 컬럼(본문, 이미지)을 분리 |

- 단점: **데이터 불일치 위험** → 트리거, 애플리케이션 로직, 배치로 동기화를 관리해야 함
- 읽기가 압도적으로 많고 쓰기가 적은 곳에 적합

> **스냅샷 데이터는 중복이 아닙니다.** 주문 당시 상품 가격을 주문 테이블에 저장하는 것은 상품 가격이 나중에 바뀌어도 주문 금액은 그대로여야 하기 때문에 필요한 설계입니다.

---

## 6. 면접 질문

1. **정규화를 하는 이유는?**
   → 데이터 중복을 줄이고 삽입·갱신·삭제 이상을 제거해 일관성을 유지하기 위해서입니다.
2. **2NF와 3NF의 차이는?**
   → 2NF는 기본키 일부에만 종속되는 부분 함수 종속을 제거하고, 3NF는 기본키가 아닌 속성을 거쳐 종속되는 이행 함수 종속을 제거합니다.
3. **3NF와 BCNF의 차이는?**
   → BCNF는 모든 결정자가 후보키여야 해서 3NF보다 엄격합니다. 후보키가 아닌 속성이 기본키 일부를 결정하는 경우 3NF지만 BCNF는 아닙니다.
4. **반정규화는 언제 하나요?**
   → 정규화로 인한 JOIN이 많아 조회 성능이 문제 될 때, 일관성 관리 비용을 감수하고 중복을 허용합니다.

---

## 핵심 정리
- 이상 현상: 삽입·갱신·삭제 → 원인은 한 테이블에 여러 주제
- 1NF(원자값) → 2NF(부분 종속 X) → 3NF(이행 종속 X) → BCNF(결정자 = 후보키)
- 반정규화 = 성능을 위해 의도적 중복, 일관성 관리 필요
