# 01. 네트워크 기초와 계층 모델

> **학습 목표**
> - 네트워크 기본 용어(LAN, WAN, 프로토콜, 대역폭, 지연)를 설명할 수 있다.
> - OSI 7계층과 TCP/IP 4계층을 대응시키고 각 계층의 역할을 말할 수 있다.
> - 캡슐화와 역캡슐화 과정을 설명할 수 있다.

---

## 1. 기본 용어

| 용어 | 의미 |
|---|---|
| **노드 / 호스트** | 네트워크에 연결된 장치 (호스트는 주로 PC·서버처럼 데이터를 주고받는 끝 장치) |
| **LAN** (Local Area Network) | 건물·학교 등 좁은 범위 네트워크 |
| **WAN** (Wide Area Network) | 도시·국가 단위 넓은 네트워크 (인터넷) |
| **프로토콜** | 통신 규칙 (HTTP, TCP, IP ...) |
| **대역폭 (Bandwidth)** | 단위 시간당 전송 가능한 최대 데이터 양 (bps) |
| **처리량 (Throughput)** | 실제로 전송된 데이터 양 |
| **지연 (Latency)** | 데이터가 출발지에서 목적지까지 걸리는 시간 |
| **RTT** (Round Trip Time) | 요청을 보내고 응답이 돌아오기까지 왕복 시간 |

### 지연의 구성
- **전송 지연**: 데이터를 링크에 밀어 넣는 시간 (데이터 크기 / 대역폭)
- **전파 지연**: 신호가 물리적으로 이동하는 시간 (거리 / 신호 속도)
- **처리 지연**: 라우터가 헤더를 보고 경로를 결정하는 시간
- **큐잉 지연**: 라우터 버퍼에서 기다리는 시간 (혼잡할수록 증가)

### 회선 교환 vs 패킷 교환
| 방식 | 설명 | 예 |
|---|---|---|
| 회선 교환 | 통신 전에 **전용 경로를 확보**하고 독점 | 전통적인 전화망 |
| **패킷 교환** | 데이터를 **패킷으로 쪼개** 각각 전송, 경로 공유 | **인터넷** |

---

## 2. 왜 계층을 나누는가?

네트워크 통신은 매우 복잡합니다(전기 신호 → 주소 찾기 → 신뢰성 → 애플리케이션). 이를 **역할별 계층으로 나누면**:
- 각 계층은 **자기 일에만 집중**하고 아래 계층을 믿고 사용
- 한 계층의 기술이 바뀌어도(유선 → 와이파이) **다른 계층은 그대로**
- 문제 발생 시 **어느 계층 문제인지** 범위를 좁혀 디버깅

---

## 3. OSI 7계층 vs TCP/IP 4계층

```
        OSI 7계층                    TCP/IP 4계층          데이터 단위     장비 / 프로토콜
+------------------------+    +---------------------+
| 7. 응용 (Application)   |    |                     |
| 6. 표현 (Presentation)  | -> |  응용 (Application)  |   메시지        HTTP, DNS, FTP, SMTP, SSH
| 5. 세션 (Session)       |    |                     |
+------------------------+    +---------------------+
| 4. 전송 (Transport)     | -> |  전송 (Transport)    |   세그먼트       TCP, UDP / 포트 번호
+------------------------+    +---------------------+
| 3. 네트워크 (Network)    | -> |  인터넷 (Internet)   |   패킷          IP, ICMP / 라우터
+------------------------+    +---------------------+
| 2. 데이터링크 (Data Link) |    |                     |   프레임         Ethernet, Wi-Fi, ARP / 스위치
| 1. 물리 (Physical)      | -> | 네트워크 액세스        |   비트          케이블, 허브, 리피터
+------------------------+    +---------------------+
```

> OSI는 **이론적 참조 모델**, TCP/IP는 **실제 인터넷에서 쓰는 모델**입니다.

### 각 계층의 역할

| 계층 | 역할 | 핵심 질문 |
|---|---|---|
| **7. 응용** | 사용자가 쓰는 애플리케이션에 서비스 제공 | 무엇을 요청하는가? (웹 페이지, 메일) |
| 6. 표현 | 데이터 형식 변환, 암호화, 압축 | 어떤 형식인가? (JPEG, UTF-8, TLS 일부) |
| 5. 세션 | 통신 세션 수립·유지·종료, 동기화 | 대화를 어떻게 관리하는가? |
| **4. 전송** | **프로세스 간** 통신, 신뢰성·흐름 제어 | **어느 프로그램(포트)** 에게, 믿을 수 있게? |
| **3. 네트워크** | **호스트 간** 경로 결정(라우팅), 논리 주소 | **어느 컴퓨터(IP)** 로, 어떤 경로로? |
| **2. 데이터링크** | **같은 네트워크 안** 인접 노드 간 전송, 오류 검출 | **바로 옆 장치(MAC)** 에게 어떻게? |
| 1. 물리 | 0과 1을 전기·광·무선 신호로 전송 | 신호를 어떻게 보내는가? |

> **주소 정리**: MAC 주소(2계층, 바로 다음 장치) → IP 주소(3계층, 최종 목적지 컴퓨터) → 포트 번호(4계층, 컴퓨터 안의 프로그램)

---

## 4. 캡슐화와 역캡슐화

데이터를 보낼 때 각 계층은 **자기 계층의 헤더를 붙여서** 아래로 내려보냅니다(캡슐화). 받는 쪽은 아래에서부터 **헤더를 하나씩 떼며** 올립니다(역캡슐화).

```
송신 측 (캡슐화)                                           수신 측 (역캡슐화)

응용      [            HTTP 데이터            ]             ↑ 데이터 전달
전송      [TCP 헤더][      HTTP 데이터         ]  세그먼트    ↑ TCP 헤더 제거 (포트 확인)
네트워크   [IP 헤더][TCP 헤더][  HTTP 데이터    ]  패킷      ↑ IP 헤더 제거 (IP 확인)
데이터링크 [Eth 헤더][IP][TCP][ HTTP 데이터 ][트레일러] 프레임  ↑ 프레임 헤더 제거 (MAC 확인)
물리      010110101011...                        비트      ↑ 신호 → 비트
```

- 데이터 단위 이름: **메시지 → 세그먼트(TCP)/데이터그램(UDP) → 패킷 → 프레임 → 비트**
- 데이터링크 계층은 **트레일러(FCS)** 도 붙여 오류를 검출합니다.

---

## 5. 네트워크 장비

| 장비 | 계층 | 역할 |
|---|---|---|
| 허브 / 리피터 | 1 | 신호를 증폭해 **모든 포트로** 전달 (충돌 많음) |
| **스위치** | 2 | MAC 주소 테이블을 보고 **해당 포트로만** 전달 |
| **라우터** | 3 | IP 주소를 보고 **다른 네트워크로** 경로 결정 |
| L4 스위치 / 로드밸런서 | 4 | IP + 포트로 트래픽 분산 |
| L7 스위치 / 로드밸런서 | 7 | URL, 헤더, 쿠키 기반 분산 (AWS ALB, Nginx) |

## 6. 네트워크 토폴로지 (간단히)

| 형태 | 특징 |
|---|---|
| 버스형 | 하나의 회선에 모두 연결, 회선 고장 시 전체 마비 |
| **스타형** | 중앙 장비(스위치)에 연결, 중앙 장애 시 전체 영향, **가장 일반적** |
| 링형 | 원형 연결, 한 노드 고장이 전체에 영향 |
| 메시형 | 모든 노드가 서로 연결, 신뢰성 높음, 비용 큼 |
| 트리형 | 계층적 스타형 |

## 7. 면접 질문

1. **OSI 7계층을 설명해 주세요.**
   → 물리(비트 전송), 데이터링크(인접 노드 간 프레임 전송, MAC), 네트워크(라우팅, IP), 전송(프로세스 간 신뢰성, 포트), 세션(연결 관리), 표현(형식 변환·암호화), 응용(사용자 서비스)입니다.
2. **계층을 나누는 이유는?**
   → 복잡한 통신을 역할별로 분리해 독립적으로 개발·교체할 수 있고, 문제 발생 시 원인 범위를 좁히기 쉽기 때문입니다.
3. **스위치와 라우터의 차이는?**
   → 스위치는 2계층 장비로 MAC 주소를 보고 같은 네트워크 안에서 전달하고, 라우터는 3계층 장비로 IP 주소를 보고 다른 네트워크로 경로를 정합니다.
4. **L4 로드밸런서와 L7 로드밸런서의 차이는?**
   → L4는 IP와 포트로 분산해 빠르고, L7은 URL·헤더·쿠키 등 애플리케이션 정보로 세밀하게 분산합니다.

---

## 핵심 정리
- OSI 7계층(이론) ↔ TCP/IP 4계층(실제)
- 주소: MAC(2) → IP(3) → 포트(4)
- 단위: 비트 → 프레임 → 패킷 → 세그먼트 → 메시지
- 캡슐화: 내려가며 헤더 추가, 역캡슐화: 올라가며 헤더 제거
