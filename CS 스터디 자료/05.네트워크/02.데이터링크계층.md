# 02. 데이터링크 계층 (Data Link Layer)

> **학습 목표**
> - MAC 주소와 이더넷 프레임 구조를 설명할 수 있다.
> - 스위치의 MAC 주소 학습과 전달 과정을 설명할 수 있다.
> - ARP의 동작 과정을 순서대로 설명할 수 있다.
> - CSMA/CD와 CSMA/CA의 차이를 설명할 수 있다.

---

## 1. 역할

**같은 네트워크 안에서 바로 연결된(인접한) 장치끼리** 프레임을 정확하게 주고받게 합니다.
- MAC 주소로 송·수신자 식별
- 오류 검출 (FCS)
- 매체 접근 제어 (여러 장치가 한 매체를 공유할 때 충돌 방지)

---

## 2. MAC 주소

**네트워크 인터페이스 카드(NIC)에 부여된 48비트 물리 주소**입니다.

```
00:1A:2B:3C:4D:5E
└──┬───┘ └──┬───┘
  OUI     장치 고유 번호
(제조사)
```

- 원칙적으로 전 세계 유일 (단, 소프트웨어로 변경 가능, 스마트폰은 개인정보 보호를 위해 무작위 MAC 사용)
- **브로드캐스트 주소**: `FF:FF:FF:FF:FF:FF` → 같은 네트워크의 모든 장치에게

### IP 주소와 MAC 주소
| 비교 | IP 주소 | MAC 주소 |
|---|---|---|
| 계층 | 3 (네트워크) | 2 (데이터링크) |
| 성격 | 논리 주소 (네트워크에 따라 바뀜) | 물리 주소 (장치에 고정) |
| 범위 | 최종 목적지 | **다음 홉(바로 옆 장치)** |
| 비유 | 최종 배송지 주소 | 다음 물류센터 |

> 패킷이 라우터를 지날 때마다 **IP 주소는 그대로, MAC 주소는 구간마다 바뀝니다.**

---

## 3. 이더넷 프레임

```
+-----------+---------+---------+------+----------------+-----+
| 프리앰블    | 목적지MAC | 출발지MAC | 타입  |   데이터(페이로드)  | FCS |
| (동기화)    | 6B      | 6B      | 2B   |   46~1500B     | 4B  |
+-----------+---------+---------+------+----------------+-----+
                                   ↑                          ↑
                         상위 프로토콜 (0x0800=IPv4,      CRC 오류 검출
                                     0x0806=ARP)
```

- **MTU (Maximum Transmission Unit)**: 이더넷 페이로드 최대 크기 **1500 바이트**. 이보다 큰 IP 패킷은 쪼개야 함(단편화)
- **FCS**: CRC로 계산한 오류 검출 코드. 오류가 있으면 프레임을 **버림** (재전송은 상위 계층 TCP가 담당)

---

## 4. 스위치의 동작

스위치는 **MAC 주소 테이블**을 보고 프레임을 필요한 포트로만 보냅니다.

```
MAC 주소 테이블
| MAC 주소            | 포트 |
|--------------------|-----|
| AA:AA:AA:AA:AA:AA  | 1   |
| BB:BB:BB:BB:BB:BB  | 2   |
```

### 동작 과정
1. **학습 (Learning)**: 프레임이 들어오면 **출발지 MAC과 들어온 포트**를 테이블에 기록
2. **전달 (Forwarding)**: 목적지 MAC이 테이블에 있으면 **그 포트로만** 전송
3. **플러딩 (Flooding)**: 목적지 MAC이 테이블에 없거나 브로드캐스트면 **들어온 포트를 제외한 모든 포트로** 전송
4. **필터링**: 목적지가 들어온 포트와 같으면 버림
5. **에이징**: 일정 시간 사용되지 않은 항목은 삭제

### 충돌 도메인 vs 브로드캐스트 도메인
| 구분 | 의미 | 나누는 장비 |
|---|---|---|
| 충돌 도메인 | 동시에 전송하면 충돌하는 범위 | **스위치** (포트마다 분리) |
| 브로드캐스트 도메인 | 브로드캐스트가 전달되는 범위 | **라우터**, VLAN |

> **VLAN**: 물리적으로 같은 스위치라도 논리적으로 네트워크를 나눠 브로드캐스트 도메인을 분리합니다.

## 5. ARP (Address Resolution Protocol)

**IP 주소는 알지만 MAC 주소를 모를 때, IP 주소로 MAC 주소를 알아내는** 프로토콜입니다.

같은 네트워크에서 프레임을 보내려면 목적지 MAC이 필요합니다. 그런데 애플리케이션은 IP 주소만 알고 있습니다.

### 동작 과정
```
호스트 A (192.168.0.10)가 B (192.168.0.20)에게 보내고 싶음

1. A는 ARP 캐시(테이블)를 확인 → 없음
2. ARP 요청을 브로드캐스트 (목적지 MAC = FF:FF:FF:FF:FF:FF)
   "192.168.0.20 가진 사람? MAC 주소 알려 줘"
3. 같은 네트워크의 모든 호스트가 받지만, B만 응답
4. B가 ARP 응답을 유니캐스트로 A에게
   "192.168.0.20은 나야, 내 MAC은 BB:BB:..."
5. A는 ARP 캐시에 저장 (일정 시간 유지) → 프레임 전송
```

```bash
arp -a     # ARP 캐시 확인
```

### 다른 네트워크로 보낼 때
목적지 IP가 **다른 네트워크**(서브넷 마스크로 판단)면, 목적지 호스트가 아니라 **기본 게이트웨이(라우터)의 MAC 주소**를 ARP로 찾습니다. 라우터가 다음 구간을 이어서 전달합니다.

### ARP 스푸핑
공격자가 **가짜 ARP 응답**을 보내 "게이트웨이 IP의 MAC은 내 MAC"이라고 속이면, 피해자의 트래픽이 공격자를 거쳐 갑니다(중간자 공격). → 정적 ARP 설정, 스위치 보안 기능(DAI), **암호화(HTTPS)** 로 대응

## 6. 매체 접근 제어

여러 장치가 하나의 전송 매체를 공유할 때 충돌을 다루는 방법입니다.

### CSMA/CD (Carrier Sense Multiple Access / Collision Detection) — 유선 이더넷
1. 전송 전에 매체가 비었는지 **감지**(Carrier Sense)
2. 비어 있으면 전송
3. 전송 중 **충돌을 감지**하면 즉시 중단, 잼 신호 전송
4. **랜덤 시간 대기** 후 재시도 (지수 백오프)

> 현대 이더넷은 스위치 + **전이중(Full Duplex)** 통신이라 충돌이 거의 없어 CSMA/CD가 사실상 쓰이지 않습니다.

### CSMA/CA (Collision Avoidance) — 무선 Wi-Fi
- 무선은 전송 중에 충돌을 감지하기 어려움 (자기 신호가 너무 강해서, 숨은 노드 문제)
- 그래서 **충돌을 미리 회피**: 매체가 비어도 랜덤 시간 대기 후 전송, ACK로 성공 확인, RTS/CTS로 예약

| 비교 | CSMA/CD | CSMA/CA |
|---|---|---|
| 환경 | 유선 | 무선 |
| 전략 | 충돌 **감지** 후 재전송 | 충돌 **회피** |

## 7. 오류 검출과 제어

| 기법 | 설명 |
|---|---|
| 패리티 비트 | 1의 개수를 짝수/홀수로 맞춤. 단일 비트 오류만 검출 |
| 체크섬 | 데이터를 더한 값 비교 (IP, TCP, UDP 헤더) |
| **CRC** | 다항식 나눗셈 나머지. 연속 오류 검출에 강함 (이더넷 FCS) |
| 해밍 코드 | 오류 **정정**까지 가능 |

## 8. 면접 질문

1. **ARP란? 동작 과정은?**
   → IP 주소로 MAC 주소를 알아내는 프로토콜입니다. ARP 요청을 브로드캐스트하면 해당 IP를 가진 호스트가 자신의 MAC 주소로 유니캐스트 응답하고, 요청자는 이를 캐시에 저장합니다.
2. **MAC 주소와 IP 주소가 모두 필요한 이유는?**
   → IP는 여러 네트워크를 거쳐 최종 목적지를 찾는 논리 주소이고, MAC은 실제로 한 구간(같은 링크)에서 다음 장치에 프레임을 전달하는 물리 주소이기 때문입니다.
3. **스위치는 어떻게 MAC 주소를 학습하나요?**
   → 들어온 프레임의 출발지 MAC과 포트를 테이블에 기록하고, 목적지를 모르면 플러딩합니다.

---

## 핵심 정리
- 데이터링크 = 같은 네트워크 내 인접 장치 간 프레임 전송, MAC 주소
- 이더넷 MTU 1500B, FCS(CRC)로 오류 검출 후 폐기
- 스위치: 학습 → 전달/플러딩
- ARP: IP → MAC, 요청은 브로드캐스트, 응답은 유니캐스트
