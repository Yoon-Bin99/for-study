# 03. 네트워크 계층 (Network Layer)

> **학습 목표**
> - IPv4 주소 구조와 서브넷 마스크, CIDR 표기를 계산할 수 있다.
> - 공인 IP와 사설 IP, NAT의 동작을 설명할 수 있다.
> - 라우팅 테이블과 라우팅 프로토콜(RIP, OSPF, BGP)을 비교할 수 있다.
> - DHCP, ICMP의 역할을 설명할 수 있다.

---

## 1. 역할

**서로 다른 네트워크에 있는 호스트까지** 패킷을 전달합니다.
- **논리 주소(IP)** 부여
- **라우팅**: 목적지까지의 경로 결정
- 패킷 단편화와 재조립

> IP는 **비연결형, 최선형(Best-Effort)** 서비스입니다. 패킷이 도착하는지, 순서대로 오는지 **보장하지 않습니다.** 신뢰성은 상위 계층(TCP)이 책임집니다.

---

## 2. IPv4 주소

**32비트**, 8비트씩 4개로 나눠 10진수로 표기합니다.
```
192.168.1.10
11000000.10101000.00000001.00001010
```
- 약 43억 개 → **부족** → 서브넷팅, 사설 IP + NAT, IPv6로 대응

### 주소 = 네트워크 부분 + 호스트 부분
```
192.168.1.10 / 24

네트워크 부분: 192.168.1      (같은 네트워크면 같음)
호스트 부분:          .10     (네트워크 안에서 개별 장치)
```

### 클래스 (과거 방식, Classful)
| 클래스 | 첫 비트 | 범위 | 기본 마스크 | 네트워크 크기 |
|---|---|---|---|---|
| A | 0 | 0.0.0.0 ~ 127.255.255.255 | /8 | 약 1,677만 호스트 |
| B | 10 | 128.0.0.0 ~ 191.255.255.255 | /16 | 65,534 호스트 |
| C | 110 | 192.0.0.0 ~ 223.255.255.255 | /24 | 254 호스트 |
| D | 1110 | 224 ~ 239 | - | 멀티캐스트 |
| E | 1111 | 240 ~ 255 | - | 예약 |

→ 크기가 딱딱하게 정해져 **낭비가 심해** 지금은 **CIDR**을 씁니다.

---

## 3. 서브넷 마스크와 CIDR

**서브넷 마스크**: IP 주소에서 **어디까지가 네트워크 부분인지** 알려 주는 32비트 값
```
IP:       192.168.1.10    11000000.10101000.00000001.00001010
마스크:    255.255.255.0   11111111.11111111.11111111.00000000
AND 연산 → 네트워크 주소: 192.168.1.0
```

**CIDR 표기**: `/24` = 앞의 24비트가 네트워크 부분 = 255.255.255.0

### 서브넷 계산 예시
`192.168.1.0/26`
```
마스크: /26 → 11111111.11111111.11111111.11000000 = 255.255.255.192
호스트 비트: 32 - 26 = 6비트 → 2⁶ = 64개 주소

서브넷 (4개):
192.168.1.0   ~ 192.168.1.63
192.168.1.64  ~ 192.168.1.127
192.168.1.128 ~ 192.168.1.191
192.168.1.192 ~ 192.168.1.255

각 서브넷에서
- 첫 주소 (예: .0)   = 네트워크 주소  (호스트에 할당 X)
- 마지막 주소 (.63)   = 브로드캐스트 주소 (호스트에 할당 X)
- 사용 가능 호스트 = 64 - 2 = 62개
```

| CIDR | 마스크 | 주소 수 | 사용 가능 호스트 |
|---|---|---|---|
| /24 | 255.255.255.0 | 256 | 254 |
| /25 | 255.255.255.128 | 128 | 126 |
| /26 | 255.255.255.192 | 64 | 62 |
| /27 | 255.255.255.224 | 32 | 30 |
| /28 | 255.255.255.240 | 16 | 14 |
| /16 | 255.255.0.0 | 65,536 | 65,534 |

> AWS VPC에서 `10.0.0.0/16`으로 VPC를 만들고 `10.0.1.0/24`, `10.0.2.0/24`로 퍼블릭·프라이빗 서브넷을 나누는 것이 바로 서브네팅입니다. (AWS는 서브넷마다 5개 주소를 예약합니다)

## 4. 특수 주소, 공인 IP와 사설 IP

| 주소 | 의미 |
|---|---|
| `127.0.0.1` (127.0.0.0/8) | **루프백** (localhost, 자기 자신) |
| `0.0.0.0` | 모든 인터페이스 / 주소 미지정 |
| `255.255.255.255` | 제한된 브로드캐스트 |
| `169.254.x.x` | DHCP 실패 시 자동 할당 (링크 로컬) |

### 사설 IP (Private IP)
인터넷에서 라우팅되지 않고 **내부 네트워크에서만** 쓰는 주소입니다.
| 범위 | CIDR |
|---|---|
| 10.0.0.0 ~ 10.255.255.255 | 10.0.0.0/8 |
| 172.16.0.0 ~ 172.31.255.255 | 172.16.0.0/12 |
| 192.168.0.0 ~ 192.168.255.255 | 192.168.0.0/16 |

## 5. NAT (Network Address Translation)

**사설 IP를 공인 IP로 바꿔서** 인터넷과 통신하게 해 줍니다. 공유기가 대표적입니다.

```
내부 PC (192.168.0.10:50000) ─→ [공유기 NAT] ─→ 인터넷 (공인 IP 203.0.113.5:62001)

NAT 테이블
| 내부 IP:포트           | 외부 IP:포트           |
|----------------------|----------------------|
| 192.168.0.10:50000   | 203.0.113.5:62001    |
| 192.168.0.11:50000   | 203.0.113.5:62002    |

응답이 62001로 돌아오면 → 테이블을 보고 192.168.0.10:50000으로 전달
```

- 포트까지 바꿔서 공인 IP 하나를 여러 장치가 공유하는 방식을 **PAT (NAPT)** 라고 합니다.
- 장점: **IP 주소 절약**, 내부 구조 숨김(보안)
- 단점: 외부에서 내부로 먼저 연결하기 어려움 → 포트 포워딩 필요, P2P 통신 어려움

> AWS의 **NAT 게이트웨이**는 프라이빗 서브넷의 서버가 외부로 나가는 요청(패키지 다운로드 등)만 할 수 있게 해 줍니다.

## 6. IP 패킷 헤더 (IPv4 주요 필드)

| 필드 | 의미 |
|---|---|
| 버전 | 4 (IPv4) |
| 전체 길이 | 헤더 + 데이터 |
| 식별자, 플래그, 단편 오프셋 | **단편화**된 패킷을 재조립하기 위한 정보 |
| **TTL** (Time To Live) | 라우터를 지날 때마다 1 감소, **0이면 폐기** → 패킷이 무한히 도는 것 방지 |
| 프로토콜 | 상위 프로토콜 (6 = TCP, 17 = UDP, 1 = ICMP) |
| 헤더 체크섬 | 헤더 오류 검출 |
| 출발지 IP, 목적지 IP | |

## 7. 라우팅 (Routing)

라우터는 **라우팅 테이블**을 보고 패킷을 다음 라우터(next hop)로 보냅니다.

```
라우팅 테이블
| 목적지 네트워크      | 다음 홉          | 인터페이스 |
|-------------------|----------------|----------|
| 10.0.1.0/24       | 직접 연결         | eth0     |
| 10.0.0.0/16       | 10.0.1.254     | eth0     |
| 0.0.0.0/0         | 203.0.113.1    | eth1     |  ← 기본 경로 (default route)
```

- **최장 접두사 매칭 (Longest Prefix Match)**: 여러 항목이 일치하면 **가장 구체적인(마스크가 긴)** 경로 선택
  - 10.0.1.5 → /24와 /16 모두 일치 → /24 선택
- 일치하는 게 없으면 **기본 경로(0.0.0.0/0)** 로

### 정적 라우팅 vs 동적 라우팅
| 방식 | 설명 |
|---|---|
| 정적 | 관리자가 직접 설정. 작은 네트워크, 변경 적음 |
| 동적 | 라우팅 프로토콜로 라우터끼리 정보를 교환해 자동 갱신 |

### 라우팅 프로토콜
| 프로토콜 | 종류 | 알고리즘 | 특징 |
|---|---|---|---|
| **RIP** | 내부 (IGP), **거리 벡터** | 벨만-포드 | 홉 수 기준, 최대 15홉, 소규모 |
| **OSPF** | 내부 (IGP), **링크 상태** | **다익스트라** | 대역폭 기반 비용, 빠른 수렴, 중대형 |
| **BGP** | 외부 (EGP), 경로 벡터 | - | **AS(통신사·대기업 네트워크) 간** 라우팅, 인터넷의 뼈대 |

## 8. 관련 프로토콜

### ICMP (Internet Control Message Protocol)
IP는 오류를 알려 주지 않으므로, **오류 보고와 진단**을 위해 ICMP를 씁니다.
```bash
ping google.com          # ICMP Echo Request / Reply → 연결 확인, RTT 측정
traceroute google.com    # TTL을 1, 2, 3 ... 늘려 가며 보냄
                         # 각 라우터가 TTL 0이 될 때 보내는 "Time Exceeded"로 경로 파악
```

### DHCP (Dynamic Host Configuration Protocol)
네트워크에 접속한 장치에 **IP 주소, 서브넷 마스크, 게이트웨이, DNS 서버를 자동으로 할당**합니다. (UDP 67/68)
```
1. DISCOVER (클라이언트 → 브로드캐스트): "DHCP 서버 있나요?"
2. OFFER    (서버 → 클라이언트): "192.168.0.10 쓰세요"
3. REQUEST  (클라이언트 → 브로드캐스트): "그 주소 쓸게요"
4. ACK      (서버 → 클라이언트): "확정, 임대 기간 24시간"
```
→ 앞 글자를 따서 **DORA**

## 9. IPv6

| 항목 | IPv4 | IPv6 |
|---|---|---|
| 주소 길이 | 32비트 | **128비트** (사실상 무한) |
| 표기 | 192.168.0.1 | 2001:0db8:85a3::8a2e:0370:7334 (16진수, 연속 0은 `::`로 생략) |
| NAT | 필요 | 원칙적으로 불필요 |
| 헤더 | 가변, 체크섬 있음 | 고정 40바이트, 단순화 (체크섬 제거) |
| 단편화 | 라우터도 가능 | **출발지만** 가능 |
| 보안 | IPsec 선택 | IPsec 지원 기본 고려 |

## 10. 면접 질문

1. **서브넷 마스크란?**
   → IP 주소에서 네트워크 부분과 호스트 부분을 구분하는 값으로, IP와 AND 연산해 네트워크 주소를 구합니다.
2. **192.168.10.0/27의 사용 가능한 호스트 수는?**
   → 호스트 비트 5개로 32개 주소 중 네트워크·브로드캐스트 주소를 뺀 30개입니다.
3. **NAT란? 왜 필요한가요?**
   → 사설 IP를 공인 IP로 변환하는 기술로, 부족한 IPv4 주소를 절약하고 내부 네트워크를 숨길 수 있습니다.
4. **TTL의 역할은?**
   → 라우터를 지날 때마다 감소해 0이 되면 패킷을 폐기함으로써 라우팅 루프에서 패킷이 무한히 도는 것을 막습니다.
5. **traceroute는 어떻게 동작하나요?**
   → TTL을 1부터 늘려 가며 패킷을 보내 각 라우터가 반환하는 ICMP Time Exceeded 메시지로 경로를 파악합니다.

## 핵심 정리
- IP = 비연결형 최선형, 32비트(v4) / 128비트(v6)
- CIDR /n → 주소 2^(32-n)개, 호스트 = 그중 2개 제외
- 사설 IP + NAT(PAT)로 주소 절약
- 라우팅: 최장 접두사 매칭, RIP(벨만-포드) / OSPF(다익스트라) / BGP(AS 간)
- ICMP(ping, traceroute), DHCP(DORA)
