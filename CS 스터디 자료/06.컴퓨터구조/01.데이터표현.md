# 01. 데이터 표현 (Data Representation)

> **학습 목표**
> - 2진수, 16진수 변환을 할 수 있다.
> - 2의 보수로 음수를 표현하는 이유와 방법을 설명할 수 있다.
> - IEEE 754 부동소수점 구조와 0.1 + 0.2 ≠ 0.3인 이유를 설명할 수 있다.
> - 문자 인코딩(ASCII, 유니코드, UTF-8)과 엔디언을 설명할 수 있다.

---

## 1. 비트와 바이트

| 단위 | 크기 |
|---|---|
| 비트 (bit) | 0 또는 1 |
| 바이트 (byte) | 8비트 → 0 ~ 255 (2⁸ = 256가지) |
| KB / MB / GB | 2¹⁰ / 2²⁰ / 2³⁰ 바이트 (KiB, MiB, GiB로 구분하기도 함) |
| 워드 (word) | CPU가 한 번에 처리하는 단위 (64비트 CPU → 8바이트) |

## 2. 진법 변환

### 10진수 → 2진수: 2로 나눈 나머지를 거꾸로
```
13 ÷ 2 = 6 ... 1
 6 ÷ 2 = 3 ... 0
 3 ÷ 2 = 1 ... 1
 1 ÷ 2 = 0 ... 1
→ 1101₂
```

### 2진수 → 10진수: 자릿값 합
```
1101₂ = 1×2³ + 1×2² + 0×2¹ + 1×2⁰ = 8 + 4 + 0 + 1 = 13
```

### 2진수 ↔ 16진수: 4비트씩 묶기
```
1101 0110₂ = D6₁₆ = 0xD6
(1101 = 13 = D, 0110 = 6)
```
- 16진수는 2진수를 짧게 쓰기 위해 사용 (메모리 주소, 색상 `#FF8800`, MAC 주소)

```java
Integer.toBinaryString(13);   // "1101"
Integer.toHexString(214);     // "d6"
Integer.parseInt("1101", 2);  // 13
```

## 3. 정수 표현: 음수는 어떻게?

### 방법 1: 부호-크기 (Sign-Magnitude)
맨 앞 비트를 부호로 (0 = 양수, 1 = 음수)
```
+5 = 0000 0101
-5 = 1000 0101
```
- 문제: **+0(0000 0000)과 -0(1000 0000)이 둘 다 존재**, 덧셈 회로가 복잡

### 방법 2: 1의 보수
모든 비트를 뒤집음
```
-5 = 1111 1010
```
- 여전히 +0, -0 문제

### 방법 3: 2의 보수 (현재 표준)
**모든 비트를 뒤집고 1을 더함**
```
+5 = 0000 0101
뒤집기 1111 1010
+1   → 1111 1011 = -5
```

장점:
- **0이 하나뿐**
- **뺄셈을 덧셈 회로로** 처리 가능: `A - B = A + (-B)`
```
  5   0000 0101
+(-5) 1111 1011
---------------
  0  1 0000 0000  ← 넘친 비트(캐리)는 버림 → 0
```

### n비트 정수 범위
| 타입 (Java) | 비트 | 범위 |
|---|---|---|
| byte | 8 | -128 ~ 127 |
| short | 16 | -32,768 ~ 32,767 |
| int | 32 | **약 -21억 ~ 21억** (-2³¹ ~ 2³¹-1) |
| long | 64 | 약 ±922경 (-2⁶³ ~ 2⁶³-1) |

→ n비트 2의 보수 범위: **-2ⁿ⁻¹ ~ 2ⁿ⁻¹ - 1** (음수 쪽이 하나 더 많음)

### 오버플로 (Overflow)
```java
int max = Integer.MAX_VALUE;   //  2147483647  = 0111...1
System.out.println(max + 1);   // -2147483648  = 1000...0  ← 음수로 넘어감!
```
- 코딩테스트에서 합계·곱셈이 21억을 넘을 수 있으면 **long**을 쓰세요.
- `Math.addExact()`는 오버플로 시 예외를 던집니다.

## 4. 비트 연산

| 연산 | 기호 | 예 (a = 0101, b = 0011) |
|---|---|---|
| AND | `&` | 0001 |
| OR | `\|` | 0111 |
| XOR | `^` | 0110 (다르면 1) |
| NOT | `~` | ~0101 = 1010 (모든 비트 반전) |
| 왼쪽 시프트 | `<<` | 0101 << 1 = 1010 (**×2**) |
| 오른쪽 시프트 (산술) | `>>` | 부호 비트 유지하며 이동 (**÷2**) |
| 오른쪽 시프트 (논리) | `>>>` | 0으로 채움 (Java) |

활용:
```java
(n & 1) == 0          // 짝수 판별
n & (n - 1)           // 가장 낮은 1비트 제거 → 0이면 2의 거듭제곱
a ^ a                 // 항상 0, a ^ 0 = a → 모두 XOR하면 짝 없는 수만 남음
```

## 5. 실수 표현: 부동소수점 (IEEE 754)

### 고정소수점 vs 부동소수점
- 고정소수점: 소수점 위치 고정 → 범위가 좁음
- **부동소수점**: 과학적 표기법처럼 **소수점 위치를 움직여** 넓은 범위 표현

```
10진 과학적 표기:  123.45 = 1.2345 × 10²
2진 과학적 표기:   5.75 = 101.11₂ = 1.0111₂ × 2²
```

### IEEE 754 단정밀도 (float, 32비트)
```
| 부호 1비트 | 지수 8비트 | 가수(유효숫자) 23비트 |
     S          E              M

값 = (-1)^S × 1.M × 2^(E - 127)
```
- **지수에 바이어스 127**을 더해 저장 (음수 지수도 양수로 저장하기 위해)
- 가수는 맨 앞 `1.`을 생략하고 저장 (정규화, 1비트 절약)

#### 5.75를 float로
```
5.75 = 101.11₂ = 1.0111 × 2²
부호 S = 0
지수 E = 2 + 127 = 129 = 1000 0001
가수 M = 0111 0000 0000 ... (23비트)

→ 0 | 10000001 | 01110000000000000000000
```

| 형식 | 전체 | 지수 | 가수 | 유효 자릿수 (10진) |
|---|---|---|---|---|
| float (단정밀도) | 32 | 8 | 23 | 약 7자리 |
| double (배정밀도) | 64 | 11 | 52 | 약 15~16자리 |

### 0.1 + 0.2 != 0.3 인 이유
```java
System.out.println(0.1 + 0.2);         // 0.30000000000000004
System.out.println(0.1 + 0.2 == 0.3);  // false
```
- 10진수 0.1은 2진수로 **무한 소수** (0.000110011001100...₂)
- 유한한 비트에 저장하면서 **반올림 오차** 발생

해결:
- 비교할 때 오차 범위 사용: `Math.abs(a - b) < 1e-9`
- **돈 계산에는 절대 double을 쓰지 말고 `BigDecimal`** 또는 정수(원 단위 long)를 사용

```java
new BigDecimal("0.1").add(new BigDecimal("0.2"));   // 0.3 (문자열 생성자 사용!)
new BigDecimal(0.1);   // 0.1000000000000000055511151231257827... (이미 오차가 들어감)
```

## 6. 문자 인코딩

| 인코딩 | 설명 |
|---|---|
| **ASCII** | 7비트, 128문자 (영문, 숫자, 기호). `'A' = 65`, `'a' = 97`, `'0' = 48` |
| EUC-KR / CP949 | 한글 완성형 2바이트 (레거시, 일부 한글 표현 불가 → CP949로 확장) |
| **유니코드 (Unicode)** | 전 세계 문자에 **고유 번호(코드 포인트)** 부여. `'가' = U+AC00` |
| **UTF-8** | 유니코드를 **1~4바이트 가변 길이**로 인코딩. ASCII와 호환, 한글은 **3바이트**. **웹 표준** |
| UTF-16 | 2 또는 4바이트. **Java `char`, JavaScript 문자열 내부 표현** |

> 한글이 깨지는 현상은 **저장한 인코딩과 읽는 인코딩이 다를 때** 발생합니다. 프로젝트 파일, DB(`utf8mb4`), HTTP 헤더(`charset=UTF-8`)를 모두 UTF-8로 통일하세요. MySQL의 `utf8`은 3바이트까지만 지원해 이모지가 안 들어가므로 **`utf8mb4`** 를 써야 합니다.

```java
"가".getBytes(StandardCharsets.UTF_8).length;   // 3
'A' - 'A' + 'a';                                  // 'a' (문자 연산)
```

## 7. 엔디언 (Endianness)

여러 바이트로 된 데이터를 **메모리에 어떤 순서로 저장**하는가?

`0x12345678`을 저장할 때 (주소 증가 →)
```
빅 엔디언 (Big-Endian):      12 34 56 78   ← 큰 자리부터 (사람이 읽는 순서)
리틀 엔디언 (Little-Endian): 78 56 34 12   ← 작은 자리부터
```

| 방식 | 사용처 |
|---|---|
| 빅 엔디언 | **네트워크 바이트 순서** (TCP/IP 헤더), Java 클래스 파일, JVM |
| 리틀 엔디언 | **x86, ARM(기본) CPU** |

→ 네트워크로 보낼 때 `htonl()`(host to network long)로 변환합니다.

## 8. 면접 질문

1. **2의 보수를 쓰는 이유는?**
   → 0이 하나만 존재하고, 뺄셈을 덧셈 회로로 처리할 수 있어 하드웨어가 단순해지기 때문입니다.
2. **0.1 + 0.2가 0.3이 아닌 이유는?**
   → 0.1과 0.2가 2진수로 무한 소수라 유한한 비트에 저장하면서 반올림 오차가 생기기 때문입니다. 금액 계산에는 BigDecimal을 씁니다.
3. **int 최댓값에 1을 더하면?**
   → 오버플로로 int 최솟값(-2,147,483,648)이 됩니다.
4. **UTF-8의 특징은?**
   → 유니코드를 1~4바이트 가변 길이로 인코딩하고 ASCII와 호환되며, 한글은 3바이트입니다.

---

## 핵심 정리
- 음수 = 2의 보수 (뒤집고 +1), n비트 범위 -2ⁿ⁻¹ ~ 2ⁿ⁻¹-1
- 오버플로 주의 → long, `Math.addExact`
- 부동소수점 = 부호 + 지수(바이어스) + 가수, 0.1은 2진 무한소수 → 돈은 BigDecimal
- UTF-8 가변 길이(한글 3B), MySQL은 utf8mb4
- 네트워크는 빅 엔디언, x86은 리틀 엔디언
