# 04. 파이프라인과 병렬 처리 (Pipelining & Parallelism)

> **학습 목표**
> - 명령어 파이프라인의 원리와 성능 향상을 설명할 수 있다.
> - 파이프라인 해저드 3가지와 해결 방법을 설명할 수 있다.
> - 슈퍼스칼라, 비순차 실행, 분기 예측을 설명할 수 있다.
> - 병렬성의 종류와 암달의 법칙을 설명할 수 있다.

---

## 1. 파이프라인 (Pipelining)

명령어 실행을 여러 단계로 나누고, **각 단계를 겹쳐서 동시에** 실행하는 기법입니다. 세탁기 → 건조기 → 개기를 동시에 돌리는 것과 같습니다.

### 5단계 파이프라인 (MIPS 기준)
| 단계 | 이름 | 동작 |
|---|---|---|
| IF | Instruction Fetch | 명령어 인출 |
| ID | Instruction Decode | 해독 + 레지스터 읽기 |
| EX | Execute | ALU 연산 |
| MEM | Memory Access | 메모리 읽기/쓰기 |
| WB | Write Back | 결과를 레지스터에 쓰기 |

### 파이프라인 없이 vs 있을 때
```
파이프라인 X (명령어 3개 → 15 사이클)
명령1: IF ID EX ME WB
명령2:                IF ID EX ME WB
명령3:                               IF ID EX ME WB

파이프라인 O (명령어 3개 → 7 사이클)
사이클: 1  2  3  4  5  6  7
명령1:  IF ID EX ME WB
명령2:     IF ID EX ME WB
명령3:        IF ID EX ME WB
```

- k단계 파이프라인, 명령어 n개 → **k + (n - 1) 사이클**
- n이 크면 **이론상 최대 k배** 빨라짐
- 명령어 하나의 실행 시간(지연)은 줄지 않지만, **처리량(Throughput)** 이 늘어남

## 2. 파이프라인 해저드 (Pipeline Hazard)

파이프라인이 매 사이클 명령어를 하나씩 처리하지 못하고 **멈춰야(Stall)** 하는 상황입니다.

### 2-1. 구조적 해저드 (Structural Hazard)
**같은 하드웨어 자원을 동시에** 쓰려고 할 때
- 예: IF 단계(명령어 읽기)와 MEM 단계(데이터 읽기)가 동시에 메모리 접근
- 해결: **자원 추가** (명령어 캐시와 데이터 캐시 분리 = 하버드 구조)

### 2-2. 데이터 해저드 (Data Hazard)
**앞 명령어의 결과가 나오기 전에 뒤 명령어가 그 값을 필요**로 할 때
```
ADD R1, R2, R3    ; R1 = R2 + R3   (WB 단계에서야 R1에 저장)
SUB R4, R1, R5    ; R1이 필요한데 아직 계산 중!
```
해결:
| 방법 | 설명 |
|---|---|
| **포워딩 (Forwarding, Bypassing)** | EX 단계 결과를 레지스터에 쓰기 전에 **바로 다음 명령어로 전달** |
| 스톨 (버블 삽입) | 값이 준비될 때까지 대기 |
| 명령어 재배치 | 컴파일러가 의존성 없는 명령어를 사이에 끼워 넣음 |

### 2-3. 제어 해저드 (Control Hazard)
**분기 명령(if, 반복문)** 의 결과가 나오기 전까지 **다음에 어떤 명령어를 가져올지 모를 때**
```
BEQ R1, R2, LABEL   ; R1 == R2 이면 LABEL로 점프
???                 ; 다음에 뭘 인출하지?
```
해결:
| 방법 | 설명 |
|---|---|
| **분기 예측 (Branch Prediction)** | 분기 결과를 **예측해 미리 실행**, 틀리면 결과를 버리고 다시 (**분기 예측 실패 페널티**) |
| 지연 분기 | 분기 뒤 슬롯에 항상 실행되는 명령어 배치 |
| 스톨 | 결과가 나올 때까지 대기 |

> 현대 CPU의 분기 예측 정확도는 95% 이상입니다. 과거 기록(패턴)을 학습하는 **동적 분기 예측**을 씁니다.

### 해저드 정리
| 해저드 | 원인 | 해결 |
|---|---|---|
| 구조적 | 자원 충돌 | 자원 추가/분리 |
| 데이터 | 데이터 의존성 | **포워딩**, 스톨, 재배치 |
| 제어 | 분기 | **분기 예측**, 지연 분기 |

## 3. 현대 CPU의 성능 향상 기법

### 슈퍼스칼라 (Superscalar)
**파이프라인을 여러 개** 두어 한 사이클에 **여러 명령어를 동시에** 발행합니다. (IPC > 1)
```
사이클: 1  2  3  4  5  6
명령1:  IF ID EX ME WB
명령2:  IF ID EX ME WB      ← 동시에
명령3:     IF ID EX ME WB
명령4:     IF ID EX ME WB
```

### 비순차 실행 (Out-of-Order Execution)
명령어 **순서와 상관없이, 준비된(의존성이 없는) 명령어부터 먼저 실행**하고 결과는 원래 순서대로 반영합니다.
```
1: LOAD R1, [메모리]     ← 캐시 미스로 오래 걸림
2: ADD  R2, R1, R3       ← 1번 결과를 기다려야 함
3: MUL  R4, R5, R6       ← 1, 2와 무관 → 먼저 실행!
```

### 투기적 실행 (Speculative Execution)
분기 예측을 바탕으로 **아직 확정되지 않은 명령어를 미리 실행**합니다.
> 2018년 **스펙터(Spectre)·멜트다운(Meltdown)** 취약점은 투기적 실행이 남긴 캐시 흔적으로 접근 권한이 없는 메모리를 유추하는 공격이었습니다.

## 4. 병렬 처리

### 병렬성의 종류
| 종류 | 설명 | 예 |
|---|---|---|
| **명령어 수준 병렬성 (ILP)** | 한 코어 안에서 여러 명령어 동시 실행 | 파이프라인, 슈퍼스칼라, 비순차 실행 |
| **데이터 수준 병렬성 (DLP)** | 같은 연산을 **여러 데이터에 동시에** | **SIMD** 명령어(AVX), **GPU** |
| **스레드 수준 병렬성 (TLP)** | 여러 스레드를 여러 코어에서 동시 실행 | 멀티코어, 하이퍼스레딩 |

### 플린의 분류 (Flynn's Taxonomy)
| 분류 | 명령어 | 데이터 | 예 |
|---|---|---|---|
| SISD | 1 | 1 | 전통적인 단일 코어 |
| **SIMD** | 1 | 여러 개 | 벡터 연산, **GPU** |
| MISD | 여러 개 | 1 | 거의 없음 (내결함성 시스템) |
| **MIMD** | 여러 개 | 여러 개 | **멀티코어 CPU**, 분산 시스템 |

### CPU vs GPU
| 비교 | CPU | GPU |
|---|---|---|
| 코어 | 수~수십 개의 **강력한** 코어 | 수천 개의 **단순한** 코어 |
| 강점 | 복잡한 분기, 순차 로직, 낮은 지연 | **대량의 같은 연산을 병렬로** |
| 용도 | OS, 애플리케이션 로직 | 그래픽, **딥러닝(행렬 곱)**, 과학 계산 |

> 딥러닝 학습에 GPU를 쓰는 이유: 신경망 연산의 대부분이 **행렬 곱셈**이고, 행렬 원소별 곱셈·덧셈은 서로 독립적이라 수천 개 코어에서 동시에 처리할 수 있기 때문입니다.

## 5. 암달의 법칙 (Amdahl's Law)

**프로그램의 일부만 병렬화할 수 있을 때, 코어를 늘려도 전체 성능 향상에는 한계**가 있다는 법칙입니다.

```
속도 향상 = 1 / ((1 - P) + P / N)
P: 병렬화 가능한 비율, N: 프로세서 수
```

예: 프로그램의 **90%** 를 병렬화할 수 있을 때
| 코어 수 N | 속도 향상 |
|---|---|
| 2 | 1 / (0.1 + 0.45) ≈ 1.82배 |
| 10 | 1 / (0.1 + 0.09) ≈ 5.26배 |
| 100 | 1 / (0.1 + 0.009) ≈ 9.17배 |
| ∞ | 1 / 0.1 = **최대 10배** |

→ **순차 실행 부분(10%)이 병목**이 되어 아무리 코어를 늘려도 10배를 넘을 수 없습니다.

> 백엔드에 적용하면: 서버를 늘려도 **공유 DB, 락, 직렬화된 구간**이 있으면 성능이 선형으로 늘지 않습니다. 병목 구간을 줄이는 것이 핵심입니다.

## 6. 면접 질문

1. **파이프라이닝이란?**
   → 명령어 실행을 여러 단계로 나눠 서로 다른 명령어의 단계를 겹쳐 실행함으로써 처리량을 높이는 기법입니다.
2. **파이프라인 해저드의 종류와 해결책은?**
   → 자원 충돌인 구조적 해저드(자원 분리), 데이터 의존성인 데이터 해저드(포워딩), 분기로 인한 제어 해저드(분기 예측)가 있습니다.
3. **암달의 법칙이란?**
   → 병렬화할 수 없는 순차 부분이 전체 성능 향상의 상한을 결정한다는 법칙입니다.
4. **딥러닝에 GPU를 쓰는 이유는?**
   → 행렬 연산처럼 독립적인 같은 연산을 대량으로 수행해야 하는데, GPU는 수천 개의 코어로 이를 병렬 처리할 수 있기 때문입니다.

---

## 핵심 정리
- 파이프라인: 단계를 겹쳐 처리량 ↑ (k단계 → 최대 k배)
- 해저드: 구조적(자원 분리) / 데이터(포워딩) / 제어(분기 예측)
- 현대 CPU: 슈퍼스칼라 + 비순차 실행 + 투기적 실행
- 병렬성: ILP / DLP(SIMD, GPU) / TLP(멀티코어)
- 암달의 법칙: 순차 부분이 상한을 결정
