## 1. 기본형 vs 참조형

| 구분 | 기본형 (Primitive) | 참조형 (Reference) |
|---|---|---|
| 종류 | `byte short int long float double char boolean` (8개) | 클래스, 인터페이스, 배열, enum, record |
| 저장 값 | **값 자체** | 객체가 있는 **Heap의 주소(참조)** |
| 기본값 (필드) | 0, 0.0, false, '\u0000' | `null` |
| null 가능 | X | O |
| 제네릭 | 사용 불가 (`List<int>` X) | 가능 |

```java
int a = 10;                 // Stack: a = 10
Member m = new Member();    // Stack: m = 0x1234 (주소)  →  Heap: Member 객체
```
```
Stack (메서드 호출마다 프레임)        Heap (객체)
+-----------+                     +------------------+
| a = 10    |                     | Member 객체       |
| m = 0x1234| ──────────────────> | name = "kim"     |
+-----------+                     +------------------+
```

| 타입 | 크기 | 범위 |
|---|---|---|
| `int` | 4바이트 | 약 ±21억 |
| `long` | 8바이트 | 약 ±922경 (`1L`, 금액·ID에 사용) |
| `double` | 8바이트 | 부동소수점 → **돈 계산 금지** (`BigDecimal`) |
| `char` | 2바이트 | UTF-16 코드 단위 |

> 정수 오버플로, 부동소수점 오차는 CS 자료 `06.컴퓨터구조/01.데이터표현.md` 참고

## 2. 자바는 항상 Call by Value

메서드에 인자를 넘길 때 **값을 복사**해서 넘깁니다. 참조형이면 **주소 값을 복사**합니다.

```java
static void change(Member m) {
    m.setName("lee");          // ① 같은 객체를 가리키므로 원본 객체가 바뀜
    m = new Member("park");    // ② 지역 변수 m이 새 객체를 가리킬 뿐, 호출한 쪽 변수는 그대로
}

Member member = new Member("kim");
change(member);
System.out.println(member.getName());   // "lee"  (park 아님)
```
```
호출 전:  member ──> [kim]
change 안: member ──> [kim] <── m (주소 복사)
①:        member ──> [lee] <── m
②:        member ──> [lee]      m ──> [park]   ← m만 바뀜
```
> "참조형은 Call by Reference"라고 답하면 틀립니다. **참조(주소)를 값으로 전달**하는 것입니다. C++의 참조 전달처럼 호출한 쪽 변수 자체를 바꿀 수는 없습니다.

## 3. 래퍼 클래스와 오토박싱

| 기본형 | 래퍼 |
|---|---|
| int | Integer |
| long | Long |
| double | Double |
| boolean | Boolean |
| char | Character |

```java
Integer boxed = 10;        // 오토박싱: Integer.valueOf(10)
int unboxed = boxed;       // 언박싱: boxed.intValue()
```

### 함정 1: == 비교와 Integer 캐시
```java
Integer a = 127, b = 127;
System.out.println(a == b);       // true   (-128 ~ 127은 캐시된 같은 객체)

Integer c = 128, d = 128;
System.out.println(c == d);       // false  (서로 다른 객체)
System.out.println(c.equals(d));  // true
```
> 래퍼 타입은 **반드시 `equals()`로 비교**하세요. JPA 엔티티의 `Long id`를 `==`로 비교하는 버그가 흔합니다. (`Objects.equals(a, b)`는 null도 안전)

### 함정 2: 언박싱 NPE
```java
Integer count = map.get("x");   // 없으면 null
int c = count;                  // NullPointerException!
```

### 함정 3: 성능
```java
Long sum = 0L;
for (long i = 0; i < 1_000_000; i++) sum += i;   // 매번 Long 객체 생성 → 느림
```
→ 반복 계산은 기본형 사용

| 상황 | 선택 |
|---|---|
| 계산, 반복문, 지역 변수 | **기본형** |
| 컬렉션·제네릭, null이 의미 있는 값 (DB의 NULL, JPA id) | 래퍼 |

## 4. String

### 불변 (Immutable)
```java
String s = "hello";
s.concat(" world");          // 새 String을 반환할 뿐 s는 그대로
s = s.concat(" world");      // s가 새 객체를 가리킴
```
불변으로 만든 이유:
| 이유 | 설명 |
|---|---|
| **String Pool**로 공유 | 같은 문자열을 여러 곳에서 안전하게 공유 |
| **보안** | DB URL, 파일 경로, 클래스 이름이 중간에 바뀌면 위험 |
| **스레드 안전** | 동기화 없이 공유 가능 |
| **hashCode 캐싱** | HashMap 키로 쓸 때 해시를 한 번만 계산 |

### String Pool
```java
String a = "java";                  // 리터럴 → String Pool(Heap 안의 특별한 영역)
String b = "java";                  // 같은 객체 재사용
String c = new String("java");      // 항상 새 객체

a == b        // true
a == c        // false
a.equals(c)   // true
c.intern() == a   // true (Pool의 객체 반환)
```
> 문자열 비교는 **항상 `equals()`**. `==`는 같은 객체인지 비교합니다.

### 문자열 연결: + vs StringBuilder
```java
// 반복문 안에서 + : 매번 새 String 생성 (O(n²))
String result = "";
for (String s : list) result += s;

// StringBuilder: 내부 버퍼에 이어 붙임 (O(n))
StringBuilder sb = new StringBuilder();
for (String s : list) sb.append(s);
String result = sb.toString();

// 구분자 연결
String joined = String.join(", ", list);
String joined2 = list.stream().collect(Collectors.joining(", "));
```
| 클래스 | 가변 | 스레드 안전 | 용도 |
|---|---|---|---|
| `String` | X | O (불변) | 일반 |
| **`StringBuilder`** | O | X | **대부분의 문자열 조립** |
| `StringBuffer` | O | O (synchronized) | 레거시 |

> 한 줄짜리 `"a" + b + "c"`는 컴파일러가 최적화하므로 그냥 `+`를 써도 됩니다. 문제는 **반복문 안의 `+=`** 입니다.

### 자주 쓰는 메서드 (Java 11+)
```java
" hi ".strip();            // 앞뒤 공백 제거 (유니코드 공백 포함, trim보다 권장)
"".isBlank();              // 공백만 있으면 true
"ab".repeat(3);            // "ababab"
"a\nb".lines().toList();   // ["a", "b"]
"%s님 %d원".formatted("윤빈", 1000);   // Java 15+
```

## 5. 면접 질문

1. **자바는 Call by Value인가요, Call by Reference인가요?**
   → 항상 Call by Value입니다. 참조형은 객체의 주소 값을 복사해서 전달하므로 객체 내부는 바꿀 수 있지만, 호출한 쪽 변수가 다른 객체를 가리키게 할 수는 없습니다.
2. **Integer를 ==로 비교하면 생기는 문제는?**
   → -128~127은 캐시된 같은 객체라 true지만 그 밖의 값은 다른 객체라 false가 나와 버그가 생깁니다. equals로 비교해야 합니다.
3. **String이 불변인 이유는?**
   → String Pool에서 안전하게 공유하고, 보안과 스레드 안전성을 보장하며, 해시값을 캐싱해 HashMap 키로 효율적으로 쓰기 위해서입니다.
4. **String, StringBuilder, StringBuffer의 차이는?**
   → String은 불변이고, StringBuilder는 가변이며 동기화가 없어 빠르고, StringBuffer는 가변이며 메서드가 동기화되어 스레드 안전하지만 느립니다.

## 핵심 정리
- 기본형 = 값, 참조형 = Heap 주소, 자바는 **항상 Call by Value**
- 래퍼는 `equals`로 비교 (Integer 캐시 -128~127), 언박싱 NPE 주의
- String 불변(Pool, 보안, 스레드 안전, 해시 캐싱), 비교는 `equals`
- 반복 연결은 `StringBuilder`, `String.join`
