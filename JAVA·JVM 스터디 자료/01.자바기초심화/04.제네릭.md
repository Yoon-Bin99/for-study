# 04. 제네릭 (Generics)

> **학습 목표**
> - 제네릭을 쓰는 이유(타입 안전성)를 설명할 수 있다.
> - 제네릭 클래스·메서드, 타입 제한(bounded type)을 작성할 수 있다.
> - 와일드카드와 PECS 원칙을 설명할 수 있다.
> - 타입 소거(type erasure)와 그로 인한 제약을 설명할 수 있다.

---

## 1. 왜 제네릭인가?

```java
// 제네릭 이전 (Java 1.4)
List list = new ArrayList();
list.add("hello");
list.add(123);                       // 아무 타입이나 들어감
String s = (String) list.get(1);     // 런타임에 ClassCastException!

// 제네릭
List<String> list = new ArrayList<>();
list.add(123);                       // ❌ 컴파일 에러 → 실수를 미리 발견
String s = list.get(0);              // 형변환 불필요
```
| 장점 | |
|---|---|
| **컴파일 시점 타입 검사** | 런타임 ClassCastException 방지 |
| 형변환 제거 | 코드 간결 |
| 재사용 | 타입만 바꿔 같은 로직 사용 |

---

## 2. 제네릭 클래스와 메서드

```java
// 제네릭 클래스
public class ApiResponse<T> {
    private final boolean success;
    private final T data;

    private ApiResponse(boolean success, T data) { this.success = success; this.data = data; }

    public static <T> ApiResponse<T> ok(T data) { return new ApiResponse<>(true, data); }
    public T getData() { return data; }
}

ApiResponse<MemberResponse> res = ApiResponse.ok(new MemberResponse(1L, "a@b.com", "kim"));
```

```java
// 제네릭 메서드: 반환 타입 앞에 <T>
public static <T> T firstOrDefault(List<T> list, T defaultValue) {
    return list.isEmpty() ? defaultValue : list.get(0);
}
```

### 타입 매개변수 이름 관례
| 이름 | 의미 |
|---|---|
| `T` | Type |
| `E` | Element (컬렉션) |
| `K`, `V` | Key, Value |
| `R` | Return |

### 타입 제한 (Bounded Type)
```java
// Number의 하위 타입만
public static <T extends Number> double sum(List<T> numbers) {
    return numbers.stream().mapToDouble(Number::doubleValue).sum();
}

// 비교 가능한 타입만 (Comparable 구현)
public static <T extends Comparable<T>> T max(List<T> list) {
    return list.stream().max(Comparator.naturalOrder()).orElseThrow();
}
```

## 3. 제네릭은 불공변(invariant)

```java
Integer는 Number의 하위 타입이지만
List<Integer>는 List<Number>의 하위 타입이 아니다!

List<Integer> ints = new ArrayList<>();
List<Number> nums = ints;     // ❌ 컴파일 에러
```
왜? 허용하면 이런 일이 생깁니다:
```java
nums.add(3.14);               // Number니까 Double을 넣을 수 있음
Integer i = ints.get(0);      // 실제로는 Double → 깨짐
```
> 배열은 공변(`Integer[]`는 `Number[]`의 하위 타입)이라 이 문제가 **런타임** `ArrayStoreException`으로 터집니다. 제네릭은 컴파일 시점에 막습니다.

---

## 4. 와일드카드 (?)

| 문법 | 의미 | 할 수 있는 것 |
|---|---|---|
| `List<?>` | 아무 타입 | 읽기(Object로), 쓰기 X (null만) |
| `List<? extends Number>` | Number 또는 **하위** 타입 | **읽기** (Number로 꺼냄), 쓰기 X |
| `List<? super Integer>` | Integer 또는 **상위** 타입 | **쓰기** (Integer 넣기), 읽기는 Object로 |

```java
// 읽기만: extends
double total(List<? extends Number> list) {
    double sum = 0;
    for (Number n : list) sum += n.doubleValue();   // List<Integer>, List<Double> 모두 가능
    return sum;
}

// 쓰기만: super
void addNumbers(List<? super Integer> list) {
    list.add(1);                                      // List<Integer>, List<Number>, List<Object> 모두 가능
    list.add(2);
}
```

### PECS: Producer-Extends, Consumer-Super
- 매개변수가 값을 **생산(꺼내 줌)** 하면 → `extends`
- 매개변수가 값을 **소비(받아 감)** 하면 → `super`

```java
// Collections.copy의 시그니처
public static <T> void copy(List<? super T> dest, List<? extends T> src)
//                            소비자(써 넣음)          생산자(꺼냄)
```

## 5. 타입 소거 (Type Erasure)

제네릭 타입 정보는 **컴파일할 때만** 쓰이고, 바이트코드에서는 지워집니다 (하위 호환을 위해).
```java
List<String> a = new ArrayList<>();
List<Integer> b = new ArrayList<>();
a.getClass() == b.getClass();      // true — 런타임엔 둘 다 그냥 ArrayList
```
```
컴파일 전:  List<String> list;  String s = list.get(0);
컴파일 후:  List list;          String s = (String) list.get(0);   ← 형변환이 자동 삽입
          <T extends Number>는 Number로, 제한 없는 <T>는 Object로 바뀜
```

### 타입 소거로 인한 제약
| 불가능 | 이유 / 대안 |
|---|---|
| `new T()` | T가 무엇인지 런타임에 모름 → `Supplier<T>`나 `Class<T>`를 받기 |
| `new T[10]` | 마찬가지 |
| `obj instanceof List<String>` | `instanceof List<?>`만 가능 |
| 기본형 `List<int>` | Object로 소거되므로 → 래퍼 사용 |
| `static T field` | 정적 필드는 모든 인스턴스가 공유 |
| 제네릭 타입만 다른 오버로딩 `m(List<String>)`, `m(List<Integer>)` | 소거 후 시그니처가 같음 |

### 런타임에 제네릭 타입이 필요할 때
```java
// Jackson으로 List<MemberDto> 역직렬화
List<MemberDto> list = objectMapper.readValue(json, new TypeReference<List<MemberDto>>() {});

// Spring RestClient
List<MemberDto> list = restClient.get().uri("/members")
        .retrieve().body(new ParameterizedTypeReference<List<MemberDto>>() {});
```
> 익명 하위 클래스를 만들면 **상위 타입의 제네릭 정보는 클래스 메타데이터에 남기 때문에** 꺼낼 수 있습니다 (슈퍼 타입 토큰).

## 6. 면접 질문

1. **제네릭을 쓰는 이유는?**
   → 컴파일 시점에 타입을 검사해 런타임 ClassCastException을 막고, 형변환을 없애며, 여러 타입에 같은 코드를 재사용하기 위해서입니다.
2. **List<Integer>를 List<Number>에 대입할 수 없는 이유는?**
   → 제네릭은 불공변이기 때문입니다. 허용하면 Number 리스트로 Double을 넣어 Integer 리스트를 오염시킬 수 있습니다.
3. **PECS란?**
   → 값을 꺼내는 생산자 매개변수에는 extends, 값을 넣는 소비자 매개변수에는 super 와일드카드를 쓰라는 원칙입니다.
4. **타입 소거란? 어떤 제약이 있나요?**
   → 제네릭 타입 정보가 컴파일 후 지워지고 필요한 곳에 형변환이 삽입되는 것으로, 런타임에 타입을 알 수 없어 new T(), 제네릭 배열 생성, instanceof List<String>이 불가능합니다.

---

## 핵심 정리
- 제네릭 = 컴파일 시점 타입 안전 + 형변환 제거
- `<T extends X>`로 타입 제한, 제네릭 메서드는 반환 타입 앞에 `<T>`
- 제네릭은 **불공변** → 와일드카드, **PECS** (꺼내면 extends, 넣으면 super)
- **타입 소거**: 런타임엔 타입 정보 없음 → `new T()` 불가, TypeReference로 우회
