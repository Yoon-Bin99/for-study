# 05. enum, 애노테이션, 리플렉션, 동적 프록시

> **학습 목표**
> - enum을 상수 이상의 용도(상태·행위·전략)로 활용할 수 있다.
> - 애노테이션의 구조(@Target, @Retention)를 설명하고 커스텀 애노테이션을 만들 수 있다.
> - 리플렉션의 원리와 비용을 설명할 수 있다.
> - JDK 동적 프록시의 원리와 Spring AOP·JPA와의 관계를 설명할 수 있다.

---

## 1. enum

### 왜 enum인가?
```java
// ❌ 정수 상수: 타입 안전 X, 의미 없는 값이 들어갈 수 있음
public static final int STATUS_READY = 0;
order.setStatus(99);        // 컴파일 통과

// ✅ enum
public enum OrderStatus { READY, PAID, SHIPPED, CANCELED }
order.setStatus(OrderStatus.PAID);    // 정해진 값만
```
- enum 상수는 **클래스의 유일한 인스턴스**(싱글톤) → `==` 비교 가능
- `values()`, `valueOf("PAID")`, `name()`, `ordinal()` 제공

### 필드·메서드를 가진 enum
```java
public enum Grade {
    VIP(20), GOLD(10), BASIC(0);

    private final int discountRate;

    Grade(int discountRate) { this.discountRate = discountRate; }

    public long discount(long price) { return price * discountRate / 100; }
}
```

### 상수별 행위 (전략 패턴)
```java
public enum Operator {
    PLUS("+")  { public int apply(int a, int b) { return a + b; } },
    MINUS("-") { public int apply(int a, int b) { return a - b; } };

    private final String symbol;
    Operator(String symbol) { this.symbol = symbol; }
    public abstract int apply(int a, int b);

    public static Operator of(String symbol) {
        return Arrays.stream(values()).filter(o -> o.symbol.equals(symbol)).findFirst()
                .orElseThrow(() -> new IllegalArgumentException("지원하지 않는 연산자: " + symbol));
    }
}
```

### 상태 전이 규칙
```java
public enum OrderStatus {
    READY, PAID, SHIPPED, CANCELED;

    public boolean canCancel() { return this == READY || this == PAID; }
}
```

### 주의
| 주의 | 설명 |
|---|---|
| **JPA에서 `EnumType.ORDINAL` 금지** | 순서(0,1,2)로 저장 → 중간에 상수를 추가하면 기존 데이터 의미가 바뀜 → **`EnumType.STRING`** |
| `ordinal()`에 의존하지 않기 | 순서가 필요하면 필드로 |
| 성능 좋은 컬렉션 | `EnumMap`, `EnumSet` (내부적으로 배열·비트 벡터) |

## 2. 애노테이션

코드에 붙이는 **메타데이터**입니다. 그 자체로는 아무 일도 하지 않고, **컴파일러나 프레임워크가 읽어서** 동작합니다.

| 읽는 주체 | 예 |
|---|---|
| 컴파일러 | `@Override`, `@FunctionalInterface`, `@SuppressWarnings` |
| 애노테이션 프로세서 (컴파일 시 코드 생성) | **Lombok** `@Getter`, QueryDSL `@Entity` → Q클래스, MapStruct |
| 런타임 리플렉션 | Spring `@Component`, `@Transactional`, JPA `@Entity`, JUnit `@Test` |

### 커스텀 애노테이션
```java
@Target(ElementType.METHOD)              // 어디에 붙일 수 있나
@Retention(RetentionPolicy.RUNTIME)      // 언제까지 유지되나
@Documented
public @interface LogExecutionTime {
    String value() default "";
    long slowThresholdMs() default 1000;
}
```

| @Retention | 유지 범위 | 용도 |
|---|---|---|
| `SOURCE` | 소스 코드만 (컴파일 후 사라짐) | `@Override`, Lombok |
| `CLASS` (기본) | 클래스 파일까지, 런타임엔 X | 바이트코드 도구 |
| **`RUNTIME`** | 런타임까지 → **리플렉션으로 읽기 가능** | Spring, JPA, 커스텀 AOP |

| @Target | 대상 |
|---|---|
| `TYPE` | 클래스, 인터페이스, enum, record |
| `METHOD`, `FIELD`, `PARAMETER` | 메서드, 필드, 파라미터 |
| `ANNOTATION_TYPE` | 다른 애노테이션 (메타 애노테이션) |

> Spring의 `@Service`는 `@Component`를 메타 애노테이션으로 가진 애노테이션입니다. `@RestController` = `@Controller` + `@ResponseBody`.

## 3. 리플렉션 (Reflection)

**런타임에 클래스의 구조(필드, 메서드, 생성자, 애노테이션)를 조회하고 조작**하는 기능입니다.

```java
Class<?> clazz = Member.class;                 // 또는 obj.getClass(), Class.forName("com.x.Member")

for (Field f : clazz.getDeclaredFields()) {
    System.out.println(f.getName() + " : " + f.getType().getSimpleName());
}

Constructor<?> ctor = clazz.getDeclaredConstructor();
ctor.setAccessible(true);                      // private 생성자 접근
Object instance = ctor.newInstance();

Method m = clazz.getMethod("getName");
Object name = m.invoke(instance);

if (clazz.isAnnotationPresent(Entity.class)) { ... }
```

### 프레임워크가 리플렉션을 쓰는 곳
| 프레임워크 | 용도 |
|---|---|
| **Spring** | `@Component` 스캔 → 객체 생성, `@Autowired` 필드 주입, `@RequestMapping` 메서드 호출 |
| **JPA / Hibernate** | **기본 생성자로 엔티티 생성**, 필드에 값 채우기 → 엔티티에 `protected` 기본 생성자가 필요한 이유 |
| **Jackson** | JSON ↔ 객체 (기본 생성자 또는 생성자 파라미터, getter/필드) |
| **JUnit** | `@Test` 메서드 찾아 실행 |

### 단점
| 단점 | 설명 |
|---|---|
| 성능 | 일반 호출보다 느림 (최근 JVM은 MethodHandle 기반으로 많이 개선) |
| 캡슐화 파괴 | private 접근 가능 |
| 컴파일 타임 검사 X | 오타가 런타임 에러 |
| 모듈 시스템 제약 | Java 9+ 모듈의 내부 패키지는 `setAccessible` 제한 |

> 애플리케이션 코드에서 직접 쓸 일은 드뭅니다. **프레임워크가 어떻게 동작하는지 이해**하는 데 중요합니다. GraalVM 네이티브 이미지는 리플렉션 대상을 미리 알려 줘야 합니다.

## 4. 동적 프록시 (Dynamic Proxy)

**런타임에 인터페이스 구현 객체를 만들어, 메서드 호출을 가로채는** 기능입니다. Spring AOP, `@Transactional`, Spring Data JPA Repository의 기반입니다.

```java
public interface OrderService { void order(Long id); }

public class OrderServiceImpl implements OrderService {
    public void order(Long id) { System.out.println("주문 " + id); }
}

// 호출을 가로채는 핸들러
public class TimingHandler implements InvocationHandler {
    private final Object target;
    public TimingHandler(Object target) { this.target = target; }

    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        long start = System.nanoTime();
        try {
            return method.invoke(target, args);                // 실제 객체 호출
        } finally {
            System.out.printf("%s: %dμs%n", method.getName(), (System.nanoTime() - start) / 1000);
        }
    }
}

OrderService proxy = (OrderService) Proxy.newProxyInstance(
        OrderService.class.getClassLoader(),
        new Class<?>[]{OrderService.class},
        new TimingHandler(new OrderServiceImpl()));

proxy.order(1L);    // "주문 1" + "order: 52μs"
```

| 방식 | 대상 | 원리 |
|---|---|---|
| **JDK 동적 프록시** | **인터페이스**가 있어야 함 | 인터페이스를 구현한 프록시 클래스 생성 |
| **CGLIB / ByteBuddy** | 클래스 (인터페이스 없어도) | 대상 클래스를 **상속**한 하위 클래스 생성 → `final` 클래스·메서드는 불가 |

- **Spring Boot는 기본적으로 CGLIB** (`proxyTargetClass=true`)
- **JPA 지연 로딩 프록시**는 엔티티를 상속한 프록시(ByteBuddy) → 엔티티 클래스를 `final`로 만들면 안 되는 이유
- Spring Data JPA의 `interface MemberRepository extends JpaRepository`는 구현 클래스가 없어도 **동적 프록시**가 구현체를 만들어 줌

> 프록시 기반이기 때문에 생기는 문제: **같은 클래스 내부 호출(`this.method()`)은 프록시를 거치지 않아 `@Transactional`, `@Cacheable`, `@Async`가 적용되지 않습니다.** (→ Spring JPA 자료 `01.스프링핵심/03.AOP와프록시.md`)

## 5. 면접 질문

1. **JPA에서 enum을 ORDINAL로 저장하면 안 되는 이유는?**
   → 상수의 순서 번호로 저장되므로 중간에 새 상수를 추가하거나 순서를 바꾸면 기존 데이터의 의미가 바뀌기 때문에 STRING으로 저장합니다.
2. **@Retention(RUNTIME)의 의미는?**
   → 애노테이션 정보가 런타임까지 유지되어 리플렉션으로 읽을 수 있다는 뜻으로, Spring이나 JPA 같은 프레임워크가 동작하려면 필요합니다.
3. **리플렉션이란? 어디에 쓰이나요?**
   → 런타임에 클래스의 필드·메서드·생성자·애노테이션 정보를 조회하고 호출하는 기능으로, Spring의 빈 생성과 의존성 주입, JPA의 엔티티 생성, Jackson 직렬화 등에 쓰입니다.
4. **JDK 동적 프록시와 CGLIB의 차이는?**
   → JDK 동적 프록시는 인터페이스를 구현한 프록시를 만들고, CGLIB은 대상 클래스를 상속한 프록시를 만들어 인터페이스가 없어도 되지만 final 클래스·메서드에는 적용할 수 없습니다.

## 핵심 정리
- enum = 타입 안전 상수 + 필드·메서드·상수별 행위, JPA는 `EnumType.STRING`, EnumMap·EnumSet
- 애노테이션 = 메타데이터, 읽는 주체(컴파일러·프로세서·리플렉션), `@Retention(RUNTIME)` + `@Target`
- 리플렉션 = 런타임 구조 조회·조작 → Spring·JPA·Jackson의 기반 (엔티티 기본 생성자가 필요한 이유)
- 동적 프록시: JDK(인터페이스) vs CGLIB(상속, final 불가) → AOP·@Transactional·지연 로딩, 내부 호출 미적용
