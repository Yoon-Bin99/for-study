# 01. 컬렉션 프레임워크

> **학습 목표**
> - Collection 계층과 List·Set·Queue·Map의 특징을 설명할 수 있다.
> - 상황에 맞는 구현체를 시간복잡도 기준으로 고를 수 있다.
> - 불변 컬렉션과 수정 가능한 컬렉션의 차이를 설명할 수 있다.
> - Comparable·Comparator, Iterator와 ConcurrentModificationException을 설명할 수 있다.

## 1. 계층 구조

```
Iterable
 └── Collection
      ├── List         순서 O, 중복 O        ArrayList, LinkedList
      ├── Set          중복 X                 HashSet, LinkedHashSet, TreeSet
      │    └── SortedSet / NavigableSet       TreeSet
      └── Queue        FIFO 등                ArrayDeque, PriorityQueue, LinkedList
           └── Deque   양쪽                   ArrayDeque, LinkedList

Map (Collection을 상속하지 않음)  키-값       HashMap, LinkedHashMap, TreeMap
 └── SortedMap / NavigableMap                TreeMap

Java 21+: SequencedCollection, SequencedSet, SequencedMap  (순서가 있는 컬렉션에 getFirst/getLast/reversed 추가)
```

## 2. 구현체별 특징과 시간복잡도

### List
| 구현체 | 내부 | get(i) | add 끝 | add/remove 중간 | 비고 |
|---|---|---|---|---|---|
| **ArrayList** | 동적 배열 (1.5배 확장) | **O(1)** | O(1)* | O(n) | **기본 선택** |
| LinkedList | 이중 연결리스트 | O(n) | O(1) | O(1) (위치를 알 때) | 실제로는 거의 쓸 일 없음 (캐시 비효율) |

### Set
| 구현체 | 내부 | add/contains | 순서 |
|---|---|---|---|
| **HashSet** | HashMap | **O(1)** | 없음 |
| LinkedHashSet | HashMap + 연결리스트 | O(1) | **삽입 순서** |
| TreeSet | 레드블랙 트리 | O(log n) | **정렬**, 범위 검색 (`ceiling`, `floor`, `subSet`) |

### Map
| 구현체 | 내부 | get/put | 순서 | null 키 |
|---|---|---|---|---|
| **HashMap** | 해시 테이블 + 트리화 | **O(1)** | 없음 | 1개 허용 |
| LinkedHashMap | 해시 + 이중 연결리스트 | O(1) | 삽입 순서 (또는 접근 순서 → LRU) | 허용 |
| TreeMap | 레드블랙 트리 | O(log n) | 키 정렬 | X |
| ConcurrentHashMap | 버킷 단위 동기화 | O(1) | 없음 | **X** |

### Queue / Deque
| 구현체 | 용도 |
|---|---|
| **ArrayDeque** | **스택·큐·덱 모두** (Stack, LinkedList보다 빠름) |
| PriorityQueue | 힙, 우선순위 순서 (O(log n)) |

\* 분할 상환 O(1). 자료구조 원리는 CS 자료 `01.자료구조` 참고

### 선택 가이드
| 필요 | 선택 |
|---|---|
| 순서대로 저장, 인덱스 접근 | `ArrayList` |
| 중복 제거, 빠른 포함 확인 | `HashSet` |
| 중복 제거 + 넣은 순서 유지 | `LinkedHashSet` |
| 정렬 상태 유지, 범위 검색 | `TreeSet` / `TreeMap` |
| 키로 빠른 조회 | `HashMap` |
| 스택·큐 | `ArrayDeque` |
| 최솟값·최댓값을 계속 꺼냄 | `PriorityQueue` |
| 멀티스레드 공유 맵 | `ConcurrentHashMap` |

## 3. 불변 컬렉션

```java
List<String> a = List.of("a", "b");          // Java 9+ 불변
a.add("c");                                   // UnsupportedOperationException
List.of("a", null);                           // NullPointerException (null 불허)

List<String> b = Arrays.asList("a", "b");     // 고정 크기: set은 되고 add/remove는 안 됨, 원본 배열과 연결
List<String> c = new ArrayList<>(List.of("a", "b"));   // 수정 가능한 복사본
List<String> d = List.copyOf(c);              // 불변 복사본
List<String> e = Collections.unmodifiableList(c);      // 읽기 전용 뷰 (c가 바뀌면 e도 바뀜)
List<String> f = stream.toList();             // Java 16+ 불변 리스트
```

| 메서드 | 수정 | null | 원본과 연결 |
|---|---|---|---|
| `List.of`, `List.copyOf`, `stream.toList()` | X | X (`toList`는 허용) | X |
| `Arrays.asList` | set만 O | O | **O** (배열) |
| `Collections.unmodifiableList` | X | O | **O** (뷰) |
| `new ArrayList<>(...)` | O | O | X |

> 반환값으로는 불변 컬렉션을 주는 것이 안전합니다. 받은 쪽이 수정해야 하면 `new ArrayList<>(받은것)`으로 복사합니다.

## 4. Comparable과 Comparator

| 구분 | Comparable | Comparator |
|---|---|---|
| 위치 | 클래스 **자신이 구현** (`compareTo`) | **외부**에서 정의 (`compare`) |
| 의미 | **자연 순서** (기본 정렬 기준) | 상황별 정렬 기준 |
| 예 | String(사전순), Integer, LocalDate | 나이순, 이름 역순 |

```java
public record Member(String name, int age) implements Comparable<Member> {
    @Override
    public int compareTo(Member o) {
        return Integer.compare(this.age, o.age);     // 음수: 내가 앞, 0: 같음, 양수: 내가 뒤
    }
}

list.sort(null);                                   // Comparable 기준
list.sort(Comparator.comparing(Member::name));     // 이름순
list.sort(Comparator.comparingInt(Member::age).reversed()
                    .thenComparing(Member::name)); // 나이 내림차순, 같으면 이름순
list.sort(Comparator.comparing(Member::name, Comparator.nullsLast(Comparator.naturalOrder())));
```
> `(a, b) -> a.age - b.age`는 **오버플로 위험**이 있습니다. `Integer.compare`나 `Comparator.comparingInt`를 쓰세요.

## 5. Iterator와 ConcurrentModificationException

```java
List<Integer> list = new ArrayList<>(List.of(1, 2, 3, 4));

for (Integer n : list) {
    if (n % 2 == 0) list.remove(n);       // ❌ ConcurrentModificationException
}
```
- 향상된 for문은 내부적으로 **Iterator**를 씀
- ArrayList는 수정 횟수(`modCount`)를 기록하고, 순회 중 다른 경로로 구조가 바뀌면 **즉시 예외(fail-fast)**

```java
// ✅ 방법 1: removeIf (Java 8+)
list.removeIf(n -> n % 2 == 0);

// ✅ 방법 2: Iterator.remove
Iterator<Integer> it = list.iterator();
while (it.hasNext()) {
    if (it.next() % 2 == 0) it.remove();
}

// ✅ 방법 3: 새 리스트로 필터링
List<Integer> odds = list.stream().filter(n -> n % 2 != 0).toList();
```
> 이름과 달리 **멀티스레드가 아니어도** 발생합니다. 멀티스레드 환경에서는 `CopyOnWriteArrayList`, `ConcurrentHashMap`처럼 **fail-safe**(약한 일관성) 컬렉션을 씁니다.

## 7. 면접 질문

1. **ArrayList와 LinkedList의 차이는?**
   → ArrayList는 동적 배열로 인덱스 접근이 O(1)이고 중간 삽입·삭제가 O(n), LinkedList는 이중 연결리스트로 인덱스 접근이 O(n)입니다. 캐시 지역성 때문에 대부분 ArrayList가 빠릅니다.
2. **HashMap, LinkedHashMap, TreeMap의 차이는?**
   → HashMap은 순서 없이 O(1), LinkedHashMap은 삽입(또는 접근) 순서를 유지하며 O(1), TreeMap은 키 정렬을 유지하며 O(log n)이고 범위 검색이 가능합니다.
3. **Comparable과 Comparator의 차이는?**
   → Comparable은 클래스 스스로 자연 순서를 정의하고, Comparator는 외부에서 다양한 정렬 기준을 정의합니다.
4. **ConcurrentModificationException은 왜 발생하나요?**
   → 컬렉션을 Iterator로 순회하는 중에 Iterator가 아닌 방법으로 구조를 변경하면 fail-fast로 감지해 던집니다. removeIf나 Iterator.remove를 씁니다.

## 핵심 정리
- 기본 선택: `ArrayList`, `HashMap`, `HashSet`, `ArrayDeque`
- 순서 유지 Linked*, 정렬 Tree*, 동시성 Concurrent*
- 불변: `List.of`/`copyOf`/`toList()` vs 뷰 `unmodifiableList` vs `Arrays.asList`(고정 크기)
- Comparable(자연 순서) vs Comparator(외부 기준), `Integer.compare`
- 순회 중 삭제 → `removeIf`, fail-fast
