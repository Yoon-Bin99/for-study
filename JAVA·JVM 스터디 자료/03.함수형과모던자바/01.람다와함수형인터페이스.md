# 01. 람다와 함수형 인터페이스

> **학습 목표**
> - 람다 표현식의 문법과 익명 클래스와의 차이를 설명할 수 있다.
> - 주요 함수형 인터페이스(Function, Consumer, Supplier, Predicate)를 사용할 수 있다.
> - 메서드 참조 4가지 형태를 사용할 수 있다.
> - effectively final과 람다 캡처를 설명할 수 있다.

---

## 1. 람다 표현식

**메서드 하나짜리 인터페이스의 구현을 간결하게** 쓰는 문법입니다. (Java 8+)

```java
// 익명 클래스
Comparator<String> c1 = new Comparator<String>() {
    @Override
    public int compare(String a, String b) { return a.length() - b.length(); }
};

// 람다
Comparator<String> c2 = (a, b) -> a.length() - b.length();
```

| 형태 | 예 |
|---|---|
| 매개변수 없음 | `() -> "hello"` |
| 매개변수 하나 (괄호 생략 가능) | `x -> x * 2` |
| 여러 개 | `(a, b) -> a + b` |
| 타입 명시 | `(String s) -> s.length()` |
| 여러 문장 | `x -> { int y = x * 2; return y + 1; }` |

## 2. 함수형 인터페이스

**추상 메서드가 정확히 하나**인 인터페이스입니다. 람다는 함수형 인터페이스 타입으로만 쓸 수 있습니다.
```java
@FunctionalInterface           // 추상 메서드가 둘 이상이면 컴파일 에러로 알려 줌
public interface DiscountPolicy {
    long discount(long price);
    default String name() { return "기본"; }   // default·static 메서드는 있어도 됨
}

DiscountPolicy tenPercent = price -> price / 10;
```

### java.util.function 주요 인터페이스
| 인터페이스 | 메서드 | 형태 | 예 |
|---|---|---|---|
| **`Function<T, R>`** | `R apply(T)` | T → R | `s -> s.length()` |
| **`Consumer<T>`** | `void accept(T)` | T → (없음) | `s -> System.out.println(s)` |
| **`Supplier<T>`** | `T get()` | () → T | `() -> new ArrayList<>()` |
| **`Predicate<T>`** | `boolean test(T)` | T → boolean | `s -> s.isEmpty()` |
| `BiFunction<T, U, R>` | `R apply(T, U)` | (T, U) → R | `(a, b) -> a + b` |
| `UnaryOperator<T>` | `T apply(T)` | T → T | `s -> s.toUpperCase()` |
| `BinaryOperator<T>` | `T apply(T, T)` | (T, T) → T | `Integer::sum` |
| `Runnable` | `void run()` | () → () | 스레드 작업 |
| `Callable<V>` | `V call() throws Exception` | () → V | 결과 있는 비동기 작업 |

> 기본형 특화 버전(`IntFunction`, `ToIntFunction`, `IntPredicate`, `LongSupplier` …)은 **오토박싱 비용**을 없애 줍니다.

### 조합
```java
Predicate<String> notEmpty = s -> !s.isEmpty();
Predicate<String> shortStr = s -> s.length() < 5;
Predicate<String> valid = notEmpty.and(shortStr).negate();

Function<Integer, Integer> plus1 = x -> x + 1;
Function<Integer, Integer> times2 = x -> x * 2;
plus1.andThen(times2).apply(3);    // (3+1)*2 = 8
plus1.compose(times2).apply(3);    // 3*2+1 = 7
```

## 3. 메서드 참조

람다가 **기존 메서드 하나를 호출하기만** 할 때 더 짧게 씁니다.

| 형태 | 람다 | 메서드 참조 |
|---|---|---|
| 정적 메서드 | `s -> Integer.parseInt(s)` | `Integer::parseInt` |
| 특정 객체의 메서드 | `s -> printer.print(s)` | `printer::print` |
| 임의 객체의 메서드 (첫 인자가 수신자) | `s -> s.toUpperCase()` | `String::toUpperCase` |
| 생성자 | `() -> new ArrayList<>()` | `ArrayList::new` |

```java
members.stream().map(Member::getName).forEach(System.out::println);
Supplier<List<String>> listFactory = ArrayList::new;
Function<String, Member> creator = Member::new;     // Member(String) 생성자
```

## 4. 변수 캡처와 effectively final

람다는 바깥의 지역 변수를 사용할 수 있지만, 그 변수는 **final이거나 사실상 final**(값이 바뀌지 않음)이어야 합니다.
```java
int base = 10;
Function<Integer, Integer> add = x -> x + base;   // OK
base = 20;                                          // ❌ 이 줄이 있으면 위 람다가 컴파일 에러

// 람다 안에서 바깥 변수 변경도 불가
int count = 0;
list.forEach(x -> count++);                         // ❌
```
왜? 람다는 **변수의 값을 복사해서** 가지고 있습니다(캡처). 지역 변수는 스택에 있고, 람다는 다른 스레드에서 나중에 실행될 수 있어서 값이 바뀌면 일관성이 깨집니다.

```java
// 대안: 스트림으로 계산하거나, 스레드 안전한 객체 사용
long count = list.stream().filter(...).count();
AtomicInteger counter = new AtomicInteger();
list.forEach(x -> counter.incrementAndGet());
```
> 필드(인스턴스 변수)는 힙에 있어 람다 안에서 바꿀 수 있지만, 멀티스레드에서는 동기화 문제가 생깁니다.

## 5. 람다 vs 익명 클래스

| 비교 | 람다 | 익명 클래스 |
|---|---|---|
| 대상 | 함수형 인터페이스만 | 인터페이스, 추상 클래스 (메서드 여러 개 가능) |
| `this` | **바깥 클래스** | 익명 클래스 자신 |
| 상태(필드) | 가질 수 없음 | 가질 수 있음 |
| 구현 | `invokedynamic` (별도 클래스 파일 X) | 별도 `.class` 파일 생성 |

## 6. 실전 예: 전략을 람다로

```java
public class PriceCalculator {
    private final Map<Grade, UnaryOperator<Long>> policies = Map.of(
            Grade.VIP,   price -> price * 80 / 100,
            Grade.GOLD,  price -> price * 90 / 100,
            Grade.BASIC, price -> price);

    public long calculate(Grade grade, long price) {
        return policies.get(grade).apply(price);
    }
}

// 공통 로직 + 다른 부분만 주입 (템플릿 콜백)
public <T> T executeWithTiming(String name, Supplier<T> action) {
    long start = System.currentTimeMillis();
    try {
        return action.get();
    } finally {
        log.info("{} took {}ms", name, System.currentTimeMillis() - start);
    }
}
OrderResponse r = executeWithTiming("order", () -> orderService.order(req));
```

## 7. 면접 질문

1. **함수형 인터페이스란?**
   → 추상 메서드가 하나뿐인 인터페이스로, 람다 표현식이나 메서드 참조로 구현할 수 있습니다. @FunctionalInterface로 명시합니다.
2. **람다에서 사용하는 지역 변수가 effectively final이어야 하는 이유는?**
   → 람다는 지역 변수의 값을 복사해 캡처하는데, 람다가 다른 스레드나 나중 시점에 실행될 수 있어 값이 바뀌면 일관성이 깨지기 때문입니다.
3. **Function, Consumer, Supplier, Predicate의 차이는?**
   → Function은 입력을 받아 결과를 반환, Consumer는 입력을 받아 소비만, Supplier는 입력 없이 값을 제공, Predicate는 입력을 받아 boolean을 반환합니다.

---

## 핵심 정리
- 람다 = 함수형 인터페이스(추상 메서드 1개) 구현의 간결한 표현
- 핵심 4종: `Function`(T→R), `Consumer`(T→void), `Supplier`(()→T), `Predicate`(T→boolean)
- 메서드 참조: `Class::static`, `obj::method`, `Class::instanceMethod`, `Class::new`
- 캡처 변수는 effectively final, 람다의 this는 바깥 클래스
