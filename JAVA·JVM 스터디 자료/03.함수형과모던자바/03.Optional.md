# 03. Optional

> **학습 목표**
> - Optional이 해결하려는 문제를 설명할 수 있다.
> - Optional을 올바르게 생성하고 값을 꺼낼 수 있다.
> - Optional을 쓰면 안 되는 곳(필드, 파라미터, 컬렉션)을 안다.

---

## 1. 왜 Optional인가?

```java
Member member = memberRepository.findByEmail(email);   // null일 수도?
member.getName();                                        // NullPointerException 가능
```
메서드 시그니처만 봐서는 null이 올 수 있는지 알 수 없습니다. **Optional은 "값이 없을 수 있음"을 타입으로 표현**합니다.
```java
Optional<Member> findByEmail(String email);    // 호출자가 "없을 수도 있다"를 반드시 처리하게 됨
```
> Optional은 **메서드 반환 타입**으로 쓰도록 설계되었습니다 (Java 8, 설계자 Brian Goetz의 의도).

---

## 2. 생성

```java
Optional.of(value);          // value가 null이면 즉시 NPE
Optional.ofNullable(value);  // null이면 빈 Optional
Optional.empty();            // 빈 Optional
```

---

## 3. 값 꺼내기와 처리

```java
Optional<Member> opt = memberRepository.findByEmail(email);

// ✅ 없으면 예외 (가장 많이 씀)
Member m = opt.orElseThrow(() -> new BusinessException(ErrorCode.MEMBER_NOT_FOUND));

// ✅ 없으면 기본값
String name = opt.map(Member::getName).orElse("익명");

// ✅ 기본값 생성 비용이 크면 orElseGet (없을 때만 실행)
Member m2 = opt.orElseGet(() -> memberRepository.save(new Member(email)));

// ✅ 있을 때만 실행
opt.ifPresent(member -> log.info("found {}", member.getId()));
opt.ifPresentOrElse(this::sendMail, () -> log.warn("회원 없음"));   // Java 9+

// ✅ 변환·필터
Optional<String> city = opt.map(Member::getAddress)       // Address가 null이면 빈 Optional
                           .map(Address::getCity);
Optional<Member> adult = opt.filter(member -> member.getAge() >= 20);

// 메서드가 Optional을 반환하면 flatMap
Optional<Team> team = opt.flatMap(Member::findTeam);       // findTeam(): Optional<Team>

// 대안 Optional
Optional<Member> result = opt.or(() -> memberRepository.findByPhone(phone));   // Java 9+

// 스트림으로
List<String> names = ids.stream()
        .map(memberRepository::findById)
        .flatMap(Optional::stream)                         // Java 9+: 있는 것만
        .map(Member::getName)
        .toList();
```

### orElse vs orElseGet
```java
opt.orElse(createDefault());          // ★ 값이 있어도 createDefault()가 항상 실행됨
opt.orElseGet(() -> createDefault()); // 값이 없을 때만 실행
```
> `orElse(memberRepository.save(...))`처럼 쓰면 **값이 있어도 save가 실행**되는 버그가 납니다.

## 4. 안티 패턴

```java
// ❌ isPresent + get: null 체크와 다를 게 없음
if (opt.isPresent()) {
    return opt.get().getName();
}
return "익명";
// ✅
return opt.map(Member::getName).orElse("익명");

// ❌ get() 단독 사용: 비어 있으면 NoSuchElementException
opt.get();
// ✅ orElseThrow() (Java 10+, 이름이 의도를 드러냄)

// ❌ Optional 자체가 null
Optional<Member> find() { return null; }    // 절대 금지

// ❌ 필드
private Optional<String> nickname;          // 직렬화 불가(Serializable 아님), JPA 매핑 불가

// ❌ 메서드 파라미터
void update(Optional<String> nickname)      // 호출자가 Optional.empty(), null, 값 세 가지를 넘길 수 있음 → 오버로딩이나 null 허용으로

// ❌ 컬렉션을 Optional로
Optional<List<Member>> findAll()            // 빈 리스트를 반환하면 됨

// ❌ 단순 null 체크 대용으로 체인
Optional.ofNullable(x).ifPresent(...)       // 그냥 if (x != null)이 더 명확한 경우도 많음
```

| 쓰는 곳 | 쓰지 않는 곳 |
|---|---|
| **반환 타입** (결과가 없을 수 있는 조회) | 필드, 파라미터, 컬렉션 원소·컬렉션 자체, Map 값 |

### 기본형 Optional
`OptionalInt`, `OptionalLong`, `OptionalDouble` → 박싱 비용 없음 (`IntStream.max()`의 반환 타입)

## 5. Spring Data JPA와 Optional

```java
public interface MemberRepository extends JpaRepository<Member, Long> {
    Optional<Member> findByEmail(String email);      // 단건 조회는 Optional 반환 가능
    List<Member> findByGrade(Grade grade);           // 다건은 빈 리스트
}

Member member = memberRepository.findById(id)
        .orElseThrow(() -> new BusinessException(ErrorCode.MEMBER_NOT_FOUND));
```

## 6. 면접 질문

1. **Optional을 쓰는 이유는?**
   → 결과가 없을 수 있다는 사실을 반환 타입으로 명시해 호출자가 빈 경우를 처리하도록 강제하고, NullPointerException을 줄이기 위해서입니다.
2. **orElse와 orElseGet의 차이는?**
   → orElse의 인자는 값이 있어도 항상 평가되고, orElseGet의 Supplier는 값이 없을 때만 실행됩니다. 기본값 생성 비용이 크거나 부수 효과가 있으면 orElseGet을 씁니다.
3. **Optional을 필드나 파라미터로 쓰지 않는 이유는?**
   → 반환 타입용으로 설계되어 직렬화되지 않고 JPA 매핑이 안 되며, 파라미터로 쓰면 null·empty·값 세 가지 상태를 처리해야 해서 오히려 복잡해지기 때문입니다.

---

## 핵심 정리
- Optional = "값이 없을 수 있음"을 **반환 타입**으로 표현
- 생성: `of`(null 금지) / `ofNullable` / `empty`
- 꺼내기: `orElseThrow`, `orElse`(항상 평가) vs `orElseGet`(없을 때만), `map·flatMap·filter·ifPresent`
- `isPresent()+get()` 지양, Optional에 null 반환 금지
- 필드·파라미터·컬렉션에는 쓰지 않기
