# 01. 스레드 기초

> **학습 목표**
> - 자바에서 스레드를 만들고 실행하는 방법을 안다.
> - 스레드 상태와 전이를 설명할 수 있다.
> - start와 run의 차이, join, sleep, interrupt를 사용할 수 있다.
> - 데몬 스레드와 스레드 풀이 필요한 이유를 설명할 수 있다.

> OS 관점의 프로세스·스레드는 CS 자료 `03.운영체제/02.프로세스와스레드.md` 참고

---

## 1. 스레드 만들기

```java
// 1) Runnable (권장: 작업과 실행 방식 분리)
Runnable task = () -> System.out.println("작업 실행: " + Thread.currentThread().getName());
Thread t1 = new Thread(task, "worker-1");
t1.start();

// 2) Thread 상속 (비권장: 단일 상속을 써 버림)
class MyThread extends Thread {
    @Override public void run() { System.out.println("run"); }
}
new MyThread().start();

// 3) Java 21+ 빌더
Thread t2 = Thread.ofPlatform().name("worker-2").start(task);
Thread v = Thread.ofVirtual().start(task);          // 가상 스레드

// 4) 실무: 직접 만들지 않고 ExecutorService (→ 03 문서)
```

### start() vs run()
```java
t1.run();     // ❌ 새 스레드 없이 현재 스레드에서 그냥 메서드 호출
t1.start();   // ✅ 새 스레드를 만들고 그 스레드에서 run() 실행
t1.start();   // 두 번 호출하면 IllegalThreadStateException
```

## 2. 스레드 상태

```
          start()
  NEW ──────────────> RUNNABLE ─────────────────────> TERMINATED
                      (실행 중 or 실행 대기)    run() 종료
                       │   ↑
     synchronized 진입 대기 │   │ 락 획득
                       ↓   │
                     BLOCKED
                       │   ↑
  wait(), join(),      ↓   │ notify(), 대상 종료, unpark
  LockSupport.park()  WAITING
                       │   ↑
  sleep(ms), wait(ms) ↓   │ 시간 경과
                   TIMED_WAITING
```
| 상태 | 의미 |
|---|---|
| NEW | 생성됐지만 start 전 |
| **RUNNABLE** | 실행 중이거나 CPU를 기다림 (자바는 둘을 구분하지 않음) |
| **BLOCKED** | **synchronized 모니터 락** 획득 대기 |
| **WAITING** | 다른 스레드의 신호를 무기한 대기 |
| TIMED_WAITING | 시간 제한 대기 |
| TERMINATED | 종료 |

## 3. 주요 메서드

```java
Thread.sleep(1000);          // 현재 스레드를 1초 멈춤 (락은 놓지 않음)
t1.join();                   // t1이 끝날 때까지 현재 스레드 대기
t1.join(3000);               // 최대 3초
Thread.currentThread();      // 현재 스레드
t1.setDaemon(true);          // 데몬 스레드 (start 전에)
Thread.yield();              // 실행 양보 힌트 (거의 안 씀)
```

### interrupt: 스레드를 "정중하게" 멈추기
자바에는 스레드를 강제로 죽이는 안전한 방법이 없습니다(`stop()`은 deprecated·제거). 대신 **중단 요청 플래그**를 보냅니다.
```java
Thread worker = new Thread(() -> {
    while (!Thread.currentThread().isInterrupted()) {      // 플래그 확인
        try {
            doWork();
            Thread.sleep(500);                              // 대기 중 interrupt되면 예외
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();             // ★ 플래그 복원 (예외가 발생하면 플래그가 지워짐)
            break;                                          // 정리 후 종료
        }
    }
    cleanup();
});
worker.start();
worker.interrupt();       // 중단 요청
```
> `catch (InterruptedException e) {}`로 **삼키면** 상위 코드(스레드 풀 종료 등)가 중단 요청을 알 수 없게 됩니다. 처리할 수 없으면 다시 던지거나 `interrupt()`로 복원하세요.

## 4. 데몬 스레드

| 구분 | 사용자 스레드 (기본) | 데몬 스레드 |
|---|---|---|
| JVM 종료 | **모든 사용자 스레드가 끝나야** JVM 종료 | 사용자 스레드가 모두 끝나면 **강제 종료** |
| 용도 | 일반 작업 | GC, 백그라운드 모니터링 |
> 데몬 스레드는 finally가 실행되지 않고 종료될 수 있어, 파일 쓰기 같은 중요한 작업에 쓰면 안 됩니다. 가상 스레드는 항상 데몬입니다.

## 5. 스레드를 직접 만들면 안 되는 이유

```java
// ❌ 요청마다 새 스레드
for (Request r : requests) {
    new Thread(() -> handle(r)).start();
}
```
| 문제 | 설명 |
|---|---|
| 생성 비용 | 플랫폼 스레드 = OS 스레드, 생성·소멸 비용이 큼 |
| 메모리 | 스레드마다 스택(약 1MB) |
| 무제한 생성 | 트래픽 급증 시 `OutOfMemoryError: unable to create native thread` |
| 관리 불가 | 종료, 예외 처리, 결과 수집이 어려움 |

→ **스레드 풀(ExecutorService)** 로 정해진 수의 스레드를 재사용합니다. (I/O 위주의 대량 작업은 가상 스레드)

## 6. 스레드의 예외

스레드 안에서 던진 예외는 **호출한 스레드로 전파되지 않습니다.**
```java
Thread t = new Thread(() -> { throw new RuntimeException("실패"); });
t.setUncaughtExceptionHandler((thread, ex) -> log.error("스레드 {} 실패", thread.getName(), ex));
t.start();
```
> `ExecutorService.submit()`으로 제출한 작업의 예외는 **Future.get()을 호출해야** 드러납니다. get을 안 하면 예외가 조용히 사라집니다.

## 7. 면접 질문

1. **start()와 run()의 차이는?**
   → start는 새 스레드를 생성해 그 스레드에서 run을 실행하고, run을 직접 호출하면 새 스레드 없이 현재 스레드에서 일반 메서드처럼 실행됩니다.
2. **스레드를 안전하게 중지하는 방법은?**
   → interrupt로 중단을 요청하고, 작업 쪽에서 isInterrupted를 확인하거나 InterruptedException을 처리해 정리 후 종료합니다. InterruptedException을 잡으면 플래그를 복원해야 합니다.
3. **BLOCKED와 WAITING의 차이는?**
   → BLOCKED는 synchronized 모니터 락 획득을 기다리는 상태이고, WAITING은 wait·join·park 등으로 다른 스레드의 신호를 기다리는 상태입니다.
4. **스레드를 직접 생성하지 않고 스레드 풀을 쓰는 이유는?**
   → 스레드 생성·소멸 비용과 메모리 사용을 줄이고, 동시에 실행되는 스레드 수를 제한해 자원 고갈을 막으며, 작업 관리가 쉬워지기 때문입니다.

---

## 핵심 정리
- 생성: `Runnable` + `Thread`, Java 21 `Thread.ofPlatform()/ofVirtual()`, 실무는 ExecutorService
- **start**(새 스레드) vs run(그냥 호출)
- 상태: NEW → RUNNABLE ⇄ BLOCKED(synchronized) / WAITING / TIMED_WAITING → TERMINATED
- 중지는 **interrupt** + 플래그 확인, InterruptedException 삼키지 않기
- 직접 생성 대신 스레드 풀, 스레드 예외는 전파되지 않음
