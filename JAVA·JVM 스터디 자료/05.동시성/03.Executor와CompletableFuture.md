# 03. ExecutorService, Future, CompletableFuture

> **학습 목표**
> - ExecutorService로 스레드 풀을 만들고 안전하게 종료할 수 있다.
> - ThreadPoolExecutor의 핵심 파라미터(코어·최대 스레드, 큐, 거부 정책)를 설명할 수 있다.
> - Future의 한계와 CompletableFuture로 비동기 작업을 조합하는 방법을 설명할 수 있다.
> - Spring @Async와 스레드 풀 설정을 할 수 있다.

---

## 1. ExecutorService

```java
ExecutorService pool = Executors.newFixedThreadPool(4);

pool.execute(() -> System.out.println("결과 없는 작업"));          // Runnable
Future<Integer> future = pool.submit(() -> heavyCalc());          // Callable → Future

Integer result = future.get(3, TimeUnit.SECONDS);                // 결과 대기 (블로킹, 타임아웃)

// 여러 작업 한 번에
List<Future<String>> futures = pool.invokeAll(List.of(task1, task2, task3));
String fastest = pool.invokeAny(List.of(task1, task2));            // 가장 먼저 끝난 하나
```

### 안전한 종료
```java
pool.shutdown();                                   // 새 작업 거부, 기존 작업은 마무리
if (!pool.awaitTermination(30, TimeUnit.SECONDS)) {
    pool.shutdownNow();                            // 실행 중인 작업에 interrupt
}

// Java 19+: ExecutorService가 AutoCloseable
try (ExecutorService executor = Executors.newVirtualThreadPerTaskExecutor()) {
    executor.submit(task);
}                                                  // close()가 모든 작업 완료까지 대기
```
> 종료하지 않으면 사용자 스레드가 남아 **JVM이 끝나지 않습니다.** Spring 빈으로 관리하는 풀은 컨테이너가 종료 시 정리합니다.

### Executors 팩토리
| 메서드 | 특징 | 주의 |
|---|---|---|
| `newFixedThreadPool(n)` | 고정 n개 | 큐가 **무제한** → 작업이 쌓이면 메모리 고갈 |
| `newCachedThreadPool()` | 필요하면 무한히 생성, 60초 놀면 제거 | 스레드 **무제한** 생성 위험 |
| `newSingleThreadExecutor()` | 1개, 순서 보장 | |
| `newScheduledThreadPool(n)` | 지연·주기 실행 | |
| `newVirtualThreadPerTaskExecutor()` | 작업마다 가상 스레드 (Java 21+) | I/O 위주 대량 작업 |
| `newWorkStealingPool()` | ForkJoinPool | CPU 작업 분할 |

> 운영 코드에서는 **`ThreadPoolExecutor`를 직접 만들어 큐 크기와 거부 정책을 제한**하는 것이 안전합니다.

## 2. ThreadPoolExecutor 동작

```java
ThreadPoolExecutor executor = new ThreadPoolExecutor(
        10,                                   // corePoolSize
        50,                                   // maximumPoolSize
        60, TimeUnit.SECONDS,                 // 코어 초과 스레드의 유휴 유지 시간
        new ArrayBlockingQueue<>(200),        // 작업 큐 (크기 제한!)
        Thread.ofPlatform().name("order-", 0).factory(),   // 스레드 이름 지정 (디버깅에 중요, Java 21+)
        new ThreadPoolExecutor.CallerRunsPolicy());         // 거부 정책
```
```
작업 제출 시
1. 실행 중 스레드 < core       → 새 스레드 생성해 실행
2. core가 다 바쁨              → 큐에 넣음
3. 큐도 가득 참                → max까지 스레드 추가 생성
4. max도 가득 + 큐 가득         → 거부 정책 실행
```
> **주의**: 큐가 가득 차기 전에는 core 이상으로 스레드가 늘지 않습니다. 무제한 큐(`LinkedBlockingQueue()`)를 쓰면 **maximumPoolSize가 의미 없어집니다.**

| 거부 정책 | 동작 |
|---|---|
| `AbortPolicy` (기본) | `RejectedExecutionException` |
| **`CallerRunsPolicy`** | 제출한 스레드가 직접 실행 → 자연스러운 **역압(backpressure)** |
| `DiscardPolicy` | 조용히 버림 (위험) |
| `DiscardOldestPolicy` | 가장 오래된 작업을 버림 |

### 스레드 수 정하기
| 작업 성격 | 기준 |
|---|---|
| CPU 위주 (계산) | 코어 수 ~ 코어 수 + 1 |
| I/O 위주 (DB, API) | 코어 수 × (1 + 대기 시간 / 처리 시간) → 더 많이, 또는 **가상 스레드** |
> 실제 값은 **부하 테스트**로 정합니다. 외부 시스템(DB 커넥션 풀 크기)보다 많이 늘리면 결국 거기서 대기합니다.

## 3. Future의 한계

```java
Future<Member> f1 = pool.submit(() -> memberApi.get(id));
Future<List<Order>> f2 = pool.submit(() -> orderApi.list(id));
Member m = f1.get();               // 블로킹
List<Order> orders = f2.get();     // 블로킹
```
- `get()`은 **블로킹** → 결과를 기다리는 동안 스레드가 묶임
- 완료 시 콜백, 작업 연결(A 끝나면 B), 여러 작업 조합, 예외 처리를 깔끔하게 할 수 없음

## 4. CompletableFuture (Java 8+)

**비동기 작업을 파이프라인처럼 연결·조합**합니다.

```java
ExecutorService io = Executors.newFixedThreadPool(20);       // ★ 전용 풀 지정 권장

CompletableFuture<Member> memberF = CompletableFuture.supplyAsync(() -> memberApi.get(id), io);
CompletableFuture<List<Order>> ordersF = CompletableFuture.supplyAsync(() -> orderApi.list(id), io);

// 두 결과 합치기 (동시에 실행 → 전체 시간 = 더 느린 쪽)
CompletableFuture<MyPage> pageF = memberF.thenCombine(ordersF, MyPage::new);

MyPage page = pageF
        .orTimeout(2, TimeUnit.SECONDS)                       // Java 9+ 타임아웃
        .exceptionally(ex -> MyPage.empty())                  // 실패 시 대체 값
        .join();                                              // 결과 (Checked 예외 없음)
```

### 주요 메서드
| 메서드 | 용도 | 비유 (Stream) |
|---|---|---|
| `supplyAsync(supplier, executor)` | 결과 있는 비동기 시작 | |
| `runAsync(runnable, executor)` | 결과 없는 비동기 시작 | |
| **`thenApply(fn)`** | 결과 변환 | map |
| **`thenCompose(fn)`** | 결과로 **다음 비동기 작업** 시작 (중첩 방지) | flatMap |
| **`thenCombine(other, fn)`** | 두 작업 결과 합치기 | zip |
| `thenAccept(consumer)` | 결과 소비 | forEach |
| `allOf(...)` / `anyOf(...)` | 모두 완료 / 하나라도 완료 | |
| **`exceptionally(fn)`** | 예외 시 대체 값 | |
| `handle((result, ex) -> ...)` | 성공·실패 모두 처리 | |
| `whenComplete` | 완료 시 부수 작업 (로그) | peek |
| `orTimeout` / `completeOnTimeout(v, ...)` | 타임아웃 예외 / 기본값 | |
| `join()` / `get()` | 결과 대기 (unchecked / checked 예외) | |

```java
// 순차 의존: 회원 조회 → 그 회원의 등급으로 쿠폰 조회
CompletableFuture<List<Coupon>> coupons = CompletableFuture
        .supplyAsync(() -> memberApi.get(id), io)
        .thenCompose(member -> CompletableFuture.supplyAsync(() -> couponApi.list(member.grade()), io));

// N개 동시 호출 후 모두 모으기
List<CompletableFuture<Price>> futures = productIds.stream()
        .map(pid -> CompletableFuture.supplyAsync(() -> priceApi.get(pid), io))
        .toList();
List<Price> prices = CompletableFuture.allOf(futures.toArray(CompletableFuture[]::new))
        .thenApply(v -> futures.stream().map(CompletableFuture::join).toList())
        .join();
```

### 주의
| 주의 | 설명 |
|---|---|
| **Executor를 지정하지 않으면 공용 ForkJoinPool** | 코어 수 - 1개 스레드를 애플리케이션 전체가 공유 → I/O 작업으로 막히면 다른 곳까지 느려짐 |
| 예외는 `CompletionException`으로 감싸짐 | `ex.getCause()`로 원인 확인 |
| ThreadLocal·SecurityContext·MDC 전파 X | 다른 스레드라서 → 값을 인자로 넘기거나 컨텍스트 전파 래퍼 사용 |
| 트랜잭션 전파 X | 비동기 스레드는 호출한 쪽 트랜잭션과 별개 |

## 5. Spring @Async

```java
@Configuration
@EnableAsync
public class AsyncConfig {
    @Bean(name = "mailExecutor")
    public ThreadPoolTaskExecutor mailExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(5);
        executor.setMaxPoolSize(20);
        executor.setQueueCapacity(500);
        executor.setThreadNamePrefix("mail-");
        executor.setRejectedExecutionHandler(new ThreadPoolExecutor.CallerRunsPolicy());
        executor.setWaitForTasksToCompleteOnShutdown(true);
        executor.setAwaitTerminationSeconds(30);
        executor.initialize();
        return executor;
    }
}

@Service
public class MailService {
    @Async("mailExecutor")
    public CompletableFuture<Void> sendWelcome(String email) {
        mailClient.send(email);
        return CompletableFuture.completedFuture(null);
    }
}
```
| 주의 | |
|---|---|
| **프록시 기반** | 같은 클래스 내부 호출은 비동기로 실행되지 않음 |
| `void` 메서드의 예외 | 호출자에게 전달 안 됨 → `AsyncUncaughtExceptionHandler` 설정 |
| 기본 실행기 | Spring Boot는 `ThreadPoolTaskExecutor`를 자동 구성 (`spring.task.execution.*`), 가상 스레드 활성화 시 가상 스레드 실행기 |
| 트랜잭션 커밋 후 실행 | 메일·알림은 `@TransactionalEventListener(phase = AFTER_COMMIT)` + `@Async` 조합 |

## 6. 면접 질문

1. **스레드 풀의 동작 방식은?**
   → 코어 스레드 수까지는 새 스레드로 실행하고, 그 이상은 큐에 쌓으며, 큐가 가득 차면 최대 스레드 수까지 늘리고, 그것도 차면 거부 정책을 적용합니다.
2. **Executors.newFixedThreadPool을 운영에서 조심해야 하는 이유는?**
   → 내부 큐가 무제한이라 처리 속도보다 작업이 빨리 들어오면 큐가 계속 쌓여 메모리가 고갈될 수 있기 때문에, 큐 크기와 거부 정책을 지정한 ThreadPoolExecutor를 씁니다.
3. **Future와 CompletableFuture의 차이는?**
   → Future는 get으로 블로킹 대기만 할 수 있고, CompletableFuture는 thenApply·thenCompose·thenCombine으로 비동기 작업을 연결·조합하고 exceptionally로 예외를 처리할 수 있습니다.
4. **CompletableFuture에 Executor를 지정해야 하는 이유는?**
   → 지정하지 않으면 공용 ForkJoinPool을 사용해 I/O 작업이 애플리케이션 전체의 공용 스레드를 점유하기 때문입니다.

---

## 핵심 정리
- ExecutorService: submit → Future, **shutdown → awaitTermination → shutdownNow**, Java 19+ try-with-resources
- ThreadPoolExecutor: core → 큐 → max → 거부 정책, **무제한 큐 금지**, CallerRunsPolicy로 역압
- CompletableFuture: `supplyAsync(…, executor)` → thenApply / **thenCompose** / **thenCombine** / allOf → exceptionally / orTimeout → join
- 공용 ForkJoinPool 주의, 컨텍스트·트랜잭션 전파 X
- @Async: 전용 풀, 프록시(내부 호출 X), void 예외 핸들러
