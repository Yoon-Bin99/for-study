# 07. 설정과 프로필

> **학습 목표**
> - `application.yml`과 외부 설정의 우선순위를 이해한다.
> - `@ConfigurationProperties`로 설정을 타입 안전하게 바인딩할 수 있다.
> - 프로필로 환경(local, dev, prod)별 설정을 분리할 수 있다.
> - 비밀 정보(DB 비밀번호, API 키)를 안전하게 관리하는 방법을 안다.

---

## 1. 외부 설정이 필요한 이유

같은 jar 파일을 **로컬, 개발, 운영 환경**에서 그대로 실행하되 DB 주소·비밀번호·로그 레벨만 다르게 하고 싶습니다.
> "빌드는 한 번, 설정은 환경마다" (12-Factor App의 Config 원칙)

---

## 2. application.yml

```yaml
spring:
  application:
    name: order-service
  datasource:
    url: jdbc:mysql://localhost:3306/shop
    username: shop
    password: ${DB_PASSWORD}          # 환경 변수에서 주입
  jpa:
    open-in-view: false
    properties:
      hibernate:
        default_batch_fetch_size: 100

server:
  port: 8080

payment:
  base-url: https://api.payment.com
  timeout: 3s
  retry-count: 2
```

### 설정 우선순위 (높은 것이 이김, 주요 항목만)
```
1. 커맨드라인 인자          java -jar app.jar --server.port=9090
2. 환경 변수                SERVER_PORT=9090, SPRING_DATASOURCE_PASSWORD=...
3. jar 밖의 application-{profile}.yml
4. jar 밖의 application.yml
5. jar 안의 application-{profile}.yml
6. jar 안의 application.yml
```
> 환경 변수는 **완화된 바인딩(relaxed binding)** 으로 매핑됩니다: `spring.datasource.password` ↔ `SPRING_DATASOURCE_PASSWORD` (점 → 밑줄, 대문자). 컨테이너·쿠버네티스에서 많이 씁니다.

## 3. 설정 값 읽기

### `@Value` (간단한 값 하나)
```java
@Value("${payment.base-url}")
private String baseUrl;
```

### `@ConfigurationProperties` (권장: 묶음, 타입 안전)
```java
@Validated
@ConfigurationProperties(prefix = "payment")
public record PaymentProperties(
        @NotBlank String baseUrl,
        Duration timeout,            // "3s", "500ms" 자동 변환
        @Min(0) int retryCount        // retry-count ↔ retryCount 자동 매핑
) { }
```
```java
@SpringBootApplication
@ConfigurationPropertiesScan          // @ConfigurationProperties 클래스 스캔
public class Application { ... }

@Component
@RequiredArgsConstructor
public class PaymentClient {
    private final PaymentProperties properties;    // 일반 빈처럼 주입
}
```
| 비교 | `@Value` | `@ConfigurationProperties` |
|---|---|---|
| 묶음 바인딩 | ✗ | ✅ |
| 타입 변환 (Duration, List, 중첩 객체) | 제한적 | ✅ |
| 검증 (`@Validated`) | ✗ | ✅ 시작 시 실패 → 잘못된 설정으로 뜨지 않음 |
| IDE 자동 완성 | ✗ | ✅ (`spring-boot-configuration-processor`) |

## 4. 프로필

```
src/main/resources/
 ├── application.yml          공통
 ├── application-local.yml    로컬 (H2 또는 Docker MySQL, show-sql)
 ├── application-dev.yml      개발 서버
 └── application-prod.yml     운영 (로그 레벨 WARN, 커넥션 풀 크게)
```
```bash
java -jar app.jar --spring.profiles.active=prod
SPRING_PROFILES_ACTIVE=prod java -jar app.jar
```
```yaml
# application-local.yml
spring:
  jpa:
    show-sql: true
    hibernate:
      ddl-auto: create        # 로컬에서만! 운영에서는 validate 또는 none
logging:
  level:
    org.hibernate.SQL: debug
```

### 한 파일에 여러 프로필
```yaml
spring:
  application:
    name: order-service
---
spring:
  config:
    activate:
      on-profile: prod
logging:
  level:
    root: warn
```

### 프로필별 빈
```java
@Bean
@Profile("local")
public PaymentClient fakePaymentClient() { return new FakePaymentClient(); }

@Bean
@Profile("!local")
public PaymentClient realPaymentClient(PaymentProperties props) { return new TossPaymentClient(props); }
```

### `ddl-auto` 옵션
| 값 | 동작 | 사용 환경 |
|---|---|---|
| create / create-drop | 테이블 삭제 후 생성 | 로컬·테스트 |
| update | 변경 사항 반영 (삭제는 안 함) | 로컬 정도 (운영 ❌) |
| **validate** | 엔티티와 테이블이 맞는지 검사만 | 운영 |
| **none** | 아무것도 안 함 | 운영 (스키마는 **Flyway/Liquibase** 로 관리) |

## 5. 비밀 정보 관리

| 방법 | 설명 |
|---|---|
| ❌ yml에 평문 비밀번호 커밋 | Git 기록에 영원히 남음 |
| ✅ 환경 변수 `${DB_PASSWORD}` | 기본, 배포 도구에서 주입 |
| ✅ Kubernetes Secret → 환경 변수/파일 | `spring.config.import: optional:configtree:/etc/secrets/` |
| ✅ 외부 비밀 저장소 | AWS Secrets Manager·Parameter Store, Vault (`spring.config.import`로 연동) |
| `.gitignore`에 `application-local.yml` | 로컬 비밀 파일 커밋 방지 |

```yaml
spring:
  config:
    import: optional:file:.env[.properties]   # 로컬에서 .env 파일 읽기 (gitignore 필수)
```
> 인프라 관점(Secrets Manager, Vault, K8s Secret)은 `인프라 스터디 자료`, 암호화 키 관리는 `인증·인가 스터디 자료`의 암호화 문서 참고.

## 6. 면접 질문

1. **환경별 설정은 어떻게 분리하나요?**
   → application-{profile}.yml로 프로필별 파일을 두고 spring.profiles.active로 활성화합니다. 같은 jar를 쓰고 DB 주소나 비밀번호는 환경 변수로 주입합니다.
2. **`@Value`와 `@ConfigurationProperties`의 차이는?**
   → @Value는 단일 값을 주입하고, @ConfigurationProperties는 prefix 아래 설정을 객체로 묶어 타입 변환과 검증을 지원하므로 관련 설정이 여러 개면 후자를 권장합니다.
3. **운영 환경에서 `ddl-auto`는?**
   → validate나 none을 사용하고 스키마 변경은 Flyway 같은 마이그레이션 도구로 버전 관리합니다. update나 create는 데이터 손실과 예측 불가능한 변경 위험이 있습니다.
4. **DB 비밀번호는 어디에 두나요?**
   → 코드나 yml에 커밋하지 않고 환경 변수, 쿠버네티스 Secret, AWS Secrets Manager 같은 외부 저장소에서 주입합니다.

---

## 핵심 정리
- 우선순위: **커맨드라인 > 환경 변수 > 외부 파일 > 내부 파일**
- 묶음 설정은 **`@ConfigurationProperties` + record + `@Validated`**
- 프로필: `application-{profile}.yml`, `spring.profiles.active`, `@Profile`
- 운영 `ddl-auto: validate/none` + Flyway, 비밀은 **환경 변수·Secret 저장소**
