# 01. JPA와 ORM 개요

> **학습 목표**
> - 객체와 관계형 DB 사이의 패러다임 불일치를 설명할 수 있다.
> - ORM, JPA, Hibernate, Spring Data JPA의 관계를 구분할 수 있다.
> - JPA를 쓸 때와 SQL 매퍼(MyBatis, jOOQ)를 쓸 때를 비교할 수 있다.
> - JPA 개발에 필요한 기본 설정을 안다.

---

## 1. SQL 중심 개발의 문제

```java
// 회원에 필드 하나(tel)를 추가하면?
String sql = "INSERT INTO member(id, name, tel) VALUES (?, ?, ?)";   // INSERT 수정
String sql = "SELECT id, name, tel FROM member WHERE id = ?";        // SELECT 수정
member.setTel(rs.getString("tel"));                                   // 매핑 코드 수정
String sql = "UPDATE member SET name = ?, tel = ? WHERE id = ?";     // UPDATE 수정
```
- 반복적인 CRUD SQL과 매핑 코드
- 비즈니스 로직보다 **SQL 작성과 매핑**에 시간이 쏠림

## 2. 패러다임 불일치

객체는 **참조·상속·캡슐화**, 관계형 DB는 **테이블·외래 키·조인**으로 데이터를 표현합니다.

| 차이 | 객체 | 관계형 DB |
|---|---|---|
| 상속 | `class Album extends Item` | 상속 개념 없음 → 슈퍼타입·서브타입 테이블 + 조인 |
| 연관 관계 | **참조** `member.getTeam()` (단방향) | **외래 키** + 조인 (양방향) |
| 객체 그래프 탐색 | `order.getMember().getTeam().getName()` 자유롭게 | 처음 실행한 SQL 범위까지만 |
| 동일성 | 같은 객체면 `==` true | 두 번 조회하면 `new` 두 번 → `==` false |

```java
Member m1 = memberDao.find(1L);
Member m2 = memberDao.find(1L);
m1 == m2;    // JDBC 직접: false (다른 인스턴스)
             // JPA: true (같은 트랜잭션 안에서 동일성 보장, → 02.영속성컨텍스트.md)
```

## 3. ORM, JPA, Hibernate, Spring Data JPA

```
 ┌─────────────────────────────────────────────┐
 │ Spring Data JPA                            │  Repository 인터페이스만 만들면
 │  (JpaRepository, 쿼리 메서드)               │  구현체를 자동 생성
 └─────────────────────┬───────────────────────┘
                       │ 내부에서 EntityManager 사용
 ┌─────────────────────▼───────────────────────┐
 │ JPA (Jakarta Persistence) = 표준 명세 (인터페이스) │  EntityManager, @Entity, JPQL
 └─────────────────────┬───────────────────────┘
                       │ 구현
 ┌─────────────────────▼───────────────────────┐
 │ Hibernate (구현체, 사실상 표준)               │  SQL 생성, 캐시, 지연 로딩
 └─────────────────────┬───────────────────────┘
                       │ JDBC
                    [ DB ]
```
| 용어 | 설명 |
|---|---|
| **ORM** | Object-Relational Mapping. 객체와 테이블을 매핑해 SQL을 자동 생성 |
| **JPA** | 자바 ORM **표준 명세**. 현재 이름은 Jakarta Persistence (3.1: Boot 3, **3.2: Boot 4**) |
| **Hibernate** | JPA 구현체. Boot 3은 6.x, **Boot 4는 7.x** |
| **Spring Data JPA** | JPA를 더 쉽게 쓰게 해 주는 스프링 모듈 (`→ 03.JPA실전/02.SpringDataJPA.md`) |

> JPA가 SQL을 몰라도 되게 해 주는 것은 **아닙니다.** 생성되는 SQL을 이해하고 확인할 수 있어야 N+1 같은 성능 문제를 해결할 수 있습니다.

## 4. JPA를 쓰면 좋은 점

| 장점 | 설명 |
|---|---|
| 생산성 | `save(member)`, `findById(id)` — CRUD SQL 작성 불필요 |
| 유지보수 | 필드 추가 시 엔티티만 수정 |
| 객체 지향 설계 | 연관 관계를 참조로, 비즈니스 로직을 엔티티 안에 |
| 변경 감지 | 엔티티 값만 바꾸면 UPDATE 자동 (`→ 02.영속성컨텍스트.md`) |
| 성능 기능 | 1차 캐시, 쓰기 지연·배치, 지연 로딩 |
| DB 독립성 | 방언(Dialect)이 DB별 SQL 차이 처리 (페이징 문법 등) |

## 5. JPA vs SQL 매퍼

| 비교 | JPA (Hibernate) | MyBatis | jOOQ |
|---|---|---|---|
| 방식 | 객체 중심, SQL 자동 생성 | **SQL 직접 작성** (XML/애노테이션) | 타입 안전한 **SQL DSL** |
| CRUD 생산성 | 높음 | 낮음 | 중간 |
| 복잡한 통계·리포트 쿼리 | 어려움 → QueryDSL·네이티브 쿼리 | **쉬움** | **쉬움** |
| 학습 곡선 | **높음** (영속성 컨텍스트, 지연 로딩) | 낮음 | 중간 |
| 국내 실무 | 신규 서비스 다수가 JPA | 레거시·금융권에 많음 | 일부 |

> 실무에서는 **JPA + QueryDSL**을 기본으로 하고, 복잡한 조회는 네이티브 쿼리·MyBatis·jOOQ를 섞어 쓰는 경우가 많습니다. (`→ 03.JPA실전/03.QueryDSL과동적쿼리.md`)

## 6. 기본 설정 (Spring Boot)

```groovy
dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-data-jpa'
    runtimeOnly 'com.mysql:mysql-connector-j'
}
```
```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/shop
    username: shop
    password: ${DB_PASSWORD}
    hikari:
      maximum-pool-size: 20
  jpa:
    open-in-view: false            # OSIV 끄기 (→ 03.JPA실전/04.성능최적화.md)
    hibernate:
      ddl-auto: validate
    properties:
      hibernate:
        format_sql: true
        default_batch_fetch_size: 100
logging:
  level:
    org.hibernate.SQL: debug                     # 실행 SQL 로그
    org.hibernate.orm.jdbc.bind: trace           # 바인딩 파라미터 (Hibernate 6+)
```
> `show-sql: true`는 System.out으로 출력되므로 로거(`org.hibernate.SQL`) 사용을 권장합니다. 파라미터까지 보기 좋게 보려면 p6spy 같은 라이브러리를 씁니다(로컬에서만).

## 7. 면접 질문

1. **JPA란? Hibernate와의 관계는?**
   → JPA는 자바 ORM 표준 명세(인터페이스)이고, Hibernate는 그 구현체입니다. Spring Data JPA는 JPA 위에서 Repository 구현을 자동으로 만들어 주는 스프링 모듈입니다.
2. **패러다임 불일치란?**
   → 객체는 상속·참조·그래프 탐색으로, 관계형 DB는 테이블·외래 키·조인으로 데이터를 표현하기 때문에 생기는 차이로, ORM이 이 간극을 매핑으로 해결합니다.
3. **JPA와 MyBatis 중 무엇을 선택하나요?**
   → 도메인 중심 CRUD가 많으면 생산성과 유지보수가 좋은 JPA를, 복잡한 통계 쿼리가 많거나 SQL을 세밀하게 제어해야 하면 MyBatis나 jOOQ를 고려하며, 실무에선 혼용하기도 합니다.

---

## 핵심 정리
- 패러다임 불일치(상속·연관·탐색·동일성)를 **ORM**이 해결
- **JPA = 명세**, Hibernate = 구현, Spring Data JPA = 편의 계층
- Boot 4: Jakarta Persistence 3.2 + Hibernate 7
- JPA를 써도 **실행 SQL을 반드시 확인**
