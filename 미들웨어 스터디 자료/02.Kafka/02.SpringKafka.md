# 02. Spring Kafka

> **학습 목표**
> - Spring Boot에서 프로듀서·컨슈머를 설정하고 `KafkaTemplate`, `@KafkaListener`를 사용할 수 있다.
> - JSON 메시지 직렬화와 타입 매핑을 설정할 수 있다.
> - 오프셋 커밋(AckMode)과 동시성(concurrency)을 이해한다.
> - 에러 처리(재시도, DLT)를 구성할 수 있다.

---

## 1. 의존성과 설정

```groovy
implementation 'org.springframework.boot:spring-boot-starter-kafka'   // Boot 4 (Boot 3: org.springframework.kafka:spring-kafka)
testImplementation 'org.springframework.kafka:spring-kafka-test'
```
```yaml
spring:
  kafka:
    bootstrap-servers: localhost:9092
    producer:
      key-serializer: org.apache.kafka.common.serialization.StringSerializer
      acks: all
      properties:
        enable.idempotence: true
        linger.ms: 10
        compression.type: lz4
    consumer:
      group-id: payment-service
      auto-offset-reset: earliest       # 커밋된 오프셋이 없을 때 처음부터
      enable-auto-commit: false         # 스프링이 커밋 관리
      key-deserializer: org.apache.kafka.common.serialization.StringDeserializer
      max-poll-records: 100
    listener:
      ack-mode: record                  # 레코드 처리 후 커밋 (기본 BATCH)
      concurrency: 3                    # 리스너 스레드 수 (≤ 파티션 수)
```
> JSON 직렬화 클래스는 버전에 따라 다릅니다. Spring Kafka 3.x: `JsonSerializer`/`JsonDeserializer` (Jackson 2), **Spring Kafka 4.x (Boot 4): `JacksonJsonSerializer`/`JacksonJsonDeserializer` (Jackson 3)**, 예전 클래스는 deprecated. 아래 설정은 이 이름만 바꾸면 같습니다.

```yaml
spring:
  kafka:
    producer:
      value-serializer: org.springframework.kafka.support.serializer.JacksonJsonSerializer
    consumer:
      value-deserializer: org.springframework.kafka.support.serializer.ErrorHandlingDeserializer
      properties:
        spring.deserializer.value.delegate.class: org.springframework.kafka.support.serializer.JacksonJsonDeserializer
        spring.json.trusted.packages: "com.shop.event"
        spring.json.use.type.headers: false
        spring.json.value.default.type: com.shop.event.OrderCreatedEvent
```
- **`ErrorHandlingDeserializer`**: 역직렬화 실패한 메시지(Poison Pill)가 **무한 재시도 루프**에 빠지지 않고 에러 핸들러로 가게 함
- 서비스 간에는 생산자의 클래스 이름(타입 헤더)에 의존하지 않도록 **타입 헤더를 끄고 소비자 측 타입**을 지정하는 편이 안전

## 2. 프로듀서

```java
public record OrderCreatedEvent(String eventId, Long orderId, Long memberId,
                                long totalPrice, Instant occurredAt) { }
```
```java
@Slf4j
@Component
@RequiredArgsConstructor
public class OrderEventPublisher {

    private static final String TOPIC = "order-created";
    private final KafkaTemplate<String, OrderCreatedEvent> kafkaTemplate;

    public void publish(OrderCreatedEvent event) {
        kafkaTemplate.send(TOPIC, String.valueOf(event.orderId()), event)    // 키 = 주문 ID (순서 보장)
                .whenComplete((result, ex) -> {
                    if (ex != null) {
                        log.error("발행 실패 orderId={}", event.orderId(), ex);   // 재시도·Outbox로 보완
                    } else {
                        RecordMetadata m = result.getRecordMetadata();
                        log.debug("발행 완료 partition={} offset={}", m.partition(), m.offset());
                    }
                });
    }
}
```
- `send()`는 **비동기** (`CompletableFuture` 반환, Spring Kafka 3.0+)
- 반드시 결과(실패)를 처리하세요. 실패를 무시하면 이벤트가 조용히 사라집니다
- DB 저장과 발행의 원자성은 **Outbox 패턴** (`→ 03.전달보장과순서.md`)

### 토픽 생성 (애플리케이션에서)
```java
@Bean
public NewTopic orderCreatedTopic() {
    return TopicBuilder.name("order-created").partitions(6).replicas(3)
            .config(TopicConfig.MIN_IN_SYNC_REPLICAS_CONFIG, "2")
            .build();
}
```
> 운영에서는 토픽을 IaC·관리 도구로 관리하고 브로커의 `auto.create.topics.enable=false`로 두는 경우가 많습니다.

## 3. 컨슈머

```java
@Slf4j
@Component
@RequiredArgsConstructor
public class PaymentEventListener {

    private final PaymentService paymentService;

    @KafkaListener(topics = "order-created", groupId = "payment-service")
    public void onOrderCreated(OrderCreatedEvent event,
                               @Header(KafkaHeaders.RECEIVED_PARTITION) int partition,
                               @Header(KafkaHeaders.OFFSET) long offset) {
        log.info("주문 이벤트 수신 orderId={} partition={} offset={}", event.orderId(), partition, offset);
        paymentService.requestPayment(event);     // ★ 멱등하게 구현 (→ 03.전달보장과순서.md)
    }
}
```
### 수동 커밋
```java
@KafkaListener(topics = "order-created", groupId = "payment-service",
               properties = "enable.auto.commit=false")
public void listen(OrderCreatedEvent event, Acknowledgment ack) {   // ack-mode: manual
    paymentService.requestPayment(event);
    ack.acknowledge();                                              // 처리 완료 후 커밋
}
```
| AckMode | 커밋 시점 |
|---|---|
| `BATCH` (기본) | poll로 가져온 묶음을 모두 처리한 후 |
| `RECORD` | 레코드 하나 처리 후 |
| `MANUAL` / `MANUAL_IMMEDIATE` | `ack.acknowledge()` 호출 시 |

### 동시성
```
파티션 6개, 서버 2대, concurrency=3 → 서버당 리스너 스레드 3개 × 2 = 6 → 파티션당 하나 (최적)
concurrency를 파티션 수보다 크게 → 남는 스레드는 놀게 됨
```

### 배치 리스너
```java
@KafkaListener(topics = "product-viewed", batch = "true")
public void onBatch(List<ProductViewedEvent> events) {
    viewCountService.bulkIncrease(events);          // 대량 처리·DB 배치 저장에 유리
}
```

## 4. 에러 처리: 재시도와 DLT

### DefaultErrorHandler + Dead Letter Topic
```java
@Bean
public DefaultErrorHandler errorHandler(KafkaTemplate<Object, Object> template) {
    DeadLetterPublishingRecoverer recoverer = new DeadLetterPublishingRecoverer(template);
    // 실패한 메시지를 "{원래토픽}.DLT" 토픽으로 (DeadLetterPublishingRecoverer 기본 규칙)

    ExponentialBackOffWithMaxRetries backOff = new ExponentialBackOffWithMaxRetries(3);
    backOff.setInitialInterval(1_000);
    backOff.setMultiplier(2.0);                       // 1초, 2초, 4초

    DefaultErrorHandler handler = new DefaultErrorHandler(recoverer, backOff);
    handler.addNotRetryableExceptions(                // 재시도해도 소용없는 예외는 바로 DLT
            IllegalArgumentException.class, DeserializationException.class);
    return handler;
}
```
Boot는 `CommonErrorHandler` 빈을 리스너 컨테이너에 자동 적용합니다.
```
메시지 처리 실패
 → 같은 스레드에서 1s, 2s, 4s 후 재시도 (그동안 같은 파티션의 다음 메시지는 대기 = 순서 유지)
 → 그래도 실패 → DLT로 발행 후 오프셋 커밋 → 다음 메시지 진행
 → DLT는 모니터링·알림 후 수동 확인 / 재처리
```

### 논블로킹 재시도: `@RetryableTopic`
```java
// Spring Kafka 4 (Boot 4): Spring Retry 의존성이 빠지고 @BackOff로 변경
@RetryableTopic(attempts = "4", backOff = @BackOff(delayString = "1s", multiplier = 2),
                exclude = IllegalArgumentException.class)
// Spring Kafka 3.x: backoff = @Backoff(delay = 1000, multiplier = 2.0)
@KafkaListener(topics = "order-created", groupId = "payment-service")
public void listen(OrderCreatedEvent event) { ... }

@DltHandler
public void handleDlt(OrderCreatedEvent event) {
    log.error("최종 실패 orderId={}", event.orderId());
}
```
- 실패 메시지를 **재시도 토픽**(`-retry-0`, `-retry-1`...)으로 옮겨 나중에 처리, 최종 실패는 `-dlt` 토픽 → **원래 파티션은 막히지 않음**
- 대신 **순서가 깨짐** → 순서가 중요한 이벤트에는 블로킹 재시도(DefaultErrorHandler)

| | 블로킹 재시도 (DefaultErrorHandler) | 논블로킹 (`@RetryableTopic`) |
|---|---|---|
| 순서 | 유지 | **깨짐** |
| 장애 시 처리량 | 해당 파티션 정체 | 영향 적음 |
| 적합 | 순서 중요, 짧은 일시 장애 | 외부 API 장애처럼 오래 걸리는 실패 |

## 5. 테스트

```java
@SpringBootTest
@Import(TestcontainersConfig.class)       // KafkaContainer + @ServiceConnection
class OrderEventIntegrationTest {

    @Autowired OrderEventPublisher publisher;
    @MockitoSpyBean PaymentService paymentService;

    @Test
    void 주문_이벤트를_발행하면_결제_서비스가_소비한다() {
        publisher.publish(new OrderCreatedEvent(UUID.randomUUID().toString(), 1L, 10L, 20_000L, Instant.now()));

        await().atMost(Duration.ofSeconds(10))
               .untilAsserted(() -> verify(paymentService).requestPayment(any()));

}
```

## 6. 면접 질문

1. **`@KafkaListener`의 오프셋 커밋은 언제 일어나나요?**
   → 기본 BATCH 모드에서는 poll로 가져온 레코드를 모두 처리한 후 커밋하고, RECORD는 레코드마다, MANUAL은 Acknowledgment를 호출할 때 커밋합니다. 처리 후 커밋하므로 장애 시 중복 소비가 생길 수 있어 멱등 처리가 필요합니다.
2. **컨슈머에서 처리에 실패한 메시지는 어떻게 하나요?**
   → DefaultErrorHandler로 백오프 재시도 후 실패하면 DeadLetterPublishingRecoverer로 DLT에 보내고, 재시도해도 소용없는 예외는 바로 DLT로 보냅니다. 순서가 중요하지 않으면 RetryableTopic으로 논블로킹 재시도를 합니다.
3. **역직렬화 실패 메시지는 어떻게 처리하나요?**
   → ErrorHandlingDeserializer로 감싸 무한 재시도 루프를 막고 에러 핸들러를 통해 DLT로 보냅니다.

## 핵심 정리
- `KafkaTemplate.send(topic, key, value)` — **비동기, 실패 처리 필수**, 키로 순서
- `@KafkaListener` + **수동/레코드 커밋**, `concurrency ≤ 파티션 수`
- JSON: Boot 4는 **`JacksonJson(De)Serializer`**, 역직렬화는 **`ErrorHandlingDeserializer`**로 감싸기
- 에러: **DefaultErrorHandler(백오프) + DLT**, 순서 무관하면 `@RetryableTopic`
- 테스트: Testcontainers Kafka + Awaitility
