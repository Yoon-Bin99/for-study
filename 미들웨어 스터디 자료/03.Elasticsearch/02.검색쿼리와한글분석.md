# 02. 검색 쿼리와 한글 분석

> **학습 목표**
> - `match`, `term`, `bool`, `range` 등 Query DSL을 사용해 검색 조건을 작성할 수 있다.
> - Query context(점수)와 Filter context(필터)의 차이를 이해한다.
> - 집계(Aggregation)와 페이징(search_after)을 사용할 수 있다.
> - Nori 형태소 분석기, 동의어, 자동 완성을 설정할 수 있다.

---

## 1. 기본 쿼리

### match: 전문 검색 (text 필드)
```http
GET /products/_search
{
  "query": {
    "match": {
      "name": { "query": "무선 키보드", "operator": "and" }
    }
  }
}
```
- 검색어도 같은 분석기로 토큰화 → `[무선, 키보드]`
- `operator: or`(기본) 하나라도 포함, `and` 모두 포함
- `fuzziness: "AUTO"` → 오타 허용 (영문에 효과적)

### term: 정확히 일치 (keyword·숫자 필드)
```json
{ "query": { "term": { "brand": "logi" } } }
```
```json
{ "query": { "terms": { "category": ["keyboard", "mouse"] } } }
```
> ⚠️ `term`을 **text 필드**에 쓰면 거의 안 맞습니다. 색인된 값은 분석된 토큰이고 term 검색어는 분석되지 않기 때문입니다.

### range
```json
{ "query": { "range": { "price": { "gte": 30000, "lte": 100000 } } } }
```
```json
{ "query": { "range": { "createdAt": { "gte": "now-7d/d" } } } }
```

### multi_match: 여러 필드
```json
{
  "query": {
    "multi_match": {
      "query": "무선 키보드",
      "fields": ["name^3", "description", "brand^2"]
    }
  }
}
```
`^3` = 가중치 (상품명에서 일치하면 점수 3배)

## 2. bool 쿼리: 조건 조합 ★

```http
GET /products/_search
{
  "query": {
    "bool": {
      "must":     [ { "match": { "name": "무선 키보드" } } ],
      "filter":   [
        { "term":  { "inStock": true } },
        { "terms": { "category": ["keyboard"] } },
        { "range": { "price": { "lte": 100000 } } }
      ],
      "should":   [ { "term": { "brand": { "value": "logi", "boost": 2 } } } ],
      "must_not": [ { "term": { "status": "DELETED" } } ]
    }
  },
  "sort": [ { "_score": "desc" }, { "createdAt": "desc" } ],
  "from": 0,
  "size": 20
}
```
| 절 | 의미 | 점수 계산 | 캐시 |
|---|---|---|---|
| `must` | 반드시 일치 | ✅ | ✗ |
| **`filter`** | 반드시 일치 | ❌ (예/아니오만) | ✅ **캐시됨 → 빠름** |
| `should` | 일치하면 점수 가산 (must가 없으면 최소 하나 일치) | ✅ | ✗ |
| `must_not` | 일치하면 제외 | ❌ | ✅ |

> **원칙**: "얼마나 잘 맞는가"가 필요한 검색어는 `must`, **예/아니오 조건(카테고리, 가격, 재고, 상태)은 모두 `filter`** 에 둡니다.

## 3. 페이징

| 방식 | 특징 |
|---|---|
| `from` + `size` | 간단, **깊은 페이지는 느림** (from+size ≤ 10,000 기본 제한) |
| **`search_after`** | 마지막 문서의 정렬 값을 커서로 → 무한 스크롤, 깊은 페이징 |
| PIT (Point in Time) + search_after | 일관된 스냅샷으로 대량 순회 |
| scroll | 대량 내보내기용 (실시간 사용자 요청에는 비권장) |

```json
{
  "size": 20,
  "query": { "match": { "name": "키보드" } },
  "sort": [ { "_score": "desc" }, { "productId": "asc" } ],
  "search_after": [12.53, 10452]
}
```
> 정렬 기준에 **고유 값(ID)** 을 마지막에 넣어야 같은 점수의 문서가 누락·중복되지 않습니다.

## 4. 집계 (Aggregation)

검색 결과와 함께 **카테고리별 개수, 가격대 분포** 같은 통계를 계산합니다. (쇼핑몰 왼쪽 필터 목록)
```http
GET /products/_search
{
  "size": 0,
  "query": { "match": { "name": "키보드" } },
  "aggs": {
    "by_brand":   { "terms": { "field": "brand", "size": 10 } },
    "price_ranges": {
      "range": { "field": "price",
                 "ranges": [ { "to": 50000 }, { "from": 50000, "to": 100000 }, { "from": 100000 } ] }
    },
    "avg_price":  { "avg": { "field": "price" } }
  }
}
```
| 종류 | 예 |
|---|---|
| Bucket | `terms`(그룹), `range`, `date_histogram`(일별) |
| Metric | `avg`, `sum`, `min`, `max`, `cardinality`(근사 고유 수) |
> 집계·정렬은 **keyword·숫자·날짜** 필드에 합니다 (doc_values). text 필드는 집계할 수 없습니다.

## 5. 한글 분석: Nori

```
standard 분석기: "삼성전자노트북을" → [삼성전자노트북을]  (한 덩어리 → "노트북"으로 검색 안 됨)
nori 분석기    : "삼성전자노트북을" → [삼성, 전자, 노트북]  (조사 "을" 제거)
```
설치: `bin/elasticsearch-plugin install analysis-nori` (관리형 서비스는 대부분 기본 제공)

```http
PUT /products
{
  "settings": {
    "analysis": {
      "tokenizer": {
        "korean_tokenizer": {
          "type": "nori_tokenizer",
          "decompound_mode": "mixed",
          "user_dictionary_rules": ["무선키보드", "갤럭시북"]
        }
      },
      "filter": {
        "korean_pos": {
          "type": "nori_part_of_speech",
          "stoptags": ["J", "E", "SP", "SC", "SE", "XSV"]
        },
        "synonym_filter": {
          "type": "synonym_graph",
          "synonyms": ["노트북, 랩탑, laptop", "핸드폰, 휴대폰, 스마트폰"]
        }
      },
      "analyzer": {
        "korean_index": {
          "type": "custom",
          "tokenizer": "korean_tokenizer",
          "filter": ["lowercase", "korean_pos", "nori_readingform"]
        },
        "korean_search": {
          "type": "custom",
          "tokenizer": "korean_tokenizer",
          "filter": ["lowercase", "korean_pos", "nori_readingform", "synonym_filter"]
        }
      }
    }
  },
  "mappings": {
    "properties": {
      "name": { "type": "text", "analyzer": "korean_index", "search_analyzer": "korean_search" }
    }
  }
}
```
| 설정 | 의미 |
|---|---|
| `decompound_mode` | 복합어 처리: `none`(그대로), `discard`(분해만), **`mixed`(원형 + 분해 모두)** |
| `user_dictionary_rules` | 사전에 없는 신조어·상품명 등록 |
| `nori_part_of_speech` | 조사(J)·어미(E)·기호 등 품사 제거 |
| `nori_readingform` | 한자 → 한글 |
| **동의어는 검색 분석기에** | 동의어를 바꿔도 재색인 없이 반영 가능 (`synonym_graph`는 검색 시점 사용 권장) |

```http
POST /products/_analyze
{ "analyzer": "korean_index", "text": "삼성전자노트북을 샀어요" }
```
> 분석 결과는 꼭 `_analyze`로 확인하세요. 검색이 안 되는 원인의 대부분은 **색인 토큰과 검색 토큰이 다른 것**입니다.

## 6. 자동 완성

| 방법 | 설명 |
|---|---|
| `edge_ngram` 토크나이저 | "키보드" → [키, 키보, 키보드] 를 색인 → 앞부분 입력으로 매칭 (색인 크기 증가) |
| `search_as_you_type` 필드 타입 | 접두어·n-gram 서브필드를 자동 생성 |
| `completion` suggester | 메모리 기반 FST, 매우 빠름, 필터링 제한적 |
> 한글은 자모 단위 입력("ㅋ", "키ㅂ")까지 지원하려면 **자모 분해** 필드(초성 검색 포함)를 추가로 둡니다.

## 7. 면접 질문

1. **match와 term의 차이는?**
   → match는 검색어를 분석기로 토큰화해 text 필드에서 전문 검색하고, term은 검색어를 분석하지 않고 정확히 일치하는 값을 찾아 keyword나 숫자 필드에 사용합니다.
2. **bool 쿼리에서 must와 filter의 차이는?**
   → 둘 다 반드시 일치해야 하지만 must는 관련도 점수를 계산하고, filter는 점수를 계산하지 않고 결과가 캐시되어 빠르므로 예/아니오 조건은 filter에 둡니다.
3. **한글 검색은 어떻게 처리하나요?**
   → Nori 형태소 분석기로 복합어를 분해하고 조사·어미를 제거하며, 사용자 사전에 신조어를 등록하고, 검색 분석기에 동의어를 적용합니다.
4. **깊은 페이지 조회가 느린 이유와 해결은?**
   → from+size 방식은 각 샤드에서 from+size만큼 문서를 정렬해 모아야 해서 뒤로 갈수록 비용이 커지므로, 마지막 정렬 값을 커서로 쓰는 search_after를 사용합니다.

---

## 핵심 정리
- **match(전문 검색, text)** vs **term(정확 일치, keyword)**
- **bool**: 검색어는 `must`, 조건은 **`filter`(점수 X, 캐시)**, 가산은 `should`
- 페이징은 **search_after** (정렬 마지막에 고유 ID), 집계는 keyword·숫자 필드
- 한글: **Nori** + `mixed` 분해 + 품사 필터 + 사용자 사전 + **검색 시 동의어**
- 안 나오면 **`_analyze`로 토큰 확인**
