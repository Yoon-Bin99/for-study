# 04. 인증·인가 예외 처리

> **학습 목표**
> - ExceptionTranslationFilter가 예외를 401·403으로 바꾸는 과정을 설명할 수 있다.
> - AuthenticationEntryPoint와 AccessDeniedHandler를 구현해 JSON 에러 응답을 만들 수 있다.
> - 필터에서 발생한 예외가 `@RestControllerAdvice`로 잡히지 않는 이유와 해결법을 설명할 수 있다.
> - 로그인 성공·실패 핸들러와 인증 이벤트를 활용할 수 있다.

---

## 1. 예외의 두 종류

| 예외 | 의미 | 기본 응답 | 처리 담당 |
|---|---|---|---|
| **AuthenticationException** | **인증 실패** (로그인 안 됨, 토큰 무효, 비밀번호 틀림) | **401** | **AuthenticationEntryPoint** |
| **AccessDeniedException** | **인가 실패** (권한 없음) | **403** | **AccessDeniedHandler** |

### AuthenticationException 하위 타입
| 예외 | 상황 |
|---|---|
| `BadCredentialsException` | 아이디 또는 비밀번호 틀림 (사용자 없음도 이걸로 감춤) |
| `LockedException` | 계정 잠김 (`isAccountNonLocked() = false`) |
| `DisabledException` | 계정 비활성 |
| `AccountExpiredException`, `CredentialsExpiredException` | 계정·비밀번호 만료 |
| `InsufficientAuthenticationException` | 인증이 필요한 곳에 **익명**으로 접근 |
| `InvalidBearerTokenException` | (Resource Server) 토큰 무효·만료 |

---

## 2. ExceptionTranslationFilter의 동작

```
[ExceptionTranslationFilter]
   try {
       chain.doFilter()  → 뒤의 AuthorizationFilter, 컨트롤러 등
   } catch (AuthenticationException e) {
       → AuthenticationEntryPoint.commence()            → 401
   } catch (AccessDeniedException e) {
       if (현재 사용자가 익명) → AuthenticationEntryPoint   → 401  ("로그인부터 하세요")
       else                 → AccessDeniedHandler.handle() → 403  ("권한이 없어요")
   }
```

> **핵심: ExceptionTranslationFilter는 자기보다 "뒤"에서 발생한 예외만 잡습니다.** 그보다 앞에 있는 커스텀 JWT 필터에서 던진 예외는 잡지 못합니다. (아래 4절)

### 기본 동작
| 설정 | AuthenticationEntryPoint 기본값 |
|---|---|
| `formLogin()` | 로그인 페이지로 **302 리다이렉트** |
| `httpBasic()` | 401 + `WWW-Authenticate: Basic` |
| `oauth2ResourceServer()` | 401 + `WWW-Authenticate: Bearer error="invalid_token"` |
| 아무것도 없음 | 403 (`Http403ForbiddenEntryPoint`) |

→ REST API에서는 **리다이렉트 대신 JSON 401/403**을 주도록 직접 구현합니다.

## 3. JSON 에러 응답 구현

### 공통 에러 응답 형식
```java
public record ErrorResponse(String code, String message) { }
```

### AuthenticationEntryPoint (401)
```java
@Component
@RequiredArgsConstructor
public class JsonAuthenticationEntryPoint implements AuthenticationEntryPoint {
    private final ObjectMapper objectMapper;

    @Override
    public void commence(HttpServletRequest request, HttpServletResponse response,
                         AuthenticationException authException) throws IOException {
        response.setStatus(HttpServletResponse.SC_UNAUTHORIZED);
        response.setContentType(MediaType.APPLICATION_JSON_VALUE);
        response.setCharacterEncoding(StandardCharsets.UTF_8.name());

        // JWT 필터에서 저장해 둔 구체적 원인이 있으면 사용 (만료 / 위조 구분)
        Object code = request.getAttribute("auth.error");
        ErrorResponse body = new ErrorResponse(
                code != null ? code.toString() : "UNAUTHORIZED",
                "인증이 필요합니다.");
        objectMapper.writeValue(response.getWriter(), body);
    }
}
```

### AccessDeniedHandler (403)
```java
@Component
@RequiredArgsConstructor
public class JsonAccessDeniedHandler implements AccessDeniedHandler {
    private final ObjectMapper objectMapper;

    @Override
    public void handle(HttpServletRequest request, HttpServletResponse response,
                       AccessDeniedException accessDeniedException) throws IOException {
        response.setStatus(HttpServletResponse.SC_FORBIDDEN);
        response.setContentType(MediaType.APPLICATION_JSON_VALUE);
        response.setCharacterEncoding(StandardCharsets.UTF_8.name());
        objectMapper.writeValue(response.getWriter(), new ErrorResponse("FORBIDDEN", "접근 권한이 없습니다."));
    }
}
```

### 등록
```java
http.exceptionHandling(ex -> ex
        .authenticationEntryPoint(jsonAuthenticationEntryPoint)
        .accessDeniedHandler(jsonAccessDeniedHandler));
```

> Spring Boot 4(Jackson 3)에서는 `ObjectMapper` 대신 `tools.jackson.databind.json.JsonMapper`를 주입받습니다. Jackson 2를 계속 쓰도록 설정할 수도 있습니다.

## 4. 필터 예외는 @RestControllerAdvice가 못 잡는다

```
[CustomJwtFilter] ← 여기서 예외   ✗ ExceptionTranslationFilter보다 앞
   ↓
[ExceptionTranslationFilter]
   ↓
[DispatcherServlet] ← @RestControllerAdvice는 여기 안쪽(컨트롤러)의 예외만 처리
```

`@RestControllerAdvice`는 **DispatcherServlet 안에서** 발생한 예외만 처리합니다. 필터는 그 바깥이라 잡히지 않고, 결국 서블릿 컨테이너의 기본 에러 처리(`/error`)로 넘어가 의도와 다른 응답이 나갑니다.

### 해결 방법
| 방법 | 설명 |
|---|---|
| **① 필터에서 예외를 던지지 않기** (권장) | 토큰이 무효하면 **인증 정보를 설정하지 않고 그냥 다음 필터로** → 뒤의 AuthorizationFilter가 "익명 사용자"로 판단해 거부 → EntryPoint가 401. 원인은 `request.setAttribute`로 전달 |
| ② 필터에서 직접 응답 작성 | `response.setStatus(401)` + JSON 쓰고 `return` (체인 중단) |
| ③ 예외 처리 전용 필터 | JWT 필터 앞에 try-catch 필터를 두고 JSON 응답 |
| ④ `HandlerExceptionResolver`로 위임 | EntryPoint·필터에서 `resolver.resolveException(...)`을 호출해 `@RestControllerAdvice`로 처리 통일 |

```java
// ① 방식: JWT 필터
try {
    Authentication auth = jwtProvider.getAuthentication(token);
    SecurityContextHolder.getContext().setAuthentication(auth);
} catch (ExpiredJwtException e) {
    request.setAttribute("auth.error", "TOKEN_EXPIRED");      // EntryPoint에서 사용
} catch (JwtException | IllegalArgumentException e) {
    request.setAttribute("auth.error", "INVALID_TOKEN");
}
chain.doFilter(request, response);    // 예외를 던지지 않고 계속 진행
```
> 클라이언트는 `TOKEN_EXPIRED` 코드를 보고 **Refresh Token으로 재발급**을 시도하고, `INVALID_TOKEN`이면 로그아웃시킵니다.

### ④ 방식: @RestControllerAdvice로 통일
```java
@Component
public class DelegatingEntryPoint implements AuthenticationEntryPoint {
    private final HandlerExceptionResolver resolver;

    public DelegatingEntryPoint(@Qualifier("handlerExceptionResolver") HandlerExceptionResolver resolver) {
        this.resolver = resolver;
    }

    @Override
    public void commence(HttpServletRequest req, HttpServletResponse res, AuthenticationException ex) {
        resolver.resolveException(req, res, null, ex);   // → @ExceptionHandler(AuthenticationException.class)
    }
}
```

## 5. 컨트롤러·서비스에서 발생하는 인가 예외

`@PreAuthorize`가 던지는 `AccessDeniedException`은 **컨트롤러 계층**(DispatcherServlet 안)에서 발생합니다. 그래서 `@RestControllerAdvice`가 먼저 잡을 수 있습니다.

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(Exception.class)          // ⚠️ 모든 예외를 잡으면
    public ResponseEntity<ErrorResponse> handle(Exception e) {
        return ResponseEntity.status(500).body(new ErrorResponse("SERVER_ERROR", "서버 오류"));
    }
}
```
→ `AccessDeniedException`도 여기에 잡혀 **403이어야 할 응답이 500**이 됩니다.

해결: 인가 예외를 명시적으로 처리하거나 다시 던져서 ExceptionTranslationFilter에 맡깁니다.
```java
@ExceptionHandler(AccessDeniedException.class)
public ResponseEntity<ErrorResponse> handleAccessDenied(AccessDeniedException e) {
    return ResponseEntity.status(HttpStatus.FORBIDDEN).body(new ErrorResponse("FORBIDDEN", "접근 권한이 없습니다."));
}

@ExceptionHandler(AuthenticationException.class)
public ResponseEntity<ErrorResponse> handleAuth(AuthenticationException e) {
    return ResponseEntity.status(HttpStatus.UNAUTHORIZED).body(new ErrorResponse("UNAUTHORIZED", "인증이 필요합니다."));
}
```
> 로그인 API에서 `authenticationManager.authenticate()`가 던지는 `BadCredentialsException`도 컨트롤러에서 발생하므로 같은 방식으로 401 처리합니다.

## 6. 로그인 성공·실패 핸들러 (폼 로그인)

```java
http.formLogin(form -> form
        .loginProcessingUrl("/login")
        .successHandler((req, res, auth) -> {
            res.setStatus(200);
            res.setContentType("application/json;charset=UTF-8");
            res.getWriter().write("{\"result\":\"ok\"}");
        })
        .failureHandler((req, res, ex) -> {
            res.setStatus(401);
            res.setContentType("application/json;charset=UTF-8");
            String code = (ex instanceof LockedException) ? "ACCOUNT_LOCKED" : "BAD_CREDENTIALS";
            res.getWriter().write("{\"code\":\"" + code + "\"}");
        }));
```

## 7. 인증 이벤트: 로그인 실패 횟수 제한

Spring Security는 인증 성공·실패 시 **이벤트를 발행**합니다. 감사 로그, 로그인 시도 제한에 활용합니다.

```java
@Component
@RequiredArgsConstructor
public class AuthenticationEventsListener {
    private final LoginAttemptService loginAttemptService;

    @EventListener
    public void onSuccess(AuthenticationSuccessEvent event) {
        loginAttemptService.reset(event.getAuthentication().getName());
    }

    @EventListener
    public void onFailure(AuthenticationFailureBadCredentialsEvent event) {
        String username = (String) event.getAuthentication().getPrincipal();
        loginAttemptService.increase(username);   // 5회 실패 시 계정 잠금 or 일정 시간 차단 (Redis TTL)
    }
}
```
> 로그인 API에는 **IP 기준 레이트 리밋**도 함께 적용하세요. 계정 잠금만 있으면 공격자가 남의 계정을 일부러 잠가 버리는 공격(서비스 거부)이 가능하므로, 영구 잠금보다 **일정 시간 지연·CAPTCHA**가 나은 경우가 많습니다.

## 8. 면접 질문

1. **AuthenticationEntryPoint와 AccessDeniedHandler의 차이는?**
   → EntryPoint는 인증되지 않은 사용자의 접근(인증 예외)을 처리해 401을, AccessDeniedHandler는 인증됐지만 권한이 없는 경우를 처리해 403을 응답합니다.
2. **ExceptionTranslationFilter의 역할은?**
   → 뒤쪽 필터와 애플리케이션에서 발생한 인증·인가 예외를 잡아, 인증 예외나 익명 사용자의 인가 예외는 EntryPoint로, 인증된 사용자의 인가 예외는 AccessDeniedHandler로 보냅니다.
3. **JWT 필터에서 던진 예외가 @RestControllerAdvice에서 처리되지 않는 이유는?**
   → @RestControllerAdvice는 DispatcherServlet 내부의 예외만 처리하는데, 필터는 그 바깥에서 실행되기 때문입니다. 필터에서는 인증을 설정하지 않고 넘기거나 직접 응답을 작성합니다.
4. **@ExceptionHandler(Exception.class)가 있을 때 주의할 점은?**
   → @PreAuthorize가 던진 AccessDeniedException까지 잡혀 403 대신 500이 응답될 수 있으므로, 인증·인가 예외를 별도로 처리해야 합니다.

---

## 핵심 정리
- AuthenticationException → **EntryPoint(401)** / AccessDeniedException → **AccessDeniedHandler(403)** (익명이면 401)
- ExceptionTranslationFilter는 **자기 뒤의 예외만** 처리
- 필터 예외는 @RestControllerAdvice가 못 잡음 → 인증 미설정 후 통과 + request attribute로 원인 전달
- `@ExceptionHandler(Exception.class)`가 AccessDeniedException을 삼키지 않게
- 인증 이벤트로 실패 횟수 제한, 로그인 API는 레이트 리밋
