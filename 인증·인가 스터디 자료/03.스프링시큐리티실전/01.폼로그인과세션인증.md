# 01. 폼 로그인과 세션 인증

> **학습 목표**
> - `formLogin()`, `logout()`, `rememberMe()`를 설정할 수 있다.
> - Spring Security 6에서 JSON 로그인 API로 세션 인증을 구현할 때 SecurityContext를 명시적으로 저장해야 하는 이유를 설명할 수 있다.
> - 동시 세션 제한, 세션 고정 방어, Redis 세션 공유를 설정할 수 있다.

## 1. 폼 로그인 (서버 렌더링 웹)

```java
@Configuration
@EnableWebSecurity
public class WebSecurityConfig {

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        http
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/", "/login", "/signup", "/css/**", "/js/**", "/error").permitAll()
                .requestMatchers("/admin/**").hasRole("ADMIN")
                .anyRequest().authenticated())
            .formLogin(form -> form
                .loginPage("/login")                  // 직접 만든 로그인 페이지 (GET)
                .loginProcessingUrl("/login")         // 로그인 처리 URL (POST, 필터가 처리 — 컨트롤러 불필요)
                .usernameParameter("email")           // 기본값 username
                .passwordParameter("password")
                .defaultSuccessUrl("/", false)        // false: 원래 가려던 페이지가 있으면 그쪽으로
                .failureUrl("/login?error"))
            .logout(logout -> logout
                .logoutUrl("/logout")                 // POST /logout (CSRF 토큰 필요)
                .logoutSuccessUrl("/login?logout")
                .invalidateHttpSession(true)
                .deleteCookies("JSESSIONID"))
            .rememberMe(remember -> remember
                .key("change-this-to-a-secure-random-key")
                .tokenValiditySeconds(60 * 60 * 24 * 14));   // 14일 자동 로그인
        return http.build();
    }
}
```

```html
<!-- templates/login.html (Thymeleaf) -->
<form th:action="@{/login}" method="post">
    <input type="email" name="email" required>
    <input type="password" name="password" required>
    <label><input type="checkbox" name="remember-me"> 자동 로그인</label>
    <button type="submit">로그인</button>
    <!-- Thymeleaf는 CSRF 토큰 hidden input을 자동으로 추가 -->
</form>
<p th:if="${param.error}">아이디 또는 비밀번호가 올바르지 않습니다.</p>
```

### 동작 흐름
```
1. 비로그인 사용자가 /my/orders 접근
2. AuthorizationFilter 거부 → ExceptionTranslationFilter
   → 원래 요청을 RequestCache(세션)에 저장 → /login으로 302
3. POST /login → UsernamePasswordAuthenticationFilter → 인증 성공
   → 세션 ID 변경(세션 고정 방어) → SecurityContext를 세션에 저장
4. 저장해 둔 /my/orders로 리다이렉트
5. 이후 요청: SecurityContextHolderFilter가 세션에서 SecurityContext를 꺼내 복원
```

## 2. JSON 로그인 API + 세션 (SPA)

React 같은 SPA에서 세션 방식을 쓰려면 폼 대신 JSON으로 로그인합니다.

### ⚠️ Spring Security 6의 변경: SecurityContext 자동 저장 X
Spring Security 5까지는 `SecurityContextHolder`에 넣으면 요청이 끝날 때 **자동으로 세션에 저장**됐습니다. 6부터는 **명시적으로 저장**해야 합니다. 그렇지 않으면 "로그인은 성공했는데 다음 요청에서 로그인이 풀리는" 문제가 생깁니다.

```java
@RestController
@RequiredArgsConstructor
@RequestMapping("/api/auth")
public class SessionAuthController {

    private final AuthenticationManager authenticationManager;
    private final SecurityContextRepository securityContextRepository = new HttpSessionSecurityContextRepository();
    private final SecurityContextHolderStrategy strategy = SecurityContextHolder.getContextHolderStrategy();

    @PostMapping("/login")
    public ResponseEntity<Void> login(@RequestBody @Valid LoginRequest req,
                                      HttpServletRequest request, HttpServletResponse response) {
        Authentication authentication = authenticationManager.authenticate(
                UsernamePasswordAuthenticationToken.unauthenticated(req.email(), req.password()));

        // 세션 고정 방어: 기존 세션이 있으면 ID 변경 (컨트롤러 로그인은 필터처럼 자동 처리되지 않음)
        if (request.getSession(false) != null) {
            request.changeSessionId();
        }

        SecurityContext context = strategy.createEmptyContext();
        context.setAuthentication(authentication);
        strategy.setContext(context);
        securityContextRepository.saveContext(context, request, response);   // ★ 세션에 저장
        return ResponseEntity.ok().build();
    }

    @GetMapping("/me")
    public MeResponse me(@AuthenticationPrincipal CustomUserDetails user) {
        return new MeResponse(user.getId(), user.getUsername());
    }
}

public record LoginRequest(@NotBlank String email, @NotBlank String password) { }
public record MeResponse(Long id, String email) { }
```

```java
@Bean
public SecurityFilterChain apiChain(HttpSecurity http,
                                    JsonAuthenticationEntryPoint entryPoint) throws Exception {
    http
        .securityContext(ctx -> ctx.securityContextRepository(new HttpSessionSecurityContextRepository()))
        .csrf(csrf -> csrf                                                    // SPA용 CSRF (자세한 내용 → 07 문서)
            .csrfTokenRepository(CookieCsrfTokenRepository.withHttpOnlyFalse())
            .csrfTokenRequestHandler(new CsrfTokenRequestAttributeHandler()))
        .authorizeHttpRequests(auth -> auth
            .requestMatchers("/api/auth/login", "/error").permitAll()
            .anyRequest().authenticated())
        .exceptionHandling(ex -> ex.authenticationEntryPoint(entryPoint))     // 302 대신 401 JSON
        .logout(logout -> logout
            .logoutUrl("/api/auth/logout")
            .logoutSuccessHandler((req, res, auth) -> res.setStatus(204)));
    return http.build();
}
```
> 로그인 API에서 던지는 `BadCredentialsException`은 컨트롤러 안에서 발생하므로 `@RestControllerAdvice`에서 401로 처리합니다. (→ `02.스프링시큐리티구조/04.예외처리.md`)

## 3. 세션 관리 설정

```java
http.sessionManagement(session -> session
        .sessionCreationPolicy(SessionCreationPolicy.IF_REQUIRED)
        .sessionFixation(fixation -> fixation.changeSessionId())    // 기본값: 로그인 시 세션 ID 변경
        .maximumSessions(1)                                         // 계정당 동시 로그인 1개
            .maxSessionsPreventsLogin(false)                        // false: 새 로그인 시 기존 세션 만료
            .expiredUrl("/login?expired"));
```

| 옵션 | 의미 |
|---|---|
| `maximumSessions(1)` | 동시 세션 수 제한 |
| `maxSessionsPreventsLogin(true)` | 이미 로그인 중이면 **새 로그인을 거부** |
| `maxSessionsPreventsLogin(false)` | 새 로그인 허용, **기존 세션을 만료** (일반적) |

> 동시 세션 제한은 `SessionRegistry`로 세션을 추적하는데, 기본 구현은 **서버 메모리**입니다. 서버가 여러 대면 Spring Session의 `SpringSessionBackedSessionRegistry`를 써야 정확히 동작합니다. 또한 `UserDetails` 구현체가 `equals()`/`hashCode()`를 구현해야 같은 사용자로 인식됩니다.

### 세션 타임아웃·쿠키 설정 (application.yml)
```yaml
server:
  servlet:
    session:
      timeout: 30m
      tracking-modes: cookie         # URL에 jsessionid 붙는 것 방지
      cookie:
        http-only: true
        secure: true                 # HTTPS 환경
        same-site: lax
```

## 4. 세션 저장소: Redis (다중 서버)

```groovy
implementation 'org.springframework.boot:spring-boot-starter-data-redis'
implementation 'org.springframework.session:spring-session-data-redis'
```
```yaml
spring:
  data:
    redis:
      host: localhost
      port: 6379
  session:
    timeout: 30m
    redis:
      namespace: myapp:session
```
→ `HttpSession`과 Spring Security의 SecurityContext가 **Redis에 저장**되어 어느 서버로 요청이 가도 로그인이 유지됩니다.

> 세션에 저장되는 principal(`CustomUserDetails`)은 **직렬화**됩니다. 기본 JDK 직렬화를 쓰면 클래스 구조가 바뀔 때 기존 세션을 읽지 못할 수 있으므로, principal은 작고 단순하게 유지하세요. (Redis 직렬화를 JSON으로 바꿀 수도 있습니다)

## 5. Remember-Me (자동 로그인)

| 방식 | 동작 | 특징 |
|---|---|---|
| `TokenBasedRememberMeServices` (기본) | 쿠키에 `사용자명 + 만료시각 + 서명` | 저장소 불필요, **비밀번호 바꾸면 무효화**, 탈취 시 만료까지 유효 |
| `PersistentTokenBasedRememberMeServices` | 쿠키에 랜덤 series + token, DB에 저장 | 사용할 때마다 토큰 교체, **탈취 감지 가능** |

```java
http.rememberMe(remember -> remember
        .tokenRepository(persistentTokenRepository)       // 아래 빈을 주입받아 사용 (DB 저장 방식)
        .tokenValiditySeconds(1209600));

@Bean
public PersistentTokenRepository persistentTokenRepository(DataSource dataSource) {
    JdbcTokenRepositoryImpl repo = new JdbcTokenRepositoryImpl();
    repo.setDataSource(dataSource);       // persistent_logins 테이블 필요
    return repo;
}
```
> 자동 로그인으로 들어온 사용자는 비밀번호 변경·결제 같은 **중요 작업 전에 재인증**하게 하세요. (`fullyAuthenticated()`)

## 6. 면접 질문

1. **폼 로그인은 어떤 순서로 처리되나요?**
   → 비로그인 요청이 거부되면 원래 요청을 저장하고 로그인 페이지로 보내며, POST /login을 UsernamePasswordAuthenticationFilter가 받아 인증한 뒤 세션 ID를 바꾸고 SecurityContext를 세션에 저장한 다음 원래 페이지로 리다이렉트합니다.
2. **Spring Security 6에서 직접 로그인 API를 만들 때 주의할 점은?**
   → SecurityContext가 자동으로 세션에 저장되지 않으므로 SecurityContextRepository로 명시적으로 저장해야 하고, 세션 고정 방어도 직접 처리해야 합니다.
3. **동시 로그인을 1개로 제한하려면?**
   → sessionManagement의 maximumSessions(1)을 설정하며, 여러 서버에서는 Spring Session 기반 SessionRegistry를 사용해야 합니다.

## 핵심 정리
- 폼 로그인: `formLogin()` + 로그인 처리는 필터가 담당 (컨트롤러 X), RequestCache로 원래 페이지 복원
- **Security 6+: 직접 만든 로그인 API는 `securityContextRepository.saveContext()` 필수**
- 세션 고정 방어(기본 changeSessionId), 동시 세션 `maximumSessions`
- 다중 서버 → Spring Session + Redis, principal은 작게
- Remember-Me는 Persistent 방식이 더 안전, 중요 작업은 재인증
