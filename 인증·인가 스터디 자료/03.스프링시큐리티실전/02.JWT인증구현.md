# 02. JWT 인증 구현 (커스텀 필터 방식)

> **학습 목표**
> - jjwt 라이브러리로 Access Token을 발급·검증할 수 있다.
> - JWT 인증 필터를 만들어 SecurityFilterChain에 등록할 수 있다.
> - 로그인 API → 토큰 발급 → 인증된 API 호출까지 전체 흐름을 구현할 수 있다.
> - 커스텀 필터 방식과 Spring 공식 Resource Server 방식의 차이를 안다.

> 이 문서는 국내 프로젝트에서 가장 많이 쓰는 **직접 구현(커스텀 필터) 방식**입니다. Spring Security가 제공하는 표준 방식은 → `05.리소스서버와JWT검증.md`

## 1. 전체 구조

```
POST /api/auth/login {email, password}
  → AuthController → AuthenticationManager로 비밀번호 검증 → JwtTokenProvider.createAccessToken()
  ← { accessToken, refreshToken }

GET /api/orders   Authorization: Bearer eyJ...
  → [JwtAuthenticationFilter] 토큰 꺼내기 → 서명·만료 검증 → Authentication 생성 → SecurityContextHolder
  → [AuthorizationFilter] 인증됨? 권한? → 통과
  → OrderController (@AuthenticationPrincipal AuthMember)
```

## 3. JwtTokenProvider: 발급과 검증

```java
@Component
public class JwtTokenProvider {

    private static final String ISSUER = "myapp";
    private static final String ROLE_CLAIM = "role";

    private final SecretKey key;
    private final JwtProperties properties;

    public JwtTokenProvider(JwtProperties properties) {
        this.properties = properties;
        this.key = Keys.hmacShaKeyFor(Decoders.BASE64.decode(properties.secret()));   // 짧은 키면 예외 → 실수 방지
    }

    public String createAccessToken(Long memberId, Role role) {
        Instant now = Instant.now();
        return Jwts.builder()
                .issuer(ISSUER)
                .subject(String.valueOf(memberId))          // sub: 사용자 ID (이메일 등 개인정보 X)
                .claim(ROLE_CLAIM, role.name())
                .id(UUID.randomUUID().toString())           // jti: 로그아웃 블랙리스트용
                .issuedAt(Date.from(now))
                .expiration(Date.from(now.plus(properties.accessTokenValidity())))
                .signWith(key)                              // 256비트 키 → HS256
                .compact();
    }

    /** 서명·만료·발급자를 검증하고 클레임을 반환. 실패 시 JwtException 계열 예외 */
    public Claims parse(String token) {
        return Jwts.parser()
                .verifyWith(key)
                .requireIssuer(ISSUER)
                .build()
                .parseSignedClaims(token)                   // 서명 없는 토큰(alg: none)은 거부됨
                .getPayload();
    }

    public Authentication getAuthentication(String token) {
        Claims claims = parse(token);
        AuthMember principal = new AuthMember(
                Long.valueOf(claims.getSubject()),
                Role.valueOf(claims.get(ROLE_CLAIM, String.class)));
        return UsernamePasswordAuthenticationToken.authenticated(
                principal, null, List.of(new SimpleGrantedAuthority("ROLE_" + principal.role().name())));
    }
}
```

```java
/** 토큰에서 복원한 로그인 사용자 (DB 조회 없이 사용) */
public record AuthMember(Long id, Role role) { }
```

> 요청마다 DB에서 사용자를 다시 조회하지 않는 것이 JWT의 장점입니다. 대신 **권한이 바뀌어도 토큰이 만료될 때까지는 이전 권한**이 유지됩니다. 권한 변경·계정 정지를 즉시 반영해야 한다면 Access Token 수명을 짧게 하거나, 중요한 API에서는 DB 상태를 다시 확인합니다.

### jjwt 0.12 API 변경 (옛날 예제 주의)
| 0.11 이하 (deprecated) | 0.12+ |
|---|---|
| `setSubject()`, `setExpiration()` | `subject()`, `expiration()` |
| `signWith(key, SignatureAlgorithm.HS256)` | `signWith(key)` (키로 알고리즘 결정) |
| `Jwts.parserBuilder().setSigningKey(key)` | `Jwts.parser().verifyWith(key)` |
| `parseClaimsJws(token).getBody()` | `parseSignedClaims(token).getPayload()` |

## 4. JwtAuthenticationFilter

```java
@RequiredArgsConstructor
public class JwtAuthenticationFilter extends OncePerRequestFilter {

    private static final String BEARER_PREFIX = "Bearer ";
    private final JwtTokenProvider jwtTokenProvider;

    @Override
    protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response,
                                    FilterChain filterChain) throws ServletException, IOException {
        String token = resolveToken(request);

        if (token != null) {
            try {
                Authentication authentication = jwtTokenProvider.getAuthentication(token);
                SecurityContext context = SecurityContextHolder.createEmptyContext();
                context.setAuthentication(authentication);
                SecurityContextHolder.setContext(context);
            } catch (ExpiredJwtException e) {
                request.setAttribute("auth.error", "TOKEN_EXPIRED");    // EntryPoint가 응답에 사용
            } catch (JwtException | IllegalArgumentException e) {
                request.setAttribute("auth.error", "INVALID_TOKEN");
            }
        }
        // 토큰이 없거나 무효하면 인증 정보 없이 진행 → permitAll 경로는 통과, 나머지는 EntryPoint가 401
        filterChain.doFilter(request, response);
    }

    private String resolveToken(HttpServletRequest request) {
        String header = request.getHeader(HttpHeaders.AUTHORIZATION);
        if (StringUtils.hasText(header) && header.startsWith(BEARER_PREFIX)) {
            return header.substring(BEARER_PREFIX.length());
        }
        return null;
    }
}
```

| 포인트 | 이유 |
|---|---|
| `OncePerRequestFilter` | 포워드·에러 디스패치에서 중복 실행 방지 |
| **예외를 던지지 않고 attribute로 원인 전달** | 필터 예외는 @RestControllerAdvice가 못 잡음 (→ 예외 처리 문서) |
| `@Component`로 등록하지 않음 | 서블릿 필터로 중복 등록 방지 → SecurityConfig에서 `new` |
| 토큰 없으면 그냥 통과 | 로그인·회원 가입 같은 공개 API도 같은 체인을 지나기 때문 |

## 5. SecurityConfig

```java
@Configuration
@EnableWebSecurity
@EnableMethodSecurity
@RequiredArgsConstructor
public class SecurityConfig {

    private final JwtTokenProvider jwtTokenProvider;
    private final JsonAuthenticationEntryPoint authenticationEntryPoint;
    private final JsonAccessDeniedHandler accessDeniedHandler;

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        http
            .csrf(csrf -> csrf.disable())                  // 헤더로 토큰 전송 → CSRF 대상 아님
            .cors(Customizer.withDefaults())
            .formLogin(form -> form.disable())
            .httpBasic(basic -> basic.disable())
            .logout(logout -> logout.disable())            // 로그아웃은 API로 직접 구현
            .sessionManagement(session -> session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/auth/login", "/api/auth/signup", "/api/auth/reissue", "/error").permitAll()
                .requestMatchers(HttpMethod.GET, "/api/products/**").permitAll()
                .requestMatchers("/api/admin/**").hasRole("ADMIN")
                .anyRequest().authenticated())
            .exceptionHandling(ex -> ex
                .authenticationEntryPoint(authenticationEntryPoint)
                .accessDeniedHandler(accessDeniedHandler))
            .addFilterBefore(new JwtAuthenticationFilter(jwtTokenProvider),
                             UsernamePasswordAuthenticationFilter.class);
        return http.build();
    }

    @Bean
    public PasswordEncoder passwordEncoder() {
        return PasswordEncoderFactories.createDelegatingPasswordEncoder();
    }

    @Bean
    public AuthenticationManager authenticationManager(AuthenticationConfiguration configuration) throws Exception {
        return configuration.getAuthenticationManager();
    }
}
```

## 6. 로그인 API

```java
public record LoginRequest(@NotBlank @Email String email, @NotBlank String password) { }
public record TokenResponse(String accessToken, String refreshToken) { }
```

```java
@Service
@RequiredArgsConstructor
public class AuthService {

    private final AuthenticationManager authenticationManager;
    private final JwtTokenProvider jwtTokenProvider;
    private final RefreshTokenService refreshTokenService;      // → 03.리프레시토큰과로그아웃.md

    public TokenResponse login(LoginRequest req) {
        // CustomUserDetailsService + PasswordEncoder로 검증 (실패 시 BadCredentialsException, LockedException)
        Authentication authentication = authenticationManager.authenticate(
                UsernamePasswordAuthenticationToken.unauthenticated(req.email(), req.password()));

        CustomUserDetails user = (CustomUserDetails) authentication.getPrincipal();
        String accessToken = jwtTokenProvider.createAccessToken(user.getId(), user.getRole());
        String refreshToken = refreshTokenService.issue(user.getId());
        return new TokenResponse(accessToken, refreshToken);
    }
}
```
(`CustomUserDetails`에 `getRole()` getter를 추가합니다.)

```java
@RestController
@RequiredArgsConstructor
@RequestMapping("/api/auth")
public class AuthController {
    private final AuthService authService;

    @PostMapping("/login")
    public TokenResponse login(@RequestBody @Valid LoginRequest req) {
        return authService.login(req);
    }
}
```

```java
@RestControllerAdvice
public class AuthExceptionHandler {
    @ExceptionHandler(AuthenticationException.class)      // 로그인 실패 (컨트롤러 안에서 발생)
    public ResponseEntity<ErrorResponse> handle(AuthenticationException e) {
        String code = (e instanceof LockedException) ? "ACCOUNT_LOCKED" : "BAD_CREDENTIALS";
        return ResponseEntity.status(HttpStatus.UNAUTHORIZED)
                .body(new ErrorResponse(code, "아이디 또는 비밀번호가 올바르지 않습니다."));
    }
}
```

## 7. 인증된 API에서 사용자 꺼내기

```java
@RestController
@RequestMapping("/api/orders")
@RequiredArgsConstructor
public class OrderController {
    private final OrderService orderService;

    @GetMapping
    public List<OrderResponse> myOrders(@AuthenticationPrincipal AuthMember member) {
        return orderService.findByMember(member.id());       // ★ 사용자 ID는 토큰에서 (요청 파라미터로 받지 않음)
    }
}
```
> **사용자 ID를 요청 바디·쿼리로 받지 마세요.** `GET /api/orders?memberId=43`처럼 받으면 남의 주문을 조회할 수 있습니다(IDOR). 항상 **인증 정보에서** 꺼냅니다.

### 호출 테스트
```bash
# 로그인
curl -s -X POST localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"user@example.com","password":"password1234"}'
# {"accessToken":"eyJhbGciOiJIUzI1NiJ9...","refreshToken":"..."}

# 인증 API
curl -s localhost:8080/api/orders -H "Authorization: Bearer eyJhbGciOiJIUzI1NiJ9..."

# 토큰 없이 → 401 {"code":"UNAUTHORIZED",...}
# 만료된 토큰 → 401 {"code":"TOKEN_EXPIRED",...}
# USER 토큰으로 /api/admin/** → 403 {"code":"FORBIDDEN",...}
```

## 8. 커스텀 필터 vs Resource Server

| 비교 | 커스텀 필터 (이 문서) | **OAuth2 Resource Server** (→ 05 문서) |
|---|---|---|
| 구현량 | 필터·파싱·예외 처리 직접 | 설정 몇 줄 |
| 라이브러리 | jjwt | Spring Security 내장 (Nimbus) |
| 표준 에러 응답 | 직접 | `WWW-Authenticate: Bearer` 표준 |
| 외부 인증 서버(Keycloak, Cognito) 연동 | 직접 구현 | `issuer-uri` 한 줄 |
| 학습 효과 | 내부 동작 이해에 좋음 | 실무 표준 |

> 원리를 이해하려면 커스텀 필터로 한 번 만들어 보고, 실무에서는 Resource Server 방식을 우선 검토하는 것을 권장합니다.

## 9. 면접 질문

1. **JWT 인증 필터는 어떻게 동작하나요?**
   → Authorization 헤더에서 Bearer 토큰을 꺼내 서명·만료를 검증하고, 클레임으로 Authentication 객체를 만들어 SecurityContextHolder에 넣은 뒤 다음 필터로 넘깁니다. 이후 AuthorizationFilter가 이 인증 정보로 인가를 판단합니다.
2. **JWT 필터를 UsernamePasswordAuthenticationFilter 앞에 두는 이유는?**
   → 인증 정보를 인가 필터보다 먼저 SecurityContext에 설정해야 하고, 관례적으로 인증 처리 필터들의 위치에 두기 위해서입니다.
3. **JWT 방식에서 SessionCreationPolicy.STATELESS를 쓰는 이유는?**
   → 매 요청 토큰으로 인증하므로 서버에 세션을 만들 필요가 없고, 세션이 생기면 무상태의 장점과 수평 확장성이 사라지기 때문입니다.
4. **토큰이 유효하지 않을 때 필터에서 예외를 던지지 않는 이유는?**
   → 필터 예외는 컨트롤러 예외 처리기로 가지 않고, 공개 API까지 막을 수 있기 때문에 인증만 설정하지 않고 넘겨 인가 단계와 EntryPoint가 401을 처리하게 합니다.

## 핵심 정리
- jjwt 0.12: `Jwts.builder().subject().claim().expiration().signWith(key)`, 검증 `Jwts.parser().verifyWith(key).build().parseSignedClaims()`
- 키: 256비트 이상 랜덤, 환경 변수로 주입
- `OncePerRequestFilter` → 검증 → `SecurityContextHolder` 설정 → **예외 대신 attribute** → `chain.doFilter`
- SecurityConfig: csrf disable, STATELESS, `addFilterBefore(..., UsernamePasswordAuthenticationFilter.class)`, EntryPoint·AccessDeniedHandler
- 로그인: AuthenticationManager로 검증 → 토큰 발급, 사용자 ID는 항상 토큰에서
