# 04. OAuth2 소셜 로그인 (카카오·구글)

> **학습 목표**
> - `spring-boot-starter-oauth2-client`로 구글·카카오 로그인을 설정할 수 있다.
> - 카카오처럼 기본 제공되지 않는 공급자의 provider 설정을 작성할 수 있다.
> - `OAuth2UserService`를 구현해 소셜 사용자를 우리 회원으로 가입·매핑할 수 있다.
> - 로그인 성공 후 JWT(또는 세션)를 발급하는 흐름을 구현할 수 있다.

---

## 1. 전체 흐름 (Spring Security가 해 주는 것)

```
① 프론트: <a href="https://api.example.com/oauth2/authorization/kakao">카카오로 로그인</a>
② OAuth2AuthorizationRequestRedirectFilter → 카카오 인가 페이지로 302 (state, PKCE 자동 생성·저장)
③ 사용자 카카오 로그인·동의
④ 카카오 → GET /login/oauth2/code/kakao?code=...&state=...
⑤ OAuth2LoginAuthenticationFilter → state 검증 → code로 토큰 요청 → 사용자 정보 API 호출
⑥ ★ OAuth2UserService.loadUser()  ← 우리가 구현: 회원 가입·조회
⑦ ★ AuthenticationSuccessHandler   ← 우리가 구현: JWT 발급 → 프론트로 리다이렉트
```
→ 인가 코드 교환, state 검증, 토큰 요청은 **Spring Security가 처리**하고, 우리는 **⑥ 회원 매핑과 ⑦ 로그인 후 처리**만 만듭니다.

## 2. 사전 준비

### 구글 (Google Cloud Console)
- OAuth 클라이언트 ID 생성 (웹 애플리케이션)
- 승인된 리디렉션 URI: `http://localhost:8080/login/oauth2/code/google`

### 카카오 (Kakao Developers)
- 애플리케이션 추가 → **REST API 키** = client-id
- 보안 → Client Secret 생성·활성화 (선택이지만 권장)
- 카카오 로그인 활성화, Redirect URI: `http://localhost:8080/login/oauth2/code/kakao`
- 동의 항목: 닉네임, (이메일은 비즈 앱 전환이 필요할 수 있음)

> Redirect URI는 콘솔에 등록한 값과 **정확히 일치**해야 합니다. 운영 도메인(`https://api.example.com/...`)도 따로 등록하세요.

## 3. 설정

```groovy
implementation 'org.springframework.boot:spring-boot-starter-oauth2-client'
```

```yaml
spring:
  security:
    oauth2:
      client:
        registration:
          google:
            client-id: ${GOOGLE_CLIENT_ID}
            client-secret: ${GOOGLE_CLIENT_SECRET}
            scope: profile, email                  # openid를 빼면 OAuth2UserService 사용 (아래 주의 참고)

          kakao:
            client-id: ${KAKAO_CLIENT_ID}          # REST API 키
            client-secret: ${KAKAO_CLIENT_SECRET}
            client-authentication-method: client_secret_post
            authorization-grant-type: authorization_code
            redirect-uri: "{baseUrl}/login/oauth2/code/{registrationId}"
            scope: profile_nickname, account_email
            client-name: Kakao

        provider:
          kakao:                                   # 구글·깃허브·페이스북 등은 기본 제공, 카카오·네이버는 직접 등록
            authorization-uri: https://kauth.kakao.com/oauth/authorize
            token-uri: https://kauth.kakao.com/oauth/token
            user-info-uri: https://kapi.kakao.com/v2/user/me
            user-name-attribute: id

app:
  frontend-url: http://localhost:3000
```

> ⚠️ **scope에 `openid`가 들어가면** Spring Security는 OIDC 흐름으로 처리하고 `OAuth2UserService`가 아니라 **`OidcUserService`** 를 호출합니다. 커스텀 `OAuth2UserService`가 호출되지 않는다면 이 경우입니다. OIDC를 쓰려면 `oidcUserService(...)`를 따로 등록하세요.

## 4. 회원 엔티티

```java
@Entity
@Getter
@NoArgsConstructor(access = AccessLevel.PROTECTED)
@Table(uniqueConstraints = @UniqueConstraint(columnNames = {"provider", "providerId"}))
public class Member {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String email;           // 소셜은 제공되지 않을 수 있음 → nullable
    private String password;        // 소셜 회원은 null
    private String name;

    @Enumerated(EnumType.STRING)
    private Role role;

    private String provider;        // "local", "google", "kakao"
    private String providerId;      // 공급자의 사용자 고유 ID
    private boolean locked;

    public static Member ofSocial(OAuth2UserInfo info) {
        Member m = new Member();
        m.email = info.email();
        m.name = info.name();
        m.provider = info.provider();
        m.providerId = info.providerId();
        m.role = Role.USER;
        return m;
    }

    public void updateProfile(String name) { this.name = name; }
}
```
> 회원 식별은 **(provider, providerId)** 로 합니다. 이메일은 바뀌거나 비어 있을 수 있습니다.

## 5. 공급자별 사용자 정보 정리

공급자마다 응답 형식이 다릅니다.
구글:
```json
{ "sub": "110169484474386276334", "email": "yoon@gmail.com", "name": "윤빈", "picture": "..." }
```
카카오:
```json
{ "id": 4123456789,
  "kakao_account": { "email": "yoon@kakao.com", "profile": { "nickname": "윤빈" } } }
```

```java
public record OAuth2UserInfo(String provider, String providerId, String email, String name) {

    public static OAuth2UserInfo of(String registrationId, Map<String, Object> attributes) {
        return switch (registrationId) {
            case "google" -> new OAuth2UserInfo("google",
                    (String) attributes.get("sub"),
                    (String) attributes.get("email"),
                    (String) attributes.get("name"));
            case "kakao" -> ofKakao(attributes);
            default -> throw new OAuth2AuthenticationException("unsupported_provider");
        };
    }

    @SuppressWarnings("unchecked")
    private static OAuth2UserInfo ofKakao(Map<String, Object> attributes) {
        Map<String, Object> account = (Map<String, Object>) attributes.getOrDefault("kakao_account", Map.of());
        Map<String, Object> profile = (Map<String, Object>) account.getOrDefault("profile", Map.of());
        return new OAuth2UserInfo("kakao",
                String.valueOf(attributes.get("id")),
                (String) account.get("email"),
                (String) profile.get("nickname"));
    }
}
```

## 6. CustomOAuth2UserService

```java
@Service
@RequiredArgsConstructor
public class CustomOAuth2UserService extends DefaultOAuth2UserService {

    private final MemberRepository memberRepository;

    @Override
    @Transactional
    public OAuth2User loadUser(OAuth2UserRequest userRequest) throws OAuth2AuthenticationException {
        OAuth2User oAuth2User = super.loadUser(userRequest);          // 공급자의 사용자 정보 API 호출
        String registrationId = userRequest.getClientRegistration().getRegistrationId();
        OAuth2UserInfo info = OAuth2UserInfo.of(registrationId, oAuth2User.getAttributes());

        Member member = memberRepository.findByProviderAndProviderId(info.provider(), info.providerId())
                .map(existing -> { existing.updateProfile(info.name()); return existing; })
                .orElseGet(() -> memberRepository.save(Member.ofSocial(info)));   // 최초 로그인 = 가입

        if (member.isLocked()) {
            throw new OAuth2AuthenticationException("account_locked");
        }
        return new CustomOAuth2User(member.getId(), member.getRole(), oAuth2User.getAttributes());
    }
}
```

```java
public class CustomOAuth2User implements OAuth2User {
    private final Long memberId;
    private final Role role;
    private final Map<String, Object> attributes;

    public CustomOAuth2User(Long memberId, Role role, Map<String, Object> attributes) {
        this.memberId = memberId;
        this.role = role;
        this.attributes = attributes;
    }

    public Long getMemberId() { return memberId; }
    public Role getRole() { return role; }

    @Override public Map<String, Object> getAttributes() { return attributes; }
    @Override public Collection<? extends GrantedAuthority> getAuthorities() {
        return List.of(new SimpleGrantedAuthority("ROLE_" + role.name()));
    }
    @Override public String getName() { return String.valueOf(memberId); }
}
```

```java
public interface MemberRepository extends JpaRepository<Member, Long> {
    Optional<Member> findByEmail(String email);
    Optional<Member> findByProviderAndProviderId(String provider, String providerId);
}
```

## 7. 로그인 성공 후: JWT 발급

**토큰을 URL 쿼리로 넘기지 마세요.** (`/callback?token=eyJ...` → 브라우저 기록, 서버 로그, Referer 헤더로 유출)

```java
@Component
@RequiredArgsConstructor
public class OAuth2LoginSuccessHandler implements AuthenticationSuccessHandler {

    private final RefreshTokenService refreshTokenService;
    private final RefreshTokenCookie refreshTokenCookie;

    @Value("${app.frontend-url}")
    private String frontendUrl;

    @Override
    public void onAuthenticationSuccess(HttpServletRequest request, HttpServletResponse response,
                                        Authentication authentication) throws IOException {
        CustomOAuth2User user = (CustomOAuth2User) authentication.getPrincipal();
        String refreshToken = refreshTokenService.issue(user.getMemberId());

        response.addHeader(HttpHeaders.SET_COOKIE, refreshTokenCookie.create(refreshToken).toString());
        response.sendRedirect(frontendUrl + "/oauth/callback");      // 토큰은 URL에 넣지 않음
    }
}
```
```
프론트 /oauth/callback 페이지
 → POST /api/auth/reissue (credentials: 'include', 쿠키의 Refresh 전송)
 → accessToken 받아 메모리에 저장 → 메인 화면으로
```
> Refresh 쿠키가 `SameSite=Strict`이면 **프론트와 API가 같은 사이트**(`app.example.com` / `api.example.com`)여야 재발급 요청에 쿠키가 실립니다. 완전히 다른 도메인이면 `SameSite=None; Secure` + CSRF 대비가 필요합니다.

> 대안: 리다이렉트 URL에 **짧은 수명(30초)의 일회용 코드**를 넣고, 프론트가 그 코드를 API로 보내 토큰과 교환하는 방식도 많이 씁니다.

## 8. SecurityConfig에 추가

```java
http
    .oauth2Login(oauth -> oauth
        .userInfoEndpoint(userInfo -> userInfo.userService(customOAuth2UserService))
        .successHandler(oAuth2LoginSuccessHandler)
        .failureHandler((req, res, ex) -> res.sendRedirect(frontendUrl + "/login?error=oauth")))
    .authorizeHttpRequests(auth -> auth
        .requestMatchers("/oauth2/**", "/login/oauth2/**").permitAll()
        // ... 나머지 규칙
        .anyRequest().authenticated())
    .exceptionHandling(ex -> ex.authenticationEntryPoint(jsonAuthenticationEntryPoint));   // API는 302 대신 401
```

| URL | 역할 |
|---|---|
| `GET /oauth2/authorization/{registrationId}` | 로그인 시작 (공급자로 리다이렉트) |
| `GET /login/oauth2/code/{registrationId}` | 공급자 콜백 (기본 redirect-uri) |

### STATELESS + oauth2Login 주의
로그인 진행 중의 **인가 요청 정보(state, PKCE)** 는 기본적으로 **세션**(`HttpSessionOAuth2AuthorizationRequestRepository`)에 잠시 저장됩니다.
- 서버 1대: 그대로 동작
- 서버 여러 대: ②와 ④가 다른 서버로 가면 실패 → **스티키 세션**, **Spring Session(Redis)**, 또는 **쿠키 기반 `AuthorizationRequestRepository`** 를 직접 구현

## 9. 같은 이메일, 다른 로그인 방식은?

`yoon@gmail.com`으로 일반 가입한 사람이 구글로 로그인하면?

| 정책 | 설명 | 위험 |
|---|---|---|
| 별도 계정 | provider별로 다른 회원 | 사용자 혼란 |
| **자동 연결** | 이메일이 같으면 기존 계정에 연결 | **공급자가 이메일 소유를 검증하지 않으면 계정 탈취 가능** → `email_verified` 확인 필수 |
| **수동 연결** (권장) | 기존 계정으로 로그인한 상태에서 "구글 계정 연결" | 안전 |

## 10. 면접 질문

1. **Spring Security에서 소셜 로그인은 어떻게 동작하나요?**
   → `/oauth2/authorization/{id}`로 요청하면 필터가 공급자 인가 페이지로 리다이렉트하고, 콜백으로 받은 code를 토큰으로 교환한 뒤 사용자 정보를 받아 OAuth2UserService에 넘깁니다. 우리는 여기서 회원을 조회·가입하고 성공 핸들러에서 세션이나 JWT를 발급합니다.
2. **소셜 회원을 이메일이 아닌 provider와 providerId로 식별하는 이유는?**
   → 이메일은 변경되거나 제공되지 않을 수 있고 공급자마다 검증 여부가 다르지만, providerId는 공급자 안에서 고유하고 변하지 않기 때문입니다.
3. **로그인 성공 후 JWT를 URL로 전달하면 안 되는 이유는?**
   → URL은 브라우저 기록, 서버 접근 로그, Referer 헤더 등으로 쉽게 유출되기 때문에 HttpOnly 쿠키나 일회용 코드 교환 방식을 씁니다.
4. **커스텀 OAuth2UserService가 호출되지 않는다면?**
   → scope에 openid가 포함되어 OIDC 흐름으로 처리되는 경우로, OidcUserService를 등록하거나 openid scope를 빼야 합니다.

## 핵심 정리
- `oauth2-client` + yml(registration, 카카오는 provider까지) → 코드 교환·state·PKCE는 Spring이 처리
- 우리가 구현: **OAuth2UserService**(회원 매핑) + **SuccessHandler**(우리 토큰 발급)
- 회원 식별 = (provider, providerId), 이메일 자동 연결은 위험
- 토큰을 URL에 넣지 않기 → Refresh 쿠키 + 프론트에서 reissue
- `openid` scope → OidcUserService, 다중 서버 → 인가 요청 저장소 주의
