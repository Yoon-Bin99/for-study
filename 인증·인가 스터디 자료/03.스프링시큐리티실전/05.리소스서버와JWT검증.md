# 05. OAuth2 Resource Server로 JWT 검증하기 (Spring 공식 방식)

> **학습 목표**
> - `oauth2ResourceServer().jwt()`로 커스텀 필터 없이 JWT 인증을 구성할 수 있다.
> - 직접 발급한 HS256 토큰을 `JwtEncoder`/`JwtDecoder`로 발급·검증할 수 있다.
> - 외부 인증 서버(Keycloak, Cognito, Auth0)의 RS256 토큰을 `issuer-uri`로 검증할 수 있다.
> - JWT 클레임을 권한(GrantedAuthority)으로 변환하고, 추가 검증 규칙을 넣을 수 있다.

---

## 1. 왜 Resource Server 방식인가?

`02.JWT인증구현.md`에서 직접 만든 것(필터, 파싱, 예외 처리, 401 응답)을 Spring Security가 **표준대로** 제공합니다.

```
요청 Authorization: Bearer eyJ...
 → [BearerTokenAuthenticationFilter]  토큰 추출
 → [JwtAuthenticationProvider]
      JwtDecoder: 서명·exp·nbf·iss 검증
      JwtAuthenticationConverter: 클레임 → 권한
 → JwtAuthenticationToken (principal = Jwt) 을 SecurityContext에
 실패 시 → BearerTokenAuthenticationEntryPoint: 401 + WWW-Authenticate: Bearer error="invalid_token"
```

```groovy
implementation 'org.springframework.boot:spring-boot-starter-oauth2-resource-server'
```

## 2. 외부 인증 서버의 토큰 검증 (RS256)

Keycloak, AWS Cognito, Auth0, Spring Authorization Server 등이 토큰을 발급하고, 우리 API는 **검증만** 하는 경우입니다.

```yaml
spring:
  security:
    oauth2:
      resourceserver:
        jwt:
          issuer-uri: https://keycloak.example.com/realms/myapp
          # 또는 jwk-set-uri: https://keycloak.example.com/realms/myapp/protocol/openid-connect/certs
          audiences: order-api                # aud 클레임 검증
```

```java
@Bean
public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
    http
        .csrf(csrf -> csrf.disable())
        .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
        .authorizeHttpRequests(auth -> auth
            .requestMatchers("/error").permitAll()
            .requestMatchers("/api/admin/**").hasRole("ADMIN")
            .anyRequest().authenticated())
        .oauth2ResourceServer(oauth2 -> oauth2.jwt(Customizer.withDefaults()));
    return http.build();
}
```
이게 전부입니다.
- `issuer-uri`의 `/.well-known/openid-configuration`에서 **JWKS(공개키) 주소**를 찾아 자동으로 가져옴
- 토큰 헤더의 `kid`로 맞는 공개키 선택, **키 교체(rotation)** 도 자동 반영
- `iss`가 issuer-uri와 일치하는지, `exp`·`nbf` 검증

## 3. 직접 발급하는 HS256 토큰 (단일 서비스)

인증 서버 없이 우리 서버가 로그인과 토큰 발급까지 할 때도 Resource Server를 쓸 수 있습니다.

```java
@Configuration
public class JwtConfig {

    private final SecretKey secretKey;

    public JwtConfig(JwtProperties properties) {
        byte[] bytes = Base64.getDecoder().decode(properties.secret());
        this.secretKey = new SecretKeySpec(bytes, "HmacSHA256");
    }

    @Bean
    public JwtDecoder jwtDecoder() {
        NimbusJwtDecoder decoder = NimbusJwtDecoder.withSecretKey(secretKey)
                .macAlgorithm(MacAlgorithm.HS256)
                .build();
        decoder.setJwtValidator(JwtValidators.createDefaultWithIssuer("myapp"));   // exp + iss 검증
        return decoder;
    }

    @Bean
    public JwtEncoder jwtEncoder() {
        return new NimbusJwtEncoder(new ImmutableSecret<>(secretKey));
        // Spring Security 7.0부터는 SecretKey·키 쌍을 받는 빌더 API도 제공
    }
}
```

### 토큰 발급
```java
@Service
@RequiredArgsConstructor
public class TokenService {
    private final JwtEncoder jwtEncoder;
    private final JwtProperties properties;

    public String createAccessToken(Long memberId, Role role) {
        Instant now = Instant.now();
        JwtClaimsSet claims = JwtClaimsSet.builder()
                .issuer("myapp")
                .subject(String.valueOf(memberId))
                .issuedAt(now)
                .expiresAt(now.plus(properties.accessTokenValidity()))
                .id(UUID.randomUUID().toString())
                .claim("roles", List.of(role.name()))          // ["USER"]
                .build();
        JwsHeader header = JwsHeader.with(MacAlgorithm.HS256).build();
        return jwtEncoder.encode(JwtEncoderParameters.from(header, claims)).getTokenValue();
    }
}
```

## 4. 클레임 → 권한 변환

기본 동작: **`scope`(또는 `scp`) 클레임**을 `SCOPE_` 접두사 권한으로 변환합니다.
```
"scope": "order:read order:write"  →  SCOPE_order:read, SCOPE_order:write
→ .requestMatchers(...).hasAuthority("SCOPE_order:read")
```

우리 토큰의 `roles` 클레임을 `ROLE_` 권한으로 쓰려면:
```java
@Bean
public JwtAuthenticationConverter jwtAuthenticationConverter() {
    JwtGrantedAuthoritiesConverter authorities = new JwtGrantedAuthoritiesConverter();
    authorities.setAuthoritiesClaimName("roles");     // 어떤 클레임을 읽을지
    authorities.setAuthorityPrefix("ROLE_");          // USER → ROLE_USER

    JwtAuthenticationConverter converter = new JwtAuthenticationConverter();
    converter.setJwtGrantedAuthoritiesConverter(authorities);
    converter.setPrincipalClaimName("sub");           // authentication.getName()으로 쓸 클레임
    return converter;
}
```
```java
.oauth2ResourceServer(oauth2 -> oauth2
        .jwt(jwt -> jwt.jwtAuthenticationConverter(jwtAuthenticationConverter()))
        .authenticationEntryPoint(jsonAuthenticationEntryPoint)     // 401 응답 커스터마이징
        .accessDeniedHandler(jsonAccessDeniedHandler))
```

> Keycloak은 역할을 `realm_access.roles`처럼 **중첩 클레임**에 넣습니다. 이럴 때는 `Converter<Jwt, Collection<GrantedAuthority>>`를 직접 구현해 넘깁니다.

## 5. 컨트롤러에서 사용

```java
@GetMapping("/api/me")
public JwtMeResponse me(@AuthenticationPrincipal Jwt jwt) {
    Long memberId = Long.valueOf(jwt.getSubject());
    List<String> roles = jwt.getClaimAsStringList("roles");
    return new JwtMeResponse(memberId, roles);   // record JwtMeResponse(Long id, List<String> roles)
}

// 또는
@GetMapping("/api/me2")
public String me2(JwtAuthenticationToken authentication) {
    return authentication.getName();      // principalClaimName (sub)
}
```

메서드 보안에서도 그대로:
```java
@PreAuthorize("#memberId.toString() == authentication.name or hasRole('ADMIN')")
public MemberResponse getMember(Long memberId) { ... }
```

## 6. 추가 검증 규칙: 블랙리스트, audience

```java
@Component
@RequiredArgsConstructor
public class BlacklistValidator implements OAuth2TokenValidator<Jwt> {
    private final AccessTokenBlacklist blacklist;

    @Override
    public OAuth2TokenValidatorResult validate(Jwt jwt) {
        if (jwt.getId() != null && blacklist.contains(jwt.getId())) {
            return OAuth2TokenValidatorResult.failure(
                    new OAuth2Error("invalid_token", "로그아웃된 토큰입니다.", null));
        }
        return OAuth2TokenValidatorResult.success();
    }
}
```
```java
decoder.setJwtValidator(new DelegatingOAuth2TokenValidator<>(
        JwtValidators.createDefaultWithIssuer("myapp"),
        new JwtClaimValidator<List<String>>("aud", aud -> aud != null && aud.contains("order-api")),
        blacklistValidator));
```

## 7. 비교 정리

| 항목 | 커스텀 필터 + jjwt | **Resource Server** |
|---|---|---|
| 토큰 추출·검증 필터 | 직접 | `BearerTokenAuthenticationFilter` |
| 401 응답 | 직접 | 표준 (`WWW-Authenticate`) + 커스터마이징 가능 |
| 외부 인증 서버, 공개키 교체 | 직접 구현 | `issuer-uri` 설정 |
| 권한 매핑 | 직접 | `JwtAuthenticationConverter` |
| principal | 직접 만든 객체 | `Jwt` |
| 테스트 | 토큰 직접 생성 | `jwt()` 요청 후처리기 (→ `08.시큐리티테스트.md`) |

### 불투명 토큰 (Opaque Token)
JWT가 아닌 랜덤 문자열 토큰은 **인증 서버의 introspection 엔드포인트**에 매번 물어봐서 검증합니다.
```yaml
spring.security.oauth2.resourceserver.opaquetoken:
  introspection-uri: https://auth.example.com/oauth2/introspect
  client-id: order-api
  client-secret: ${SECRET}
```
→ 즉시 무효화가 가능하지만 매 요청 네트워크 호출 (캐시로 완화)

## 8. 면접 질문

1. **OAuth2 Resource Server란?**
   → 액세스 토큰으로 보호되는 API 서버 역할로, Spring Security의 oauth2ResourceServer 설정을 쓰면 Bearer 토큰 추출, 서명·만료·발급자 검증, 권한 변환, 표준 401 응답을 제공받습니다.
2. **issuer-uri만 설정하면 어떻게 토큰을 검증하나요?**
   → 발급자의 OpenID 설정 문서에서 JWKS 주소를 찾아 공개키를 가져오고, 토큰 헤더의 kid로 키를 골라 서명을 검증하며 iss와 만료 시간을 확인합니다.
3. **JWT의 scope와 역할을 권한으로 바꾸는 방법은?**
   → 기본은 scope 클레임을 SCOPE_ 접두사 권한으로 바꾸고, JwtAuthenticationConverter와 JwtGrantedAuthoritiesConverter로 읽을 클레임과 접두사를 바꿀 수 있습니다.

---

## 핵심 정리
- `oauth2ResourceServer(o -> o.jwt(...))` = 필터·검증·401을 Spring이 제공
- 외부 인증 서버: `issuer-uri`(JWKS 자동, 키 교체 자동), `audiences`
- 직접 발급: `NimbusJwtEncoder`/`NimbusJwtDecoder.withSecretKey`, `JwtValidators.createDefaultWithIssuer`
- 권한: 기본 `SCOPE_`, `JwtAuthenticationConverter`로 `roles` → `ROLE_`
- principal = `Jwt`, 추가 검증은 `OAuth2TokenValidator`
