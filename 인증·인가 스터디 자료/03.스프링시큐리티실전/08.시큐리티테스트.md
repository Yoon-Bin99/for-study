# 08. Spring Security 테스트

> **학습 목표**
> - `spring-security-test`로 인증된 사용자를 흉내 내 컨트롤러를 테스트할 수 있다.
> - `@WithMockUser`, `user()`, `authentication()`, `jwt()`, `csrf()`를 상황에 맞게 사용할 수 있다.
> - 커스텀 principal용 테스트 애노테이션(`@WithSecurityContext`)을 만들 수 있다.
> - 인가 규칙(401/403)과 메서드 보안, 로그인 흐름을 테스트할 수 있다.

---

## 1. 준비

```groovy
testImplementation 'org.springframework.boot:spring-boot-starter-test'
testImplementation 'org.springframework.security:spring-security-test'
```

### 무엇을 테스트할까?
| 테스트 | 확인 내용 |
|---|---|
| **인가 규칙** | 비로그인 → 401, USER → 403, ADMIN → 200 |
| **소유자 검사** | 남의 리소스 → 404/403 |
| 로그인 | 올바른 비밀번호 → 토큰, 틀림 → 401 |
| 토큰 | 만료·위조 토큰 → 401 |
| CSRF | 세션 방식에서 토큰 없는 POST → 403 |

> 보안 테스트는 **"되는 것"보다 "안 되는 것"** 을 꼼꼼히 확인하는 것이 핵심입니다. 설정 한 줄 실수로 관리자 API가 열려도 기능 테스트는 모두 통과하기 때문입니다.

## 2. @WebMvcTest + 시큐리티 설정

`@WebMvcTest`는 컨트롤러 계층만 띄우지만 **`SecurityFilterChain` 빈은 직접 가져와야** 실제 설정대로 동작합니다.

```java
@WebMvcTest(OrderController.class)
@Import({SecurityConfig.class, JsonAuthenticationEntryPoint.class, JsonAccessDeniedHandler.class})
class OrderControllerTest {

    @Autowired MockMvc mockMvc;

    @MockitoBean OrderService orderService;          // Spring Boot 3.4+ (@MockBean은 deprecated)
    @MockitoBean JwtTokenProvider jwtTokenProvider;  // SecurityConfig가 의존하는 빈

    @Test
    void 비로그인이면_401() throws Exception {
        mockMvc.perform(get("/api/orders"))
               .andExpect(status().isUnauthorized())
               .andExpect(jsonPath("$.code").value("UNAUTHORIZED"));
    }
}
```
> Spring Boot 4에서는 `@WebMvcTest`의 패키지가 `org.springframework.boot.webmvc.test.autoconfigure`로 바뀌었습니다(테스트 모듈 분리).

## 3. 인증된 사용자 흉내 내기

### @WithMockUser: 가장 간단
```java
@Test
@WithMockUser(username = "user@example.com", roles = "USER")     // principal = Spring의 User 객체
void USER는_관리자_API_403() throws Exception {
    mockMvc.perform(get("/api/admin/members"))
           .andExpect(status().isForbidden());
}

@Test
@WithMockUser(roles = "ADMIN")
void ADMIN은_관리자_API_200() throws Exception {
    mockMvc.perform(get("/api/admin/members")).andExpect(status().isOk());
}
```
- `roles = "ADMIN"` → `ROLE_ADMIN`, `authorities = "member:read"` → 그대로
- 한계: principal이 **Spring의 `User`** 라서, 컨트롤러가 `@AuthenticationPrincipal AuthMember`를 받으면 **null**이 됩니다.

### 요청 후처리기: 커스텀 principal
```java
import static org.springframework.security.test.web.servlet.request.SecurityMockMvcRequestPostProcessors.*;

@Test
void 내_주문_조회() throws Exception {
    AuthMember member = new AuthMember(1L, Role.USER);
    var auth = UsernamePasswordAuthenticationToken.authenticated(
            member, null, List.of(new SimpleGrantedAuthority("ROLE_USER")));
    given(orderService.findByMember(1L)).willReturn(List.of());

    mockMvc.perform(get("/api/orders").with(authentication(auth)))
           .andExpect(status().isOk());

    then(orderService).should().findByMember(1L);     // 토큰 속 사용자 ID가 전달됐는지
}
```

| 후처리기 | 용도 |
|---|---|
| `user("email").roles("USER")` | 간단한 사용자 |
| `user(userDetails)` | `UserDetails` 구현체 (`CustomUserDetails`) |
| `authentication(auth)` | **임의의 Authentication** (커스텀 principal) |
| `jwt()` | Resource Server의 `JwtAuthenticationToken` |
| `oauth2Login()` | 소셜 로그인 사용자 |
| `csrf()` | CSRF 토큰 포함 |
| `anonymous()` | 익명 |

### 커스텀 애노테이션: @WithAuthMember
매번 Authentication을 만들기 번거로우면 애노테이션을 만듭니다.
```java
@Retention(RetentionPolicy.RUNTIME)
@WithSecurityContext(factory = WithAuthMemberSecurityContextFactory.class)
public @interface WithAuthMember {
    long id() default 1L;
    Role role() default Role.USER;
}

public class WithAuthMemberSecurityContextFactory implements WithSecurityContextFactory<WithAuthMember> {
    @Override
    public SecurityContext createSecurityContext(WithAuthMember annotation) {
        AuthMember principal = new AuthMember(annotation.id(), annotation.role());
        var auth = UsernamePasswordAuthenticationToken.authenticated(
                principal, null, List.of(new SimpleGrantedAuthority("ROLE_" + annotation.role().name())));
        SecurityContext context = SecurityContextHolder.createEmptyContext();
        context.setAuthentication(auth);
        return context;
    }
}
```
```java
@Test
@WithAuthMember(id = 7, role = Role.ADMIN)
void 관리자_회원_삭제() throws Exception {
    mockMvc.perform(delete("/api/admin/members/3")).andExpect(status().isNoContent());
}
```

## 4. Resource Server: jwt()

```java
@Test
void JWT_사용자() throws Exception {
    mockMvc.perform(get("/api/me")
                    .with(jwt()
                        .jwt(j -> j.subject("1").claim("roles", List.of("USER")))
                        .authorities(new SimpleGrantedAuthority("ROLE_USER"))))
           .andExpect(status().isOk())
           .andExpect(jsonPath("$.id").value(1));
}
```
> `jwt()`는 **토큰 디코딩을 건너뛰고** 인증 객체를 바로 넣습니다. 그래서 `JwtDecoder`가 필요 없고, `.authorities()`를 직접 지정해야 합니다(컨버터가 실행되지 않음). 컨버터까지 검증하려면 실제 토큰을 만들어 헤더로 보내세요.

## 5. CSRF 테스트 (세션 방식)

```java
@Test
@WithMockUser
void CSRF_토큰_없으면_403() throws Exception {
    mockMvc.perform(post("/posts").param("title", "t"))
           .andExpect(status().isForbidden());
}

@Test
@WithMockUser
void CSRF_토큰_있으면_성공() throws Exception {
    mockMvc.perform(post("/posts").param("title", "t").with(csrf()))
           .andExpect(status().is3xxRedirection());
}
```

## 6. 메서드 보안 테스트

```java
@SpringBootTest
class AdminMemberServiceTest {

    @Autowired AdminMemberService adminMemberService;

    @Test
    @WithMockUser(roles = "USER")
    void USER는_회원_삭제_불가() {
        assertThatThrownBy(() -> adminMemberService.deleteMember(1L))
                .isInstanceOf(AccessDeniedException.class);
    }

    @Test
    void 비로그인도_불가() {
        assertThatThrownBy(() -> adminMemberService.deleteMember(1L))
                .isInstanceOf(AuthenticationCredentialsNotFoundException.class);
    }
}
```

## 7. 통합 테스트: 실제 로그인 → 토큰 → API

```java
@SpringBootTest
@AutoConfigureMockMvc
@Transactional
class AuthFlowTest {

    @Autowired MockMvc mockMvc;
    @Autowired MemberRepository memberRepository;
    @Autowired PasswordEncoder passwordEncoder;
    @Autowired ObjectMapper objectMapper;

    @BeforeEach
    void setUp() {
        memberRepository.save(new Member("user@example.com", passwordEncoder.encode("password1234"), Role.USER));
    }

    @Test
    void 로그인_후_토큰으로_API_호출() throws Exception {
        String body = mockMvc.perform(post("/api/auth/login")
                        .contentType(MediaType.APPLICATION_JSON)
                        .content("""
                                {"email":"user@example.com","password":"password1234"}
                                """))
                .andExpect(status().isOk())
                .andExpect(cookie().httpOnly("refresh_token", true))
                .andReturn().getResponse().getContentAsString();

        String accessToken = objectMapper.readTree(body).get("accessToken").asText();

        mockMvc.perform(get("/api/orders").header(HttpHeaders.AUTHORIZATION, "Bearer " + accessToken))
               .andExpect(status().isOk());
    }

    @Test
    void 비밀번호_틀리면_401() throws Exception {
        mockMvc.perform(post("/api/auth/login")
                        .contentType(MediaType.APPLICATION_JSON)
                        .content("""
                                {"email":"user@example.com","password":"wrong"}
                                """))
               .andExpect(status().isUnauthorized());
    }

    @Test
    void 위조된_토큰은_401() throws Exception {
        mockMvc.perform(get("/api/orders").header(HttpHeaders.AUTHORIZATION, "Bearer abc.def.ghi"))
               .andExpect(status().isUnauthorized())
               .andExpect(jsonPath("$.code").value("INVALID_TOKEN"));
    }
}
```
> Redis를 쓰는 기능(Refresh, 블랙리스트)은 **Testcontainers**로 실제 Redis를 띄우거나, 테스트용으로 인터페이스를 분리해 인메모리 구현을 주입합니다.

## 8. 인가 규칙을 표로 테스트하기

```java
@ParameterizedTest
@CsvSource({
    "GET,    /api/products,       ANONYMOUS, 200",
    "GET,    /api/orders,         ANONYMOUS, 401",
    "GET,    /api/orders,         USER,      200",
    "GET,    /api/admin/members,  USER,      403",
    "GET,    /api/admin/members,  ADMIN,     200",
})
void 인가_규칙(String method, String url, String role, int expected) throws Exception {
    MockHttpServletRequestBuilder req = request(HttpMethod.valueOf(method), url);
    if (!role.equals("ANONYMOUS")) {
        req = req.with(user("u").roles(role));
    }
    mockMvc.perform(req).andExpect(status().is(expected));
}
```
→ 보안 정책이 바뀔 때 **표만 보고 리뷰**할 수 있어 실수를 줄입니다.

## 9. 면접 질문

1. **Spring Security가 적용된 컨트롤러는 어떻게 테스트하나요?**
   → spring-security-test의 @WithMockUser나 MockMvc 요청 후처리기(user, authentication, jwt, csrf)로 인증 상태를 만들고, 비로그인 401·권한 없음 403·정상 200을 각각 검증합니다.
2. **@WithMockUser의 한계는?**
   → principal이 Spring의 User 객체라서 커스텀 principal을 쓰는 컨트롤러에서는 값을 꺼낼 수 없으므로, authentication() 후처리기나 @WithSecurityContext 커스텀 애노테이션을 씁니다.
3. **보안 테스트에서 특히 중요한 것은?**
   → 정상 동작보다 접근이 거부되어야 하는 경우(비로그인, 다른 역할, 남의 리소스, 위조·만료 토큰)를 빠짐없이 검증하는 것입니다.

## 핵심 정리
- `@WebMvcTest` + `@Import(SecurityConfig)` + `@MockitoBean`으로 실제 보안 설정 테스트
- `@WithMockUser`(간단) / `with(authentication(...))`(커스텀 principal) / `@WithSecurityContext`(재사용) / `jwt()` / `csrf()`
- 메서드 보안: `@SpringBootTest` + `AccessDeniedException` 검증
- 통합: 로그인 → 토큰 → API, 위조·만료 토큰
- **"안 되는 것"을 표로 테스트**
