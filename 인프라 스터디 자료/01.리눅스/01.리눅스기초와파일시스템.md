# 01. 리눅스 기초와 파일 시스템

> **학습 목표**
> - 서버 운영체제로 리눅스를 쓰는 이유와 배포판의 차이를 설명할 수 있다.
> - 리눅스 디렉토리 구조(FHS)에서 주요 디렉토리의 용도를 말할 수 있다.
> - 파일·디렉토리를 다루는 기본 명령어와 리다이렉션·파이프를 사용할 수 있다.

---

## 1. 왜 서버는 리눅스인가?

| 이유 | 설명 |
|---|---|
| 무료·오픈소스 | 라이선스 비용 없음, 소스 공개 |
| 안정성 | 몇 년씩 재부팅 없이 운영 가능 |
| 원격 관리 | GUI 없이 **SSH + CLI**로 모든 작업 → 자동화 쉬움 |
| 생태계 | Docker, Kubernetes, 클라우드가 모두 리눅스 기반 |
| 가벼움 | 필요한 것만 설치 → 리소스 효율 |

### 커널과 배포판
- **리눅스 커널**: 운영체제의 핵심 (리누스 토르발스)
- **배포판 (Distribution)**: 커널 + 패키지 관리자 + 기본 도구를 묶은 것

| 계열 | 배포판 | 패키지 관리자 | 사용처 |
|---|---|---|---|
| Debian 계열 | **Ubuntu**, Debian | `apt` (.deb) | 개발·클라우드에서 가장 흔함 |
| Red Hat 계열 | RHEL, Rocky Linux, **Amazon Linux 2023**, Fedora | `dnf` / `yum` (.rpm) | 기업 서버, AWS 기본 AMI |
| 경량 | **Alpine** | `apk` | **도커 이미지** (수 MB) |

```bash
cat /etc/os-release     # 배포판 확인
uname -r                # 커널 버전
```

## 2. 터미널과 쉘

- **터미널**: 명령어를 입력하는 창
- **쉘 (Shell)**: 입력한 명령어를 해석해 커널에 전달하는 프로그램 (`bash`, `zsh`, `sh`)

```
user@server:~$ ls -al
 │      │    │  └── 명령어
 │      │    └── $ 일반 사용자 / # root
 │      └── 현재 위치 (~ = 홈 디렉토리)
 └── 사용자@호스트
```

### 명령어 구조
```bash
명령어 [옵션] [인자]
ls     -al    /var/log
```
- 짧은 옵션 `-a -l` = `-al`, 긴 옵션 `--all`
- 도움말: `man ls`, `ls --help`

## 3. 디렉토리 구조 (FHS)

리눅스는 **모든 것이 `/`(루트) 아래 하나의 트리**입니다. 윈도우처럼 C:, D: 드라이브가 없습니다.

```
/
├── bin, sbin    기본 명령어 (ls, cp) / 관리자 명령어 (현대 배포판은 /usr/bin 링크)
├── etc          ★ 설정 파일 (nginx.conf, hosts, passwd)
├── home         일반 사용자 홈 (/home/ubuntu)
├── root         root 사용자 홈
├── var          ★ 자주 바뀌는 데이터
│   ├── log      ★ 로그 (/var/log/nginx/access.log)
│   └── lib      프로그램 데이터 (/var/lib/docker, /var/lib/mysql)
├── tmp          임시 파일 (재부팅 시 삭제될 수 있음)
├── usr          사용자 프로그램 (/usr/bin, /usr/local)
├── opt          별도 설치 프로그램 (/opt/app)
├── dev          장치 파일 (/dev/sda, /dev/null)
├── proc         ★ 프로세스·커널 정보 (가상 파일시스템, /proc/cpuinfo)
├── sys          장치·커널 정보 (가상)
├── mnt, media   마운트 지점
└── boot         부팅 파일, 커널 이미지
```

> **"리눅스에서는 모든 것이 파일이다."** 장치(`/dev/sda`), 프로세스 정보(`/proc/1234`), 소켓도 파일처럼 다룹니다.

### 경로
| 표현 | 의미 |
|---|---|
| `/home/ubuntu/app` | **절대 경로** (루트부터) |
| `./app`, `app` | **상대 경로** (현재 위치 기준) |
| `.` / `..` | 현재 디렉토리 / 상위 디렉토리 |
| `~` | 홈 디렉토리 |
| `-` | 직전 디렉토리 (`cd -`) |

## 4. 기본 명령어

### 이동·조회
```bash
pwd                     # 현재 위치
cd /var/log             # 이동
ls -al                  # 숨김 파일 포함 상세 목록
ls -lh                  # 크기를 KB, MB로
tree -L 2               # 트리 형태 (설치 필요)
```

### 파일·디렉토리 조작
```bash
mkdir -p app/logs       # 중간 디렉토리까지 생성
touch a.txt             # 빈 파일 생성 (또는 수정 시각 갱신)
cp a.txt b.txt          # 복사
cp -r dir1 dir2         # 디렉토리 복사
mv a.txt /tmp/          # 이동 / 이름 변경
rm a.txt                # 삭제 (휴지통 없음!)
rm -rf dir              # 디렉토리 강제 삭제 — 매우 주의
ln -s /opt/app-1.2 /opt/app   # 심볼릭 링크 (배포 버전 전환에 활용)
```

> `rm -rf`는 되돌릴 수 없습니다. 특히 변수로 경로를 만들 때 `rm -rf $DIR/` 에서 `$DIR`이 비어 있으면 `rm -rf /`가 됩니다.

### 파일 내용 보기
```bash
cat app.log             # 전체 출력
less app.log            # 페이지 단위 (q 종료, /검색)
head -n 20 app.log      # 앞 20줄
tail -n 100 app.log     # 뒤 100줄
tail -f app.log         # ★ 실시간으로 추가되는 로그 보기
```

### 검색
```bash
find /var/log -name "*.log" -mtime -1     # 1일 이내 수정된 .log 파일
find . -type f -size +100M                # 100MB 넘는 파일
grep "ERROR" app.log                       # 문자열 검색
grep -rn "password" ./config               # 하위 디렉토리까지, 줄 번호 포함
grep -i -C 3 "exception" app.log           # 대소문자 무시, 앞뒤 3줄 함께
which java                                 # 명령어 위치
```

### 디스크·용량
```bash
df -h                   # 파일시스템별 디스크 사용량 ("디스크 꽉 찼다" 확인)
du -sh /var/log/*       # 디렉토리별 용량
free -h                 # 메모리 사용량
```

### 압축
```bash
tar -czvf backup.tar.gz ./app      # 압축 (c 생성, z gzip, v 진행 표시, f 파일)
tar -xzvf backup.tar.gz            # 해제 (x)
zip -r app.zip ./app; unzip app.zip
```

## 5. 리다이렉션과 파이프

| 기호 | 의미 | 예 |
|---|---|---|
| `>` | 출력을 파일로 (**덮어쓰기**) | `echo hi > a.txt` |
| `>>` | 출력을 파일로 (**이어쓰기**) | `echo hi >> a.txt` |
| `<` | 파일을 입력으로 | `mysql db < dump.sql` |
| `2>` | **에러 출력**을 파일로 | `cmd 2> err.log` |
| `2>&1` | 에러 출력을 표준 출력과 합침 | `cmd > all.log 2>&1` |
| `\|` | 앞 명령 출력 → 뒤 명령 입력 (**파이프**) | `ps aux \| grep java` |
| `/dev/null` | 버리는 곳 | `cmd > /dev/null 2>&1` |

표준 스트림: **0 = stdin**, **1 = stdout**, **2 = stderr**

### 파이프 조합 예
```bash
# 접근 로그에서 가장 많이 요청한 IP 상위 10개
cat access.log | awk '{print $1}' | sort | uniq -c | sort -rn | head -10

# 오늘 발생한 ERROR 개수
grep "2026-11-09" app.log | grep -c "ERROR"

# 백그라운드로 Spring Boot 실행, 로그는 파일로
nohup java -jar app.jar > app.log 2>&1 &
```

| 도구 | 용도 |
|---|---|
| `awk` | 열 단위 처리 (`awk '{print $1}'` 첫 번째 열) |
| `sed` | 문자열 치환 (`sed -i 's/old/new/g' file`) |
| `sort`, `uniq` | 정렬, 중복 제거 (`uniq`는 정렬된 입력 필요) |
| `wc -l` | 줄 수 |
| `cut -d',' -f2` | 구분자로 자르기 |
| `xargs` | 입력을 인자로 변환 (`find . -name "*.tmp" \| xargs rm`) |

## 6. 텍스트 편집기: vim 최소한

서버에는 GUI 편집기가 없으므로 `vim`(또는 `nano`) 기본 조작은 필수입니다.

| 모드 | 진입 | 할 일 |
|---|---|---|
| 일반 모드 | `Esc` | 이동, 삭제, 복사 |
| 입력 모드 | `i` (커서 앞), `a` (뒤), `o` (아래 줄) | 글자 입력 |
| 명령 모드 | `:` | 저장·종료 |

| 명령 | 동작 |
|---|---|
| `:w` / `:q` / `:wq` / `:q!` | 저장 / 종료 / 저장 후 종료 / **저장 안 하고 강제 종료** |
| `dd` / `yy` / `p` | 줄 삭제 / 줄 복사 / 붙여넣기 |
| `u` / `Ctrl + r` | 실행 취소 / 다시 실행 |
| `/word` → `n` | 검색 → 다음 결과 |
| `gg` / `G` | 맨 위 / 맨 아래 |
| `:%s/old/new/g` | 전체 치환 |
| `:set nu` | 줄 번호 표시 |

## 8. 면접 질문

1. **`/etc`, `/var/log`, `/proc` 디렉토리의 용도는?**
   → `/etc`는 시스템·프로그램 설정 파일, `/var/log`는 로그, `/proc`는 프로세스와 커널 정보를 파일 형태로 보여 주는 가상 파일시스템입니다.
2. **`>`와 `>>`의 차이, `2>&1`의 의미는?**
   → `>`는 덮어쓰기, `>>`는 이어쓰기이고, `2>&1`은 표준 에러를 표준 출력과 같은 곳으로 보낸다는 뜻입니다.
3. **실시간으로 로그를 확인하려면?**
   → `tail -f 파일명`을 쓰고, 특정 단어만 보려면 `tail -f app.log | grep ERROR`처럼 파이프로 필터링합니다.
4. **디스크가 가득 찼을 때 어떻게 확인하나요?**
   → `df -h`로 어느 파일시스템이 찼는지 보고, `du -sh /*` 등으로 큰 디렉토리를 좁혀 갑니다. 주로 로그나 도커 이미지가 원인입니다.

## 핵심 정리
- 서버 = 리눅스 (Ubuntu / Amazon Linux / 도커는 Alpine)
- 모든 것은 `/` 아래 트리, 설정은 `/etc`, 로그는 `/var/log`
- 필수 명령어: `ls cd cp mv rm find grep tail -f df du`
- 리다이렉션 `> >> 2>&1`, 파이프 `|`로 명령어 조합
