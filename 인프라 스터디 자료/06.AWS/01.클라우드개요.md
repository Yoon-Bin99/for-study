# 01. 클라우드 개요

> **학습 목표**
> - 온프레미스 대비 클라우드의 장점과 고려 사항을 설명할 수 있다.
> - IaaS, PaaS, SaaS(+ 서버리스)를 구분할 수 있다.
> - AWS 리전, 가용 영역(AZ), 엣지 로케이션의 관계를 설명할 수 있다.
> - 공동 책임 모델과 비용 구조를 설명할 수 있다.

---

## 1. 온프레미스 vs 클라우드

| 비교 | 온프레미스 (On-Premise) | 클라우드 |
|---|---|---|
| 서버 준비 | 구매·설치에 **수 주~수 개월** | **수 분** |
| 비용 | 초기 투자(CAPEX) 큼 | **쓴 만큼 지불**(OPEX) |
| 용량 | 최대 트래픽 기준으로 미리 구매 → 평소엔 낭비 | **필요할 때 늘리고 줄임** (탄력성) |
| 관리 | 하드웨어·전력·네트워크 직접 | 물리 인프라는 클라우드 사업자 |
| 글로벌 | 해외 데이터센터 구축 어려움 | 리전 선택만으로 |
| 고려 사항 | 통제권 완전 | 비용 관리 실패 시 과금 폭탄, 벤더 종속(Lock-in), 규제 |

### 클라우드의 핵심 특성
- **온디맨드 셀프서비스**: 콘솔·API로 즉시 생성
- **탄력성 (Elasticity)**: 부하에 따라 자동 확장·축소
- **종량제**: 초 단위·시간 단위 과금
- **고가용성**: 여러 데이터센터에 분산 배치 가능

## 2. 서비스 모델

```
          온프레미스    IaaS        PaaS        SaaS
애플리케이션   직접         직접         직접         제공
데이터        직접         직접         직접         제공
런타임        직접         직접         제공         제공
OS           직접         직접         제공         제공
가상화        직접         제공         제공         제공
서버·스토리지  직접         제공         제공         제공
네트워크      직접         제공         제공         제공
```

| 모델 | 사용자가 관리 | 예 |
|---|---|---|
| **IaaS** (Infrastructure) | OS부터 위 전부 | **EC2**, EBS, VPC |
| **PaaS** (Platform) | 코드와 데이터만 | Elastic Beanstalk, **RDS**(DB 관리), Heroku, Railway, Vercel |
| **SaaS** (Software) | 사용만 | Gmail, Notion, Slack |
| **서버리스 / FaaS** | **함수 코드만**, 요청 단위 과금, 0까지 축소 | **Lambda**, Fargate(컨테이너 서버리스), DynamoDB |

> 위로 갈수록(SaaS 쪽) **관리 부담은 줄고, 통제권과 유연성도 줄어듭니다.** 관리형 서비스(RDS, EKS, ElastiCache)를 쓰면 백업·패치·장애 조치를 AWS에 맡기고 서비스 개발에 집중할 수 있습니다.

## 3. AWS 글로벌 인프라

```
리전 (Region): ap-northeast-2 (서울)
+─────────────────────────────────────────────────+
|  AZ: ap-northeast-2a   AZ: 2b   AZ: 2c   AZ: 2d |
|  [데이터센터들]        [ ... ]  [ ... ]  [ ... ]  |
|        └──── 저지연 전용 네트워크로 연결 ────┘       |
+─────────────────────────────────────────────────+
엣지 로케이션: 전 세계 수백 곳 (CloudFront CDN, Route 53)
```

| 개념 | 설명 | 의미 |
|---|---|---|
| **리전 (Region)** | 지리적으로 분리된 지역 (서울, 도쿄, 버지니아) | 데이터 주권(법규), 사용자와의 거리, 서비스·가격 차이 |
| **가용 영역 (AZ)** | 리전 안에서 **물리적으로 분리된 하나 이상의 데이터센터** (전력·네트워크 독립) | **고가용성의 기본 단위** — 한 AZ가 장애 나도 다른 AZ는 정상 |
| **엣지 로케이션** | 사용자 가까이의 캐시·DNS 거점 | CloudFront, Route 53 지연 감소 |

> **고가용성 설계 원칙: 최소 2개 이상의 AZ에 분산**합니다. (ALB, EC2 Auto Scaling, RDS Multi-AZ, EKS 노드)

### 리전 선택 기준
1. **규정 준수** (개인정보는 국내 저장 등)
2. **사용자와의 거리** (지연 시간)
3. 필요한 **서비스 지원 여부** (신규 서비스는 미국 리전부터)
4. **가격** (리전마다 다름)

## 4. 공동 책임 모델 (Shared Responsibility Model)

| AWS 책임: 클라우드 **의** 보안 | 고객 책임: 클라우드 **안의** 보안 |
|---|---|
| 데이터센터 물리 보안 | **IAM 권한 관리** |
| 하드웨어, 네트워크 인프라 | **보안 그룹, 네트워크 설정** |
| 하이퍼바이저 | EC2 **OS 패치** |
| 관리형 서비스의 기반 운영 | **데이터 암호화**, 백업 |
| | 애플리케이션 보안 |

> 관리형 서비스일수록 AWS 책임 범위가 넓어집니다. (EC2: OS 패치가 고객 책임 / RDS: DB 엔진 패치는 AWS가 지원, 접근 제어는 고객)
> S3 버킷을 public으로 잘못 열어 데이터가 유출되는 사고는 **고객 책임**입니다.

## 6. 비용 구조와 절약

### 과금의 기본
- **컴퓨팅**: 실행 시간(초·시간) × 인스턴스 크기
- **스토리지**: GB-월
- **데이터 전송**: **들어오는(Inbound) 트래픽은 대부분 무료, 나가는(Outbound) 트래픽은 유료**, AZ 간·리전 간 전송도 유료
- 요청 수 (S3, Lambda, API Gateway)

### 숨은 비용 주의
| 항목 | 설명 |
|---|---|
| **NAT 게이트웨이** | 시간당 요금 + 처리 데이터 요금 → 생각보다 비쌈 |
| **퍼블릭 IPv4 주소** | 2024년부터 사용 중인 공인 IPv4에 시간당 과금 |
| 로드밸런서 | 켜 두기만 해도 시간당 과금 |
| 미사용 EBS·스냅샷, 꺼 둔 RDS 자동 재시작 | 잊어버린 리소스 |
| CloudWatch 로그 저장 | 보존 기간 미설정 시 계속 쌓임 |

### 절약 방법
| 방법 | 설명 |
|---|---|
| **Savings Plans / 예약 인스턴스** | 1년·3년 약정으로 크게 할인 |
| **스팟 인스턴스** | 남는 용량을 대폭 할인, 대신 **2분 전 통보 후 회수**될 수 있음 → 배치, 무상태 워커 |
| 적정 크기 (Right-sizing) | 사용률이 낮은 인스턴스 축소 |
| Graviton (ARM) | x86 대비 가격 대비 성능 우수 |
| 스케줄링 | 개발 환경은 업무 시간 외 중지 |
| **AWS Budgets 알람** | 예산 초과 시 이메일 알림 — **계정 만들자마자 설정** |

> 학습용 계정은 **루트 계정 MFA 설정 + Budgets 알람 설정**을 가장 먼저 하세요. 실습 후 리소스 삭제를 잊는 것이 가장 흔한 과금 원인입니다.

## 7. 면접 질문

1. **IaaS, PaaS, SaaS의 차이는?**
   → IaaS는 가상 서버·네트워크 같은 인프라를, PaaS는 런타임까지 관리된 플랫폼을, SaaS는 완성된 소프트웨어를 제공하며, 위로 갈수록 사용자의 관리 범위가 줄어듭니다.
2. **리전과 가용 영역의 차이는?**
   → 리전은 지리적으로 분리된 지역이고, 가용 영역은 리전 안에서 전력·네트워크가 독립된 데이터센터 묶음입니다. 고가용성을 위해 여러 AZ에 분산 배치합니다.
3. **공동 책임 모델이란?**
   → AWS는 물리 인프라와 기반 서비스의 보안을, 고객은 IAM·네트워크 설정·OS 패치·데이터 암호화 등 클라우드 안에서 구성한 것의 보안을 책임진다는 모델입니다.

## 핵심 정리
- 클라우드 = 온디맨드 + 탄력성 + 종량제
- IaaS(EC2) / PaaS(RDS, Beanstalk) / SaaS / 서버리스(Lambda, Fargate)
- 리전 ⊃ AZ(고가용성 단위), 최소 2개 AZ 분산
- 공동 책임: AWS = 클라우드의 보안, 고객 = 클라우드 안의 보안
- 아웃바운드·NAT·퍼블릭 IPv4 비용 주의, Budgets 알람 필수
