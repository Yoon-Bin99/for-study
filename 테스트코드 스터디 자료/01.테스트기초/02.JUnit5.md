# 02. JUnit 5 (Jupiter)

> **학습 목표**
> - JUnit 5의 구조(Platform, Jupiter, Vintage)와 기본 애노테이션을 사용할 수 있다.
> - 테스트 생명주기(`@BeforeEach`, `@BeforeAll`)와 인스턴스 생성 방식을 이해한다.
> - `@ParameterizedTest`, `@Nested`, `@DisplayName`으로 읽기 좋은 테스트를 작성할 수 있다.
> - 예외·타임아웃 테스트와 확장 모델을 안다.

---

## 1. JUnit 5 구조

```
JUnit 5 = JUnit Platform + JUnit Jupiter + JUnit Vintage
 ├─ Platform: 테스트를 찾고 실행하는 기반 (IDE·Gradle이 사용)
 ├─ Jupiter : JUnit 5 테스트 작성 API (@Test, @BeforeEach ...)  ← 우리가 쓰는 것
 └─ Vintage : JUnit 3·4 테스트 실행 지원
```
- `spring-boot-starter-test`에 포함 (JUnit, AssertJ, Mockito, Hamcrest, JsonPath)
- **JUnit 6** (2025.9): Java 17 필수, 모든 모듈의 버전 통일. Jupiter API(`org.junit.jupiter.api`)는 거의 그대로라 이 문서 내용이 그대로 적용됩니다. Spring Boot 4가 JUnit 6을 기본으로 사용합니다.

```groovy
dependencies {
    testImplementation 'org.springframework.boot:spring-boot-starter-test'
    testRuntimeOnly 'org.junit.platform:junit-platform-launcher'
}
test {
    useJUnitPlatform()
}
```

## 2. 기본 애노테이션

```java
class CalculatorTest {

    private Calculator calculator;

    @BeforeAll
    static void beforeAll() { }               // 클래스 전체에서 한 번 (static)

    @BeforeEach
    void setUp() {                             // 각 테스트 전마다
        calculator = new Calculator();
    }

    @Test
    @DisplayName("두 수를 더한다")
    void add() {
        assertThat(calculator.add(2, 3)).isEqualTo(5);
    }

    @Test
    @Disabled("버그 #123 수정 후 활성화")
    void divide() { }

    @AfterEach
    void tearDown() { }                        // 각 테스트 후

    @AfterAll
    static void afterAll() { }
}
```
| JUnit 4 | JUnit 5 |
|---|---|
| `@Before`, `@After` | `@BeforeEach`, `@AfterEach` |
| `@BeforeClass` | `@BeforeAll` |
| `@Ignore` | `@Disabled` |
| `@RunWith(SpringRunner.class)` | `@ExtendWith(SpringExtension.class)` (스프링 테스트 애노테이션에 포함) |
| `public` 필수 | 접근 제어자 생략 가능 (package-private) |

### 테스트 인스턴스 생명주기
- 기본: **테스트 메서드마다 새 인스턴스** 생성 → 필드 상태가 공유되지 않음 (독립성)
- `@TestInstance(Lifecycle.PER_CLASS)`: 클래스당 하나 → `@BeforeAll`을 static 없이 쓸 수 있지만 상태 공유 주의

## 3. 예외 테스트

```java
@Test
void 배송된_주문은_취소할_수_없다() {
    Order order = shippedOrder();

    // JUnit 방식
    IllegalStateException e = assertThrows(IllegalStateException.class, order::cancel);
    assertEquals("배송된 주문은 취소 불가", e.getMessage());

    // AssertJ 방식 (권장, → 03.AssertJ.md)
    assertThatThrownBy(order::cancel)
            .isInstanceOf(IllegalStateException.class)
            .hasMessageContaining("취소 불가");
}
```

## 4. `@DisplayName`과 `@Nested`

```java
@DisplayName("주문")
class OrderTest {

    @Nested
    @DisplayName("취소할 때")
    class Cancel {

        @Test
        @DisplayName("배송 전이면 취소 상태가 된다")
        void beforeShipping() { ... }

        @Test
        @DisplayName("배송 후면 예외가 발생한다")
        void afterShipping() { ... }
    }

    @Nested
    @DisplayName("총액을 계산할 때")
    class TotalPrice { ... }
}
```
```
주문
 ├─ 취소할 때
 │   ├─ ✔ 배송 전이면 취소 상태가 된다
 │   └─ ✔ 배송 후면 예외가 발생한다
 └─ 총액을 계산할 때 ...
```
> 메서드 이름 자체를 한글로 쓰는 방식(`void 배송_전이면_취소된다()`)도 국내에서 많이 씁니다. 팀 컨벤션을 따르세요.

## 5. 파라미터화 테스트 `@ParameterizedTest`

같은 로직을 **여러 입력값**으로 검증 (경계값 테스트에 최적)
```java
@ParameterizedTest(name = "수량 {0}개는 유효하지 않다")
@ValueSource(ints = {0, -1, 101})
void invalidQuantity(int quantity) {
    assertThatThrownBy(() -> new OrderLine(productId, quantity))
            .isInstanceOf(IllegalArgumentException.class);
}

@ParameterizedTest
@CsvSource({
        "10000, BRONZE, 10000",
        "10000, SILVER, 9500",
        "10000, GOLD,   9000"
})
void discountByGrade(long price, Grade grade, long expected) {
    assertThat(discountPolicy.apply(price, grade)).isEqualTo(expected);
}

@ParameterizedTest
@EnumSource(value = OrderStatus.class, names = {"SHIPPED", "DELIVERED"})
void cannotCancel(OrderStatus status) { ... }

@ParameterizedTest
@MethodSource("provideOrders")                // 복잡한 객체
void totalPrice(Order order, long expected) { ... }

static Stream<Arguments> provideOrders() {
    return Stream.of(
            Arguments.of(orderWith(1000, 2), 2000L),
            Arguments.of(orderWith(500, 0), 0L));
}

@ParameterizedTest
@NullAndEmptySource
@ValueSource(strings = {" ", "\t"})
void blankName(String name) { ... }
```

## 6. 그 밖의 기능

```java
@RepeatedTest(10)                          // 10번 반복 (불안정한 테스트 탐지)
void repeated() { }

@Test
@Timeout(value = 2, unit = TimeUnit.SECONDS)
void fast() { }

assertTimeout(Duration.ofMillis(500), () -> service.heavy());

@Tag("slow")                               // gradle test { useJUnitPlatform { excludeTags 'slow' } }
@Test void slowTest() { }

assumeTrue(System.getenv("CI") != null);   // 조건이 거짓이면 실패가 아니라 "건너뜀"

@EnabledOnOs(OS.LINUX)
@EnabledIfEnvironmentVariable(named = "DOCKER", matches = "true")

assertAll("주문 응답",                      // 실패해도 모든 검증을 실행하고 한 번에 보고
        () -> assertEquals(1L, res.id()),
        () -> assertEquals("PAID", res.status()));
```

### 실행 순서
- 기본 순서는 **정해져 있지만 의도적으로 예측 불가** → 테스트끼리 순서에 의존하면 안 됨
- `@TestMethodOrder(OrderAnnotation.class)` + `@Order(1)` 로 지정 가능 (시나리오 테스트에서만 제한적으로)

## 7. 확장 모델 (Extension)

JUnit 4의 Runner·Rule을 대체합니다.
```java
@ExtendWith(MockitoExtension.class)         // Mockito (@Mock, @InjectMocks)
@ExtendWith(SpringExtension.class)          // 스프링 (@SpringBootTest 등에 이미 포함)
@Testcontainers                             // Testcontainers 확장
```
직접 만들기: `BeforeEachCallback`, `ParameterResolver` 등을 구현 (예: 테스트마다 DB 정리)

## 8. 면접 질문

1. **JUnit 5의 구성은?**
   → 테스트 실행 기반인 Platform, 테스트 작성 API인 Jupiter, 이전 버전 테스트를 실행하는 Vintage로 구성됩니다.
2. **`@BeforeEach`와 `@BeforeAll`의 차이는?**
   → BeforeEach는 각 테스트 메서드 실행 전마다, BeforeAll은 클래스의 모든 테스트 전에 한 번 실행되며 기본적으로 static이어야 합니다.
3. **테스트마다 인스턴스를 새로 만드는 이유는?**
   → 필드 상태가 테스트 간에 공유되지 않도록 해 테스트 독립성을 보장하기 위해서입니다.
4. **`@ParameterizedTest`는 언제 쓰나요?**
   → 같은 로직을 여러 입력값으로 검증할 때, 특히 경계값이나 enum별 동작을 확인할 때 중복 없이 작성하기 위해 사용합니다.

---

## 핵심 정리
- JUnit 5 = Platform + **Jupiter** + Vintage (JUnit 6도 Jupiter API 동일)
- 생명주기: `@BeforeAll`(1번, static) / `@BeforeEach`(매번), **테스트마다 새 인스턴스**
- `@DisplayName` + `@Nested`로 명세처럼
- **`@ParameterizedTest`** (`@ValueSource`, `@CsvSource`, `@MethodSource`)로 경계값 검증
- 테스트 순서에 의존하지 않기
