# 03. AssertJ

> **학습 목표**
> - AssertJ가 JUnit 기본 assertion보다 좋은 이유를 설명할 수 있다.
> - 문자열·숫자·컬렉션·객체·예외 검증 메서드를 사용할 수 있다.
> - `extracting`, `usingRecursiveComparison`, `SoftAssertions` 같은 고급 기능을 활용할 수 있다.

---

## 1. 왜 AssertJ인가?

```java
// JUnit 기본
assertEquals(3, orders.size());          // (기대값, 실제값) 순서 헷갈림
assertTrue(name.startsWith("kim"));      // 실패 메시지: "expected: <true> but was: <false>" → 무슨 값인지 모름

// AssertJ
assertThat(orders).hasSize(3);
assertThat(name).startsWith("kim");      // 실패 메시지: Expecting actual: "lee" to start with: "kim"
```
| 장점 | 설명 |
|---|---|
| **메서드 체이닝** | `assertThat(x).isNotNull().startsWith("a").hasSize(5)` |
| IDE 자동 완성 | `assertThat(list).` 다음에 컬렉션용 메서드만 제안 |
| **읽기 쉬운 실패 메시지** | 실제 값과 기대 값을 자세히 출력 |
| 풍부한 API | 컬렉션 필터링·추출, 재귀 비교, 예외 |

```java
import static org.assertj.core.api.Assertions.*;   // spring-boot-starter-test에 포함
```

## 2. 기본 검증

```java
// 동등성·null
assertThat(order.getStatus()).isEqualTo(OrderStatus.PAID);
assertThat(member).isNotNull();
assertThat(optional).isPresent().contains(member);  // Optional
assertThat(optional).isEmpty();

// 문자열
assertThat(email)
        .isNotBlank()
        .contains("@")
        .endsWith(".com")
        .matches("^[\\w.]+@[\\w.]+$");
assertThat(message).isEqualToIgnoringCase("ok");

// 숫자
assertThat(price).isPositive().isBetween(1000L, 5000L);
assertThat(rate).isCloseTo(0.1, within(0.001));     // 부동소수점

// boolean
assertThat(order.isCancelable()).isTrue();

// 날짜
assertThat(order.getCreatedAt()).isBefore(LocalDateTime.now()).isAfter(start);
```

## 3. 컬렉션

```java
List<String> names = List.of("kim", "lee", "park");

assertThat(names)
        .hasSize(3)
        .contains("kim", "lee")                 // 포함 (순서 무관)
        .containsExactly("kim", "lee", "park")  // 정확히 이 순서로
        .containsExactlyInAnyOrder("park", "kim", "lee")
        .doesNotContain("choi")
        .allMatch(n -> n.length() >= 3);

assertThat(emptyList).isEmpty();
assertThat(map).containsEntry("kim", 30).containsKey("lee");
```

### `extracting`: 객체 리스트에서 필드만 뽑아 검증 ★
```java
List<Order> orders = orderRepository.findByMemberId(memberId);

assertThat(orders)
        .extracting("orderNo", "status")                      // 필드 이름(리플렉션)
        .containsExactlyInAnyOrder(
                tuple("ORD-1", OrderStatus.PAID),
                tuple("ORD-2", OrderStatus.CANCELED));

assertThat(orders)
        .extracting(Order::getTotalPrice)                     // 메서드 참조 (타입 안전, 권장)
        .containsExactly(10_000L, 20_000L);

assertThat(orders)
        .filteredOn(o -> o.getStatus() == OrderStatus.PAID)
        .hasSize(1)
        .first()
        .extracting(Order::getOrderNo)
        .isEqualTo("ORD-1");
```

## 4. 객체 비교

```java
// equals를 구현하지 않은 객체를 필드 단위로 비교
assertThat(actualResponse)
        .usingRecursiveComparison()
        .ignoringFields("id", "createdAt")          // 매번 바뀌는 값 제외
        .isEqualTo(expectedResponse);

// 일부 필드만 확인
assertThat(member)
        .hasFieldOrPropertyWithValue("name", "kim")
        .extracting(Member::getEmail, Member::getGrade)
        .containsExactly("kim@shop.com", Grade.GOLD);

// 타입
assertThat(policy).isInstanceOf(RateDiscountPolicy.class);
```
> `isEqualTo`는 `equals()`를 사용합니다. 엔티티처럼 `equals`가 ID 기반이거나 구현되지 않은 객체는 `usingRecursiveComparison`이나 `extracting`으로 비교하세요.

## 5. 예외 검증

```java
assertThatThrownBy(() -> stockService.decrease(productId, 999))
        .isInstanceOf(BusinessException.class)
        .hasMessageContaining("재고")
        .extracting("errorCode")
        .isEqualTo(ErrorCode.OUT_OF_STOCK);

assertThatExceptionOfType(IllegalArgumentException.class)
        .isThrownBy(() -> new Money(-1))
        .withMessage("금액은 0 이상이어야 합니다.");

assertThatIllegalStateException().isThrownBy(order::cancel);

assertThatNoException().isThrownBy(() -> validator.validate(request));

// catchThrowable: given-when-then 구분을 명확하게
Throwable thrown = catchThrowable(() -> order.cancel());   // when
assertThat(thrown).isInstanceOf(IllegalStateException.class);   // then
```

## 6. SoftAssertions: 여러 개를 모두 검증

일반 assertion은 **첫 실패에서 멈춥니다.** 응답의 여러 필드를 한 번에 확인하고 싶을 때:
```java
SoftAssertions.assertSoftly(softly -> {
    softly.assertThat(response.id()).isEqualTo(1L);
    softly.assertThat(response.status()).isEqualTo("PAID");
    softly.assertThat(response.totalPrice()).isEqualTo(30_000L);
});   // 실패한 항목을 모두 모아서 보고
```

## 7. 자주 하는 실수

```java
assertThat(orders.size() == 3);         // ❌ 검증 메서드를 호출하지 않음 → 항상 통과!
assertThat(orders.size() == 3).isTrue(); // △ 실패 메시지가 "expected true"
assertThat(orders).hasSize(3);          // ✅

assertThat(actual).isEqualTo(expected);    // ✅ actual을 assertThat에
assertThat(expected).isEqualTo(actual);    // ❌ 실패 메시지가 거꾸로 나옴
```

## 8. 면접 질문

1. **AssertJ를 사용하는 이유는?**
   → 메서드 체이닝으로 가독성이 좋고, 타입에 맞는 검증 메서드를 IDE가 제안하며, 실패 메시지에 실제 값이 자세히 나와 원인 파악이 빠르기 때문입니다.
2. **`isEqualTo`와 `usingRecursiveComparison`의 차이는?**
   → isEqualTo는 equals 메서드로 비교하고, usingRecursiveComparison은 equals와 무관하게 필드 값을 재귀적으로 비교하며 특정 필드를 제외할 수 있습니다.

---

## 핵심 정리
- `assertThat(실제값).검증()` — **체이닝 + 친절한 실패 메시지**
- 컬렉션: `containsExactly`, `containsExactlyInAnyOrder`, **`extracting` + `tuple`**
- 객체: `usingRecursiveComparison().ignoringFields(...)`
- 예외: `assertThatThrownBy(...).isInstanceOf(...).hasMessageContaining(...)`
- `assertThat(조건)`만 쓰고 검증 메서드를 빠뜨리지 않기
