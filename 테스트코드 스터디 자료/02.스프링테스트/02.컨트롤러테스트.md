# 02. 컨트롤러 테스트 (@WebMvcTest)

> **학습 목표**
> - `@WebMvcTest`와 MockMvc로 요청 매핑, 요청 검증, 응답 JSON, 예외 응답을 테스트할 수 있다.
> - AssertJ 기반 `MockMvcTester`(Spring 6.2+)를 사용할 수 있다.
> - Spring Security가 적용된 컨트롤러를 테스트할 수 있다.
> - 실제 HTTP 요청 테스트(`RestTestClient`)와 차이를 이해한다.

---

## 1. 컨트롤러 테스트에서 검증할 것

| 검증 항목 | 예 |
|---|---|
| URL·HTTP 메서드 매핑 | `POST /api/orders` |
| 요청 바인딩·**입력 검증** | 수량 0이면 400 |
| 응답 상태 코드·JSON 구조 | 201, `$.id`, `$.status` |
| **예외 → 에러 응답 변환** | 재고 부족 → 409 + `code: O002` |
| 인증·인가 | 토큰 없으면 401, 권한 없으면 403 |
> 비즈니스 로직은 서비스 테스트에서 검증합니다. 컨트롤러 테스트에서는 서비스를 `@MockitoBean`으로 대체하고 **웹 계층의 책임**만 확인합니다.

## 2. MockMvc 기본

```java
@WebMvcTest(OrderController.class)
class OrderControllerTest {

    @Autowired MockMvc mockMvc;

    @MockitoBean OrderService orderService;

    @Test
    void 주문을_생성하면_201과_주문ID를_반환한다() throws Exception {
        given(orderService.create(any())).willReturn(new OrderResponse(1L, "PAID", 20_000L));

        mockMvc.perform(post("/api/orders")
                        .contentType(MediaType.APPLICATION_JSON)
                        .content("""
                                {"productId": 10, "quantity": 2, "address": "서울시 강남구"}
                                """))
                .andDo(print())                                          // 요청·응답 출력 (디버깅)
                .andExpect(status().isCreated())
                .andExpect(header().string("Location", "/api/orders/1"))
                .andExpect(jsonPath("$.id").value(1))
                .andExpect(jsonPath("$.status").value("PAID"));
    }

    @Test
    void 수량이_0이면_400과_필드_에러를_반환한다() throws Exception {
        mockMvc.perform(post("/api/orders")
                        .contentType(MediaType.APPLICATION_JSON)
                        .content("""
                                {"productId": 10, "quantity": 0, "address": "서울시 강남구"}
                                """))
                .andExpect(status().isBadRequest())
                .andExpect(jsonPath("$.code").value("C001"))
                .andExpect(jsonPath("$.errors[0].field").value("quantity"));

        then(orderService).shouldHaveNoInteractions();                 // 검증 실패 시 서비스 호출 X
    }

    @Test
    void 재고가_부족하면_409를_반환한다() throws Exception {
        given(orderService.create(any())).willThrow(new BusinessException(ErrorCode.OUT_OF_STOCK));

        mockMvc.perform(post("/api/orders")
                        .contentType(MediaType.APPLICATION_JSON)
                        .content("""
                                {"productId": 10, "quantity": 2, "address": "서울시 강남구"}
                                """))
                .andExpect(status().isConflict())
                .andExpect(jsonPath("$.code").value("O002"));
    }
}
```
> JSON 요청 본문은 **텍스트 블록**으로 쓰면 읽기 쉽고 Jackson 버전(Boot 4는 Jackson 3)에 상관없이 동작합니다. DTO를 직렬화하고 싶으면 주입받은 `JsonMapper`/`ObjectMapper`를 사용하세요.

### 자주 쓰는 검증
```java
.andExpect(status().isOk())
.andExpect(content().contentType(MediaType.APPLICATION_JSON))
.andExpect(jsonPath("$.content.length()").value(20))       // 배열 크기
.andExpect(jsonPath("$.content[0].orderNo").value("ORD-1"))
.andExpect(jsonPath("$.email").doesNotExist())             // 민감 정보 미노출
.andExpect(jsonPath("$.totalPrice").isNumber())

mockMvc.perform(get("/api/orders").param("status", "PAID").param("page", "0"));
mockMvc.perform(get("/api/orders/{id}", 1L).header("Authorization", "Bearer token"));
```

## 3. MockMvcTester (Spring Framework 6.2+, AssertJ 스타일)

```java
@WebMvcTest(OrderController.class)
class OrderControllerTesterTest {

    @Autowired MockMvcTester mvc;
    @MockitoBean OrderService orderService;

    @Test
    void 주문_조회() {
        given(orderService.find(1L)).willReturn(new OrderResponse(1L, "PAID", 20_000L));

        assertThat(mvc.get().uri("/api/orders/{id}", 1L))
                .hasStatusOk()
                .bodyJson()
                .extractingPath("$.status").isEqualTo("PAID");
    }

    @Test
    void 존재하지_않는_주문() {
        given(orderService.find(99L)).willThrow(new BusinessException(ErrorCode.ORDER_NOT_FOUND));

        assertThat(mvc.get().uri("/api/orders/{id}", 99L))
                .hasStatus(HttpStatus.NOT_FOUND)
                .bodyJson()
                .extractingPath("$.code").isEqualTo("O001");
    }
}
```
- `throws Exception` 불필요, AssertJ 체이닝, 실패 메시지가 더 친절
- 기존 `MockMvc`와 같이 써도 됩니다

## 4. Spring Security가 있을 때

`@WebMvcTest`는 **SecurityFilterChain 설정도 로드**합니다. 아무 설정 없이 테스트하면 401/403이 날 수 있습니다.
```java
@WebMvcTest(OrderController.class)
@Import(SecurityConfig.class)                   // 내 보안 설정 적용 (필요 시)
class SecuredOrderControllerTest {

    @Autowired MockMvc mockMvc;
    @MockitoBean OrderService orderService;
    @MockitoBean JwtTokenProvider jwtTokenProvider;   // 보안 설정이 의존하는 빈

    @Test
    void 인증_없이_요청하면_401() throws Exception {
        mockMvc.perform(get("/api/orders/1"))
                .andExpect(status().isUnauthorized());
    }

    @Test
    @WithMockUser(roles = "USER")                // 가짜 인증 사용자
    void 일반_사용자는_관리자_API에_403() throws Exception {
        mockMvc.perform(get("/api/admin/orders"))
                .andExpect(status().isForbidden());
    }

    @Test
    void JWT로_인증된_사용자() throws Exception {
        mockMvc.perform(get("/api/orders/1")
                        .with(jwt().authorities(new SimpleGrantedAuthority("ROLE_USER"))))   // Resource Server
                .andExpect(status().isOk());
    }

    @Test
    @WithMockUser
    void POST는_CSRF_토큰이_필요할_수_있다() throws Exception {
        mockMvc.perform(post("/api/orders").with(csrf())     // 세션 기반이면 csrf() 필요
                        .contentType(MediaType.APPLICATION_JSON).content("{}"));
    }
}
```
- 의존성: `spring-security-test` (Boot 4: `spring-boot-starter-security-test`)
- 보안 정책 자체는 별도 테스트 클래스로, 일반 컨트롤러 테스트는 `@AutoConfigureMockMvc(addFilters = false)`로 필터를 끄는 팀도 있음 (보안 검증이 빠지므로 주의)
> 시큐리티 설정 상세는 `인증·인가 스터디 자료` 참고.

## 5. 실제 HTTP로 테스트: `RANDOM_PORT`

```java
@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)
@AutoConfigureRestTestClient                  // Boot 4 / Spring Framework 7
class OrderApiTest extends IntegrationTestSupport {

    @Autowired RestTestClient client;

    @Test
    void 주문_생성_API() {
        client.post().uri("/api/orders")
                .contentType(MediaType.APPLICATION_JSON)
                .body("""
                      {"productId": 10, "quantity": 2, "address": "서울시 강남구"}
                      """)
                .exchange()
                .expectStatus().isCreated()
                .expectBody()
                .jsonPath("$.id").isNotEmpty();
    }
}
```
| | MockMvc | RANDOM_PORT + RestTestClient / TestRestTemplate |
|---|---|---|
| 서버 | 띄우지 않음 (서블릿 Mock) | **실제 톰캣** |
| 트랜잭션 | 테스트 `@Transactional`이 요청까지 묶임 | **요청은 다른 스레드** → 테스트 `@Transactional` 롤백이 적용 안 됨 |
| 필터·직렬화 | 대부분 동일 | 완전히 실제와 동일 |
| 속도 | 빠름 | 느림 |
> Boot 4에서 `TestRestTemplate`·`RestTestClient` 자동 구성은 `spring-boot-resttestclient` 모듈(+ `spring-boot-restclient`)에 있고, `TestRestTemplate`을 주입받으려면 `@AutoConfigureTestRestTemplate`이 필요합니다. 새로 작성한다면 MockMvc와 실서버 양쪽에서 같은 API로 쓸 수 있는 **`RestTestClient`** 를 권장합니다.

## 6. 면접 질문

1. **컨트롤러 테스트에서 무엇을 검증하나요?**
   → URL 매핑, 요청 바인딩과 입력 검증, 응답 상태 코드와 JSON 구조, 예외가 에러 응답으로 변환되는지, 인증·인가를 검증하고 비즈니스 로직은 서비스를 Mock으로 대체합니다.
2. **MockMvc와 TestRestTemplate의 차이는?**
   → MockMvc는 서버를 띄우지 않고 서블릿 환경을 흉내 내어 빠르고 테스트 트랜잭션이 요청까지 적용되며, TestRestTemplate이나 RestTestClient는 실제 서버에 HTTP 요청을 보내므로 별도 스레드에서 처리되어 테스트 롤백이 적용되지 않습니다.
3. **시큐리티가 적용된 API를 어떻게 테스트하나요?**
   → spring-security-test의 @WithMockUser나 jwt() 요청 후처리기로 인증 사용자를 만들고, 인증 없음 401, 권한 부족 403을 각각 검증합니다.

## 핵심 정리
- `@WebMvcTest(Controller.class)` + **`@MockitoBean` 서비스** → 웹 계층만 검증
- 검증: 매핑 · **입력 검증 400** · JSON · **예외 응답** · 인증·인가
- `MockMvcTester`(AssertJ), 실서버는 **`RestTestClient`** (Boot 4)
- 시큐리티: `@WithMockUser`, `jwt()`, `csrf()`
